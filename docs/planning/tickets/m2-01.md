# 确认原型交接并建立可重复启动的内部环境 (M2-01)

## Parent

[用户登录后能跨浏览器保存活动与投稿](../specs/m2-spec.md) · M2-SPEC · M2。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

让实施者从干净环境运行一个明确标示内部版本的页面，经业务入口读取数据库中的演示活动，并看到后台任务健康状态。

## Inputs and boundaries

M1-08 原型P01–P11及创办人体验确认

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M2-AC01](../specs/m2-spec.md#m2-ac01) / 1 — 核对M1-08实际体验确认和P01–P11证据；登记产品仓库、模块归属、规则/设计审批引用及未完成项，不以设计系统展示替代原型。
- [ ] [M2-AC01](../specs/m2-spec.md#m2-ac01) / 2 — 锁定受支持依赖交集；全新数据库迁移后，页面→Fastify→PostgreSQL读取成功；迁移账户与运行账户分权，浏览器包和日志不含密钥。
- [ ] [M2-AC01](../specs/m2-spec.md#m2-ac01) / 3 — 建立独立工作区和CI的类型、单元、依赖方向、spec引用及验收映射检查；核验分支保护、跨厂商审阅和发布门禁，未能配置项报告成本及处置，不伪称已生效。

## Verification and recovery

展示冷启动、健康页及一次依赖违规被检查拒绝；移除新入口可回到原型，保留源设计资产。

本路径测试命名含 `M2-AC01`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
