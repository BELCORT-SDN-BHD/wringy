# 真实收款资格和备款依据决定活动能否发布 (M4-11)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

商家按已定资金路径完成就绪检查，创作者仅在实际支持的国家/账户满足收款条件后参与。

## Inputs and boundaries

M4-07 收付款提供方证明指定主体和国家路径可行；M3-14 三端重复跑通完整模拟业务并证明恢复不重奖

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC11](../specs/m4-spec.md#m4-ac11) / 1 — 读取M4资金/责任结论形成版本化费用及退款披露；备款有提供方或获批路径证据，不以填写奖励池数字认定已落实。
- [ ] [M4-AC11](../specs/m4-spec.md#m4-ac11) / 2 — 服务端同时检查社交能力、币种/国家/收款资格、资金依据和有效规则版本；篡改客户端就绪标志不能发布或参与。
- [ ] [M4-AC11](../specs/m4-spec.md#m4-ac11) / 3 — 收款资格变化、资金不足或能力撤回阻止新参与并通知；暂停不清旧计量/义务；fixture绝不满足live发布条件。

## Verification and recovery

沙盒就绪成功/缺失与被撤资格测试；真实收款本身须另有本次操作授权。

本路径测试命名含 `M4-AC11`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
