# 告警能到达值班人并指导安全处理异常 (M5-04)

## Parent

[获邀用户能在可恢复且有人负责的环境试运营](../specs/m5-spec.md) · M5-SPEC · M5。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

实际值班人收到任务卡住、连接耗尽、数据陈旧、通知失败、付款unknown及账本差异告警，并演练处置。

## Inputs and boundaries

M3-13 运营在统一队列处理异常且通知失败不会丢业务；M5-01 试运营参与者和处理负责人有明确范围与承诺

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M5-AC04](../specs/m5-spec.md#m5-ac04) / 1 — 监控覆盖探活、worker心跳/积压年龄、数据库连接、社交配额/数据新鲜度、邮件投递与资金异常，不依赖异常捕获工具单一信号。
- [ ] [M5-AC04](../specs/m5-spec.md#m5-ac04) / 2 — 注入任务卡住但不抛异常、邮件失败/退信、SSE断线和unknown，验证告警路由、接收、确认、升级及恢复关闭，记录实际响应。
- [ ] [M5-AC04](../specs/m5-spec.md#m5-ac04) / 3 — 运行手册含负责人、查看原对象/交易、受控重试和停发路径；普通用户只见其业务进度，日志与告警无令牌/私密收款信息。

## Verification and recovery

有时间线的告警演练，使用已授权内部接收者；演练停止后清理测试告警而保留证据。

本路径测试命名含 `M5-AC04`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
