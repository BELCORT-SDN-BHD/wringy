# 付款未知时只查原交易并在确认未付后受控重试 (M3-11)

## Parent

[三端在真实数据库上完成全部模拟奖励业务](../specs/m3-spec.md) · M3-SPEC · M3。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

财务在未知/失败队列查看原义务与尝试，查清事实后才允许合法后续动作。

## Inputs and boundaries

M3-10 财务能模拟付款并区分发放与银行到账

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M3-AC11](../specs/m3-spec.md#m3-ac11) / 1 — 超时记unknown并保持确认未付，重复点击、重复作业和超过提供方短期去重窗口均不能创建新付款。
- [ ] [M3-AC11](../specs/m3-spec.md#m3-ac11) / 2 — 查询原attempt获得可用完成证据则只结清一次；仍未知继续阻断；明确未付证据后由获授权财务带原因建立新attempt。
- [ ] [M3-AC11](../specs/m3-spec.md#m3-ac11) / 3 — 冲突回调、查询不可用及账本差异可追踪；界面显示下一处理步骤，审计记录证据和操作者，不泄露他人收款资料。

## Blocked by

- [M3-10](m3-10.md)：消费该票已验证的交付；见下方输入与边界。

只在上述前置的实际输出可用时执行；依赖完成不自动证明本票通过。能力调查的否定结论只允许后续禁用实现，绝不授权live开放。

## Verification and recovery

故障注入超时但实际成功、确认失败、重复查询；停止重试保留义务及原交易。

本路径测试命名含 `M3-AC11`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
