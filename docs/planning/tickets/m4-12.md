# 提供方回调和查询只结清一次真实付款义务 (M4-12)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

将模拟付款适配替换为选定提供方，在沙盒验证发起、签名、查询、未知处理与可用证据映射。

## Inputs and boundaries

M4-07 收付款提供方证明指定主体和国家路径可行；M3-11 付款未知时只查原交易并在确认未付后受控重试

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC12](../specs/m4-spec.md#m4-ac12) / 1 — 真实SDK/协议版本留证，代理原始体和签名正确；坏签名、重复和乱序事件不重复结清，日志脱敏。
- [ ] [M4-AC12](../specs/m4-spec.md#m4-ac12) / 2 — 永久业务键与提供方短期键分开；超时实际成功、去重窗口过期、查询失败均只核原交易，不盲重付。
- [ ] [M4-AC12](../specs/m4-spec.md#m4-ac12) / 3 — 按canonical账户可用证据完成义务、银行未知另记；确认未付后才受控重试；商家收款/创作者付款/银行转账引用不混同。

## Verification and recovery

提供方沙盒成功、失败、unknown矩阵及故障注入；停发但继续对账，不回滚外部事实。

本路径测试命名含 `M4-AC12`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
