# 候补者收到额度恢复通知后重新申请 (M3-05)

## Parent

[三端在真实数据库上完成全部模拟奖励业务](../specs/m3-spec.md) · M3-SPEC · M3。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

不足以预留的申请人看到候补且无付款保证，额度恢复后收到重提入口。

## Inputs and boundaries

M3-04 预算不足时创作者确认确切部分金额才预留

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M3-AC05](../specs/m3-spec.md#m3-ac05) / 1 — 候补不写预算占用或付款义务，三端状态一致；通知不承诺可领取额度。
- [ ] [M3-AC05](../specs/m3-spec.md#m3-ac05) / 2 — 释放额度事件去重生成持久通知与测试邮件；重提重新核资格、截止、可用增量和余额，获得新有效次序。
- [ ] [M3-AC05](../specs/m3-spec.md#m3-ac05) / 3 — 多人收到同一可重提通知并发提交仍由原子预留裁定；未操作不自动分配，重发通知不改变队列。

## Blocked by

- [M3-04](m3-04.md)：消费该票已验证的交付；见下方输入与边界。

只在上述前置的实际输出可用时执行；依赖完成不自动证明本票通过。能力调查的否定结论只允许后续禁用实现，绝不授权live开放。

## Verification and recovery

构造释放→重复通知→多用户竞争；关闭通知不会清候补或已预留记录。

本路径测试命名含 `M3-AC05`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
