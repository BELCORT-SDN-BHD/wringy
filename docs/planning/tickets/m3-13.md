## What to build

运营按账号、计量、任务、审核申诉、付款和账本异常找到对象及原事件，用户得到同事实的三语进度。

## Inputs and boundaries

M3-12 活动报告在结案时保留未清义务和正确内容期限；M3-05 候补者收到额度恢复通知后重新申请

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M3-AC13](../specs/m3-spec.md#m3-ac13) / 1 — 各业务票随片产生的事件在统一队列可筛选关联，重试/重同步严格限权限、原键、原因和审计，不能跳审核/改余额/重付unknown。
- [ ] [M3-AC13](../specs/m3-spec.md#m3-ac13) / 2 — 邮件失败/退信/未知、断线重连、重复事件和乱序回调均保留站内状态，缺关键译文停止资金确认而非静默混语。
- [ ] [M3-AC13](../specs/m3-spec.md#m3-ac13) / 3 — 用户只看本人/组织必要进度，运行告警仅运营可见；敏感数据脱敏；手机和键盘能完成主要处理动作。
