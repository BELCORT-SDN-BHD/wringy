# 活动剩余可退款金额经核对后沿批准路径退回 (M4-13)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

授权财务查看核对后的可退余额及费用，通过已批准渠道处理退款并留下原交易和未清款关系。

## Inputs and boundaries

M4-11 真实收款资格和备款依据决定活动能否发布；M4-12 提供方回调和查询只结清一次真实付款义务；M3-12 活动报告在结案时保留未清义务和正确内容期限

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC13](../specs/m4-spec.md#m4-ac13) / 1 — 按M4-03获批路径计算可退范围，预留/确认未付/未知付款不可挪用；报告分列奖励池、费用和实际可退额。
- [ ] [M4-AC13](../specs/m4-spec.md#m4-ac13) / 2 — 退款有唯一操作键、提供方引用、授权者和审计；超时先查询原退款，重复回调不重退，退款不抹已确认奖励。
- [ ] [M4-AC13](../specs/m4-spec.md#m4-ac13) / 3 — 沙盒覆盖部分未清、失败、未知与完成；渠道若需人工则交付有证据的受控人工记录流程，未获批准方案继续阻断。

## Verification and recovery

对账报告→退款确认→结果查询完整旅程；停止新退款保留原交易与未清责任。

本路径测试命名含 `M4-AC13`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
