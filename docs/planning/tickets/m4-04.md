# TikTok能力获得可核验的准入结论 (M4-04)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

在授权测试账号上核实TikTok奖励计量实际可用条件，给出通过、限制或不支持的证据。

## Inputs and boundaries

M4-02 取得实际主体及授权测试账号的使用证据

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC04](../specs/m4-spec.md#m4-ac04) / 1 — 验证应用许可、账号控制及归属、原始指标名、版本/权限、基线及窗口终点覆盖，保存脱敏响应和测试步骤。
- [ ] [M4-AC04](../specs/m4-spec.md#m4-ac04) / 2 — 实测零/无权限/撤权/限流/缺数据，记录配额和数据时效；地域无字段即关闭地区计费，不推算。
- [ ] [M4-AC04](../specs/m4-spec.md#m4-ac04) / 3 — 输出每项能力证据与限制；若无法形成合规固定窗口数据，计奖能力保持关闭，证据性否定结论可关闭调查但不通过能力。

## Blocked by

- [M4-02](m4-02.md)：消费该票已验证的交付；见下方输入与边界。

只在上述前置的实际输出可用时执行；依赖完成不自动证明本票通过。能力调查的否定结论只允许后续禁用实现，绝不授权live开放。

## Verification and recovery

提供可复跑受授权样本和失败样本；不支持时不以抓取或模拟替代。

本路径测试命名含 `M4-AC04`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
