# 试运营参与者和处理负责人有明确范围与承诺 (M5-01)

## Parent

[获邀用户能在可恢复且有人负责的环境试运营](../specs/m5-spec.md) · M5-SPEC · M5。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

创办人确定受邀商家/创作者范围、实际值班负责人和响应安排，使异常有人接续。

## Inputs and boundaries

M4-01 提前查明社交数据与支付路径的可行性缺口

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M5-AC01](../specs/m5-spec.md#m5-ac01) / 1 — 记录具体邀请范围、进入/退出条件和国家/币种假设，不预填人数增长目标或发送邀请；开放能力最终受M4通过清单约束。
- [ ] [M5-AC01](../specs/m5-spec.md#m5-ac01) / 2 — 落实审核、申诉、财务对账、隐私、运行事故负责人和替补，公布可执行响应与升级安排，不将角色名当具体人。
- [ ] [M5-AC01](../specs/m5-spec.md#m5-ac01) / 3 — 定案固定环境容量验收目标、允许数据丢失及恢复用时目标和回滚触发条件；沿用全栈负载假设并区分提案/承诺，记录真实批准日期。

## Verification and recovery

交付可执行值班与试运营计划；未落实负责人或目标不解除发布门槛。

本路径测试命名含 `M5-AC01`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
