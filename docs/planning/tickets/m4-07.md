# 收付款提供方证明指定主体和国家路径可行 (M4-07)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

核实候选提供方是否真正覆盖拟开放的商家收款、创作者付款及退款路径，再选择可用方案。

## Inputs and boundaries

M4-02 取得实际主体及授权测试账号的使用证据；M4-03 商家和创作者在真实收付款前得到明确责任费用与退款规则

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC07](../specs/m4-spec.md#m4-ac07) / 1 — 主体/国家/币种/产品逐组合有提供方准入证据，收款、平台转移、收款账户可用、银行到账分别说明。
- [ ] [M4-AC07](../specs/m4-spec.md#m4-ac07) / 2 — 核实签名机制、状态查询、去重窗口、失败/未知处理、账户限制、费用及退款边界；书面商业许可和沙盒结果分开。
- [ ] [M4-AC07](../specs/m4-spec.md#m4-ac07) / 3 — 选定路径或给出不可行结论与影响；无可用路径不得开放真实活动；全球目标不被悄悄改为全球可付或永久仅本地。

## Verification and recovery

输出证据矩阵和需另批替代方案；无准入证据不能用SDK成功当通过。

本路径测试命名含 `M4-AC07`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
