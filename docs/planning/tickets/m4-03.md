# 商家和创作者在真实收付款前得到明确责任费用与退款规则 (M4-03)

## Parent

[只开放有真实数据和收付款证据的平台能力](../specs/m4-spec.md) · M4-SPEC · M4。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

由创办人/财务及提供方证据定案实际资金持有、服务费用、付款时长、退款与异常责任，写成可披露的规则。

## Inputs and boundaries

M4-01 提前查明社交数据与支付路径的可行性缺口

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M4-AC03](../specs/m4-spec.md#m4-ac03) / 1 — 有证据选择资金安排和责任主体，不预设钱包、托管或垫资；奖励池与平台收入/费用分开，不采用未经批准费率。
- [ ] [M4-AC03](../specs/m4-spec.md#m4-ac03) / 2 — 逐项定案服务费/支付手续费承担、币种及跨境费用、付款处理时长及工作日历、退款条件/渠道/费用和对账责任；未确认字段不填零。
- [ ] [M4-AC03](../specs/m4-spec.md#m4-ac03) / 3 — 明确拒付/撤销/已确认奖励争议的人工处理及追加记录边界，不静默释放确认款；额外尾额补足默认不启用，若要启用须单独批准规则。

## Verification and recovery

输出批准人、实际批准日期、范围与提供方依据；未批为阻塞，不将计划授权当财务决策。

本路径测试命名含 `M4-AC03`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
