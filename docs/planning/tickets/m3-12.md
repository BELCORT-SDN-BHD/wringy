# 活动报告在结案时保留未清义务和正确内容期限 (M3-12)

## Parent

[三端在真实数据库上完成全部模拟奖励业务](../specs/m3-spec.md) · M3-SPEC · M3。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

商家、创作者与运营查看同一结算报告和保留终点，任何未清事项都不能被结案抹去。

## Inputs and boundaries

M3-08 受阻创作者获得明确新截止且不多计观看；M3-11 付款未知时只查原交易并在确认未付后受控重试

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M3-AC12](../specs/m3-spec.md#m3-ac12) / 1 — 报告区分估计/候补、四类预算、未决申诉、未知付款；暂停只挡新增参与，仍处理已接受窗口和既有义务。
- [ ] [M3-AC12](../specs/m3-spec.md#m3-ac12) / 2 — 保留终点按canonical较晚项计算，无案件/款项不等待不存在事件；延期显示具体日期和理由；未确认低额尾额提前及结案披露，不扣确认款。
- [ ] [M3-AC12](../specs/m3-spec.md#m3-ac12) / 3 — 存在争议、应付或付款未知不得显示全部结清；退款仅显示待核定并关闭真实执行，不发明补足办法或退款金额，保留可追溯报告。

## Verification and recovery

有案件/无资格无案件/确认未付/延期组合测试；关闭结案保留报告和债务。

本路径测试命名含 `M3-AC12`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
