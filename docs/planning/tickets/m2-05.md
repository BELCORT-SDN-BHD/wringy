# 商家保存规则草稿并明确知道为何不能真实发布 (M2-05)

## Parent

[用户登录后能跨浏览器保存活动与投稿](../specs/m2-spec.md) · M2-SPEC · M2。版本控制中的范围与验收记录；执行状态以关联 GitHub issue 为准。

## What to build

商家保存活动资料、权利说明和规则，刷新或换浏览器继续编辑，并在预览中理解缺少的发布条件。

## Inputs and boundaries

M2-03 同一用户能在本人和获授权商家组织间切换；M2-04 用户换设备仍能恢复语言并继续表单

交付一个可演示/可验证的窄闭环，包含本路径所需存储约束、服务器授权、页面状态、事件通知、运营恢复和测试；不拆成“只建表/只做页面”。证据/批准票交付可执行结论和验证记录，不伪造代码交付。按本票边界实现；没有相应改动则不硬建新层。

业务默认数值、时长、费率、门槛和取整规则只引用[canonical默认源](../../../phase-0/foundation/campaign-defaults-v1.md)，不能从本文另抄常量。平台/财务未知按父规格门槛处理。

## Acceptance criteria

- [ ] [M2-AC05](../specs/m2-spec.md#m2-ac05) / 1 — 默认值只从canonical规则承接；覆盖配置表当前首发字段；最低金额与封顶及高观看门槛组合校验和预览一致。
- [ ] [M2-AC05](../specs/m2-spec.md#m2-ac05) / 2 — 保存使用版本冲突检测与请求去重；并发编辑不静默覆盖；规则确认形成不可变版本，已有参与版本不追溯变更。
- [ ] [M2-AC05](../specs/m2-spec.md#m2-ac05) / 3 — 奖励池和未确定费用分列；资金/数据/付款责任未就绪时真实发布被服务端拒绝；只有明确fixture活动可作内部模拟发布，不能生成真实义务。

## Verification and recovery

两浏览器编辑冲突及缺资金发布被拒；关闭发布但保留草稿及生效版本。

本路径测试命名含 `M2-AC05`，证据写明代码/配置版本、环境、动作、期望、实得和未通过项。涉及资金、组织或任务状态用真实PostgreSQL集成测试；涉及用户操作给端到端证据，包含至少一个实质失败/越权场景。门槛票以原始证据和实际签核验收，不以测试替代许可。UI沿用设计系统、三语与手机约束；通知不得漏给正确接收方或误发他人。
