# 只开放有真实数据和收付款证据的平台能力 (M4-SPEC)

## Problem Statement

模拟成功不证明实际平台允许奖励用途、能读取窗口内观看，或马来西亚主体能向指定国家付款；若晚发现会导致无法兑现活动。

**For whom:** 商家、内容创作者及被授予相应范围的运营/财务人员；当前产品仅Content Rewards。

**Evidence:** [创办人输入](../../../phase-0/founder-inputs.md)及当前批准规则支持范围；公开机制研究和投资人认可不是独立客户付费/复购证据。实际用户与运行证据须在本阶段或试运营产生，本稿不虚构访谈、测试或完成日期。

## Solution

提前并行核查契约与准入，再逐平台替换适配器，验证资金责任、收付、退款及撤权。未验证或不支持的能力保持关闭。

**Success statement:** 下方阶段验收逐项有实际证据，三方看到一致且不越权的业务事实，未验证能力不会被当作可用。

**Appetite:** 代理规划时间盒：15个主动工作日用于首条可用组合，后续每个平台在准入结论后重新估计；不是创办人交期或费用承诺。首3个工作日先产缺口矩阵。审批/开户/数据延迟/真实观察等待不压成固定天数，到限报告而不绕门槛。

## User Stories

1. As a 实施与运营负责人, I want 提前查明社交数据与支付路径的可行性缺口，so that 无需等待M2/M3，整理可复核的官方资料和验证脚本计划，尽早发现无法计量或无法付款的路径。
2. As a 创办人或获授权负责人, I want 取得实际主体及授权测试账号的使用证据，so that 落实马来西亚独立公司的准确身份、合法授权测试账号及允许验证范围，给后续真实验证明确边界。
3. As a 创办人或获授权负责人, I want 商家和创作者在真实收付款前得到明确责任费用与退款规则，so that 由创办人/财务及提供方证据定案实际资金持有、服务费用、付款时长、退款与异常责任，写成可披露的规则。
4. As a 创办人或获授权负责人, I want TikTok能力获得可核验的准入结论，so that 在授权测试账号上核实TikTok奖励计量实际可用条件，给出通过、限制或不支持的证据。
5. As a 创办人或获授权负责人, I want Instagram能力获得可核验的准入结论，so that 核实实际Instagram登录路线、专业账号资格和Insights口径，不沿用不同路线的权限猜测。
6. As a 创办人或获授权负责人, I want YouTube能力获得可核验的准入结论，so that 验证频道控制证明、独立数据授权及可用于本产品的统计口径。
7. As a 创办人或获授权负责人, I want 收付款提供方证明指定主体和国家路径可行，so that 核实候选提供方是否真正覆盖拟开放的商家收款、创作者付款及退款路径，再选择可用方案。
8. As a 商家、创作者或运营人员, I want TikTok投稿能读取真实且有来源的合格数据，so that 按能力结论接入TikTok账号连接→本人投稿→基线→截止样本→三端状态的窄路径。
9. As a 商家、创作者或运营人员, I want Instagram投稿能读取已核准口径的真实数据，so that 按确认登录路线完成Instagram连接、投稿、基线和后续计量，并清楚展示账号/媒体限制。
10. As a 商家、创作者或运营人员, I want YouTube投稿能以独立授权取得可靠计量，so that Google登录后另行授权YouTube，完成频道归属校验、投稿和有覆盖时间的数据展示。
11. As a 商家、创作者或运营人员, I want 真实收款资格和备款依据决定活动能否发布，so that 商家按已定资金路径完成就绪检查，创作者仅在实际支持的国家/账户满足收款条件后参与。
12. As a 商家、创作者或运营人员, I want 提供方回调和查询只结清一次真实付款义务，so that 将模拟付款适配替换为选定提供方，在沙盒验证发起、签名、查询、未知处理与可用证据映射。
13. As a 商家、创作者或运营人员, I want 活动剩余可退款金额经核对后沿批准路径退回，so that 授权财务查看核对后的可退余额及费用，通过已批准渠道处理退款并留下原交易和未清款关系。
14. As a 创办人或获授权负责人, I want 数据撤权与隐私处理不会销毁必要资金证据，so that 在真实数据开放前明确各提供方撤权、原始数据保留/删除及金融审计留存的实际要求和责任。
15. As a 创办人或获授权负责人, I want 仅验证通过的真实能力进入发布候选范围，so that 汇总逐能力证据，并在具体授权范围内验证真实账户可用及结案路径，形成供M5使用的发布候选。

## Implementation Decisions

1. M4-01无阶段前置，M4-02/M4-03及逐提供方验证仅依赖必要证据；不等待M3完成才发现可行性。真实适配和闭环才消费M3结果。
2. AuthAccount、MediaRef、MetricSnapshot、PaymentAttempt沿用内部契约；每项保留fixture/live、主体范围、来源指标/覆盖时间、缺失理由和证据。
3. 账号控制、数据授权、素材版权和奖励用途许可分开；平台指标与地区能力逐项映射，无法证明就禁用而非推算。
4. TikTok、Instagram和YouTube各有准入结论和窄适配票。证据充分的不支持结论可完成调查，适配票以disabled交付；发布候选仍要求至少一个完整通过的社交及匹配支付组合。
5. 首版单币种；MYR仅沿用显式假设，实际国家/币种和主体由门槛票确认。Stripe优先调查而非默认选定，不开发自动供应商切换。
6. 付款适配不决定奖励；签名在Fastify用原始回调体验证，查询与回调都关联原attempt。资金可用阶段遵循canonical，不将转移成功当已发放。
7. 真实发布须资金保障、费用退款、数据用途及创作者收款资格同时通过；能力撤回停新增但不清既有义务。隐私策略区别原始社交数据和必要金融审计。

规则来源优先于历史草稿措辞：已批准默认和2026-09-15全栈方向为准；较早契约中“取整/付款阶段/跨活动仍待定”等历史句不重开已批准规则。本轮只细化执行和验收，不复制默认值、不修改源文件。具体实现文件位置在开工代码评审确定，本节不指定路径。

## Testing Decisions

- 最高可用边界为三端浏览器旅程→唯一业务API→真实PostgreSQL→受控提供方适配。优先复用现有M1页面测试和实际产品测试设施；当前仅核实原型规格/票据及设计系统文档存在，未核实产品仓库或测试代码，不能声称已有测试通过。
- 单元测试覆盖纯金额/期限规则，集成测试覆盖事务、权限、组织关系、重复键与任务恢复；Playwright覆盖用户可观察结果。fixture适配只替外部来源，不替数据库或服务器权限。测试名称含阶段AC，结果再映射PRD A及实施D。
- 测试边界由2026-09-16常规规划授权确定，不再额外问卷。只测外部行为和不变量，不测试内部实现形状；按每票风险增加故障/竞争/越权案例。
- 受影响范围完成类型/单元/集成检查，重型交付另有端到端与回退演练；保存独立跨厂商只读审阅。资金来源未知、真实权限未知和提供方准入不能由mock测试“通过”。
- 统一证据记录：验收ID、版本、环境、测试或人工步骤、期望、实际、时间、证据引用及未决项；当前全为未执行。发布候选必须区分模拟、沙盒及真实验证。

逐平台记录能力验证通过/全部拟开放能力、实际可用样本/采集尝试、快照新鲜度、限流/调用数、付款unknown及对账耗时、退款差异与未清数量。按主体/国家/币种拆分，disabled不计通过，模拟不算真实到账。

## Out of Scope

承诺全球支付、私自开户/采购/转账、无许可抓取、推算地区观看、钱包/托管假设、多供应商路由、自动外汇、生产发布和非Content Rewards业务。
