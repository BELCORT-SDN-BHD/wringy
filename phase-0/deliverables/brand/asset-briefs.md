# Wringy 视觉资产简报 · 预留槽位

2026-09-10，v1 proposed。此文件仅供后续图像与原生 Figma worker 制作。**本轮不生成 Logo、图片、PPT 或 Figma 节点。** 所有情境、活动、姓名、金额均为虚构示例，不作客户或业绩证明。方向锁定 Citron / Ink / Paper，Iris 辅助；改变需向主会话明确提出。

## 共用制作规则

根源：tokens.json。renderer 可读取顶层 brandColors/theme；其他 UI 使用 semantic.light / dark。不自行挑“相近”的黄绿或紫色。主要背景为 Paper、文字为 Ink、重点为 Citron、少量 Iris；最终文案与钱款放可编辑文字层，图像生成只做背景/情境或后续概念参考，不把错字截图当成产品规范。

字体 Manrope + Noto Sans SC。主会话已报告二者在目标 Figma 可用；本地渲染器若未加载，按 design-system-spec.md 的本机回退流程检查，不静默更换身份。两份 PPT 均中文；图内英文仅用于示范多语言，不成为主叙事。

下列槽位 ID 固定供 worker 认领；此文档不写入其他 worker 的图片输出目录。建议交付 PNG（演示用、sRGB）+ 可编辑文字叠层/原生 Figma（若获指派）；最终 SVG Logo 必须由矢量工作流另做，不将位图描摹当成最终字标。各图可单独裁切为 16:9 deck 区域，但不能裁掉示例标签和金额状态。

禁止：复制 Whop 的标志、颜色构成或 UI；虚构品牌 Logo、客户认证、已到账或增长证据；赌博/财富奢侈符号；真实银行信息；单一族群代表整个马来西亚；用国旗/双子塔拼贴代替市场理解；把界面规格当作已上线截图。没有未经确认的奖励费率、释放日期或付款保证。

## LOGO-DIRECTION · 后续深化，当前不渲染

品牌书 BB-10/11。一个方向：Wringy 字标 + 开放接点。清晰几何 sans 骨架，g 的收尾有连结感；独立符号是两段同粗线相接的抽象 W。先黑白，不依赖渐变；r/i/n/g 小尺寸可辨。提议保护区 W 高度的一半、字标96px、符号24px；16px单独光学版本。不要无限符号、链币、硬币、握手或盾牌。

后续设计师验收：黑白反白、24px/16px识别、中文混排、横向和方形锁定、印刷24mm/6mm测试；给 SVG/PDF 与使用说明；注明未完成商标核查。最终 Logo 的几何不是在本文件中伪造出来的。

## PHOTO-CREATIVE-COLLAB · 品牌影像

用于 BB-02/17，建议 2400×1600、3:2，可裁16:9。预留两幅：①成年创作者在明亮而真实的小型工作室拍摄日常物件；②品牌操作者与创作者围绕无真实品牌的简报讨论。环境具有现代马来西亚城市工作情境，不刻意地标化；人物多元，不标签化具体族群；自然动作和真实材质，适量 Citron 道具，避免全画面染色。

构图留左侧约35%安静区域给中文标题；人物脸与手完整；不要在照片中生成可读品牌承诺、银行界面或客户 Logo。用生成图时在资产记录和讲稿写明概念影像，不能当真实团队照。真人素材需获得适当许可。

## UI-BRAND-DESKTOP · 品牌活动简报

用途 BB-21；主画布1440×1000，浅色主题，演示导出建议2×。原生示例优先。虚构组织“示例品牌 A”，活动“周末随行杯 · 创作合作（示例）”。左侧导航：概览、活动、提交、预算、设置。主区顶部显示“活动草稿”，主要动作“保存草稿”，发布按钮禁用并说明“请先确认使用权与审核期限”。

12栏结构：主区7栏简报、右侧5栏摘要（扣除导航后按可用宽度调整）；16:9裁切必须保留标题和示例标签。必需内容：
- 交付：1 条 20–30 秒竖屏视频；语言“中文 / English / Bahasa Melayu，按活动约定”。
- 必須：展示产品使用场景；自由发挥：开场与故事方式。
- 截止：2026年9月30日 18:00 MYT (UTC+08:00)，仅示例日期。
- 单条固定报酬：MYR 150.00；示例总预算：MYR 3,000.00；预算不是每人所得，未扣任何未确定费用。
- 使用权、修改轮次、审核期限：待确认；在侧栏显示尚未完成，不制造隐含默认。
- 预览框保留无标志日常水杯内容槽位，无虚假正式品牌。

视觉重点是“要求清晰”而非大数字。错误示例可用一个内联字段提示；不做整页红色告警。验收：预算与每条报酬不会混淆、所有待定项阻止发布、字体可读、Figma文本可编辑。

## UI-BRAND-MOBILE · 品牌审核入口

用途 BB-22；390×844，额外验证320宽；导出2×。同一个示例活动，已发布版本的**独立情境示意**，不要把桌面未确认草稿误当同一次操作结果。顶部组织 + 活动名 + “示例”；摘要显示“待审核 3 份作品”（纯示例数量）、单条固定报酬 MYR 150.00、截止日期及时区。

顺序：活动摘要 → 简报入口 → 待审核作品列表 → 明确操作。每条记录“示例创作者 01/02/03”、作品缩略图槽位、提交时间、“查看作品”。底部导航“活动 / 提交 / 通知 / 我的”；不使用不可辨认的图标独撑入口。仅看审查入口，不表现不经确认的一键批量付款。

长活动名称允许2–3行；44px触控目标；焦点不被底部栏遮挡。视图下方可放第二个小状态样例“没有待审核作品”，但不能与当前3份数字混在同一实例。验收手机不隐藏金额与状态，不让全卡链接包含次级按钮。

## UI-CREATOR-DESKTOP · 奖励批准详情

用途 BB-23；1440×1000，浅色主题，导出2×。虚构“示例创作者 01”。导航“探索 / 我的合作 / 报酬 / 通知”。主区标题“报酬详情”；活动同上但明确独立虚构演示。主要金额 MYR 150.00，状态“报酬已批准”，紧邻“尚不可提现”。

左侧7栏：作品预览槽位 + 简报要求核对；右侧5栏：奖励金额、审核结论、时间线。审核反馈“已符合本次示例简报要求”。释放条件显示“释放条件待确认”，不编造到账日。提现按钮禁用并常显原因“这笔报酬尚未进入可提现余额”；可用动作“查看审核记录”。

时间线只显示“作品已提交 → 审核已批准 → 等待释放”，不能出现“银行已到账”。不放总收入卡、增长箭头或庆祝动画。底部“示例界面，非真实交易”。验收：批准状态不误导资金可提现，右栏和移动变体使用相同事实。

## UI-CREATOR-MOBILE · 奖励批准与下一步

用途 BB-24；390×844，验证320宽；导出2×。与 UI-CREATOR-DESKTOP **同一笔示例奖励**。顺序：返回报酬 → 活动短标题 → MYR 150.00 → “已批准，尚不可提现” → 简明审核记录 → “释放条件待确认” → 查看审核记录。屏幕内能读到金额与限制，不能需要滚动才发现不可提现。

手机不塞桌面整个表格；时间线用纵向文字。禁用提现不以浅灰难读字表达，使用 token disabled，并给可访问原因；底部与安全区保持空间。作品图不盖在金额后面。暗色主题可作为后续第二实例，必须从 semantic.dark 取值，不临时色相反转。

## UI-PAYOUT-CONFIRM · 可选后续槽位

可用于 BB-25，不是上述尚持有报酬的下一帧。独立可提现情境：账户扣减 MYR 150.00、示例手续费 MYR 2.00、预计到账 MYR 148.00，收款账户“示例账户 •••• 1234”，预计时间“到账时间尚未提供”。常显“示例，非实际费率”。确认按钮“确认提现 MYR 150.00”，旁边解释其为账户扣减额；不得默认勾选。

费用或收款信息未确认时阻止实际提交；图像示例只为信息层级。金额排版精确一致，不能由生成模型改成148.80或丢失MYR。状态图若做失败，保留可查记录并先核对状态，不画立即重试打款的大按钮。

## CHART-SAMPLE · 可选示例数据图

BB-27，16:9可读区域。只显示示例提交数量，避免虚构财务增长：待审核3、需修改2、已批准4、已拒绝1；注明“示例数据，10份提交，非真实运营数据”。类别用 chart tokens、形状与直接标签；提供同值表。不要把“已批准4份”自动乘以奖励当作真实可提现收入。

## 交付检查与已知缺口

每个槽位汇报：slot ID、文件/节点位置、主题、字体实际使用、示例数据标签、与 token 的偏差（应为零）、图片来源/生成属性、尚未验证项。文字覆盖层必须人工核对金额、日期、币种和三语。渲染逐页检查超界、字符缺失和错误状态；原生库检查组件实例与变量绑定。生成背景不能证明组件可访问性。

本轮没有最终视觉文件。用户研究、三语母语审读、版权授权与商标核查、真实支付条款、完整键盘与辅助技术测试仍为后续工作；主会话汇合后安排独立跨厂商审阅，不由此文档假称已完成。
