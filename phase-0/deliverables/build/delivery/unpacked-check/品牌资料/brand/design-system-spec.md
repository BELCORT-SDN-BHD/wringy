# Wringy 设计系统规格 · v1 提案

2026-09-10。此文件把 brand-strategy.md 转成可实施规范；现已交付31类本地HTML/CSS设计参考；具体实现状态以 component-inventory.json 的 stateCoverage 为准，不表示生产应用、原生Figma组件库或完整可访问性验收完成。品牌方向按主会话实时确认锁定 Citron / Ink / Paper 与 Iris 辅色。

## 1. 权威来源与交接协议

根层为 brand-strategy.md，具体数值唯一来源为 tokens.json。本文色值表和品牌书色票是从根源生成的快照，不允许单独修色。brandColors 与 theme 是方便 PPT 和图片工作者读取的派生投影；更新时必须从 primitive 重建。component-inventory.json 定义 31 个组件家族、交互和状态；brand-book-content.json 是 30 页中文内容；asset-briefs.md 定义图像槽位；实际本地参考与导出记录见 showcase/manifest.json。

引用解析：semantic.light / dark 内部的点号键是完整键名，例如 text.primary；其值 {primitive.color.ink} 沿 primitive 的对象层级解析。消费者先选 theme，再查语义键，最后解引用，未知键应报错而非随意补色。空间、字体、阴影等类别按 tokens 的 units 读取。工程若转为 DTCG、CSS 或 Figma Variables，转换器应保留原 key 并生成映射，不能把本自定义结构宣称成已经符合某个外部 schema。

版本：1.0.0-proposed。根色、语义、排版变化需同时刷新两个中文 PPT、品牌手册和原生库，先生成差异清单再视觉审阅。业务政策修改属于产品负责人，不能由视觉作者决定。Figma 目标由主会话提供：https://www.figma.com/design/qw2UHml58nEnQLtUbC058Z 。Figma成功批次报告4个集合、130个变量，后续配额阻断读回；没有原生组件、文字样式、屏幕或导出。按主会话实时授权已停止Figma调用，交付本地参考替代；不声称原生库完成。

## 2. 颜色与对比

Citron 是身份识别和少量营销强调；Ink 是浅色主题的核心操作和文字；Paper 是阅读底；Iris 是链接和次级创意强调。交易界面约 85% 中性色、10% 主色、5% 辅色是构图建议，不是强制面积公式。禁止用 Citron 承载白字；不可用主色表示“成功付款”。深色不是把浅色反相；使用 semantic.dark 明确定义的颜色。

文字正文最低对比目标 4.5:1；必要的边界、图标与焦点目标 3:1。以下为不透明颜色的公式计算，不代表截图、半透明叠层、图像背景或完整 UI 已测。以未四舍五入结果判定；完整 100 对明暗组合和阈值在 tokens.json 的 contrastAudit。

| light / text.primary | #182521 | #F7F8F2 | 14.836:1 |
| light / brand.onSecondary | #FFFFFF | #5944B8 | 7.134:1 |

状态映射：success 表示已完成且已核实的当前操作；warning 表示待处理或需注意；danger 表示失败、拒绝或账户限制；info 表示进行中；neutral 表示草稿、未知或普通信息。每个状态都同时有词和图标，不能只凭颜色。首发品牌直接付款的审核批准标签可用 success，但紧邻报酬文字必须写清“已批准 · 待品牌付款；到账尚未确认”。首发不显示平台钱包或可提现余额；不可让绿色代替财务事实。提现/释放标签只属于第6节明确区分的未来集成路线。

focus.ring 为 3px 外环，隔离带 focus.gap 2px，按钮本体不能挡住环；强色按钮尤其需要隔离带。图像上的控件放在实色面板，不直接套用公式通过的文本色。border.decorative 只能分隔无语义区块；表单边界用 border.default。禁用不采用全组件降透明度，使用显式禁用前景和背景、禁用原因在附近可读。纯装饰边界与失能控件的标准豁免不作为降低可读性的理由。

## 3. 字体、跨语言与发布

两套正式家族：Manrope 用于英文/马来文，Noto Sans SC 用于简体中文。官方 Google Fonts metadata 及 OFL 1.1 链接已于 2026-09-10 查询并保存在 tokens.json；允许范围须遵守随包许可证，分发字体带原版权与许可，修改字体需核对保留名称，不单独销售字体。本地参考已打包两家族字体及原始许可证，官方来源与文件哈希见 showcase/fonts/provenance.json；实际浏览器加载检查通过。

Figma 可用性由主会话实际检查并在本会话报告：Noto Sans SC Regular/Medium/Bold、Manrope 可用；不得凭系统回退用 Inter 或 Plus Jakarta Sans 替换身份。web 建议自托管许可字体，字体加载时保持正文可见；CJK 按实际语言分包，避免整库阻塞，但不能遗漏姓名字符。繁体中文、泰文、阿拉伯字母马来文等为未验证扩展，需独立家族/字形审阅，本 v1 不冒充全部 SEA 字符覆盖。

本地 /Library/Fonts 与 ~/Library/Fonts 未见命名匹配的 Manrope/Noto SC。已发现 /System/Library/Fonts/Supplemental/Arial.ttf 与 Arial Unicode.ttf，可作为本机演示渲染的 Arial / Arial Unicode MS 暂定回退；文件存在不等于特定 PPT 渲染器已加载。渲染 worker 必须测试“创意合作 · 报酬 MYR 150.00 · Kerjasama”、字重和换行。优先获取原定 OFL 字体；临时使用 OS 字体时只用于本机输出，不复制分发字体文件，且品牌页记录实际回退。不能声称 PingFang 已存在。

产品正文 16px；关键金额与条款不得低于 14px；12px 仅非关键辅助信息。中文正文行高 1.75，不压缩字距，不合成斜体，不全大写。Latin 展示字可小量负字距；数值使用 tabular-nums 并在目标字体检查是否生效。长姓名、邮箱、英文标题允许换行，金额与币种尽量同一行，不用省略号隐藏财务数值。日期显示“2026年9月30日 18:00 MYT (UTC+08:00)”；存储时区策略交产品实现，不由截图假设。

中文 PPT 16:9，标题建议 32pt、正文 20pt、注释 12pt；每页正文不超过约 150 中文字符，密集表拆页或把细节放讲稿。排版保持字号层级，不为了塞字缩小核心内容。两份 PPT 和品牌书都按 theme 字体与颜色读取；每页源链接进 notes。

## 4. 布局、形状与响应式

4px 为主要节奏，2px 仅微调；间距来自 space。控制圆角 8px、卡片 16px、少量大视觉 24px；圆角 999 仅头像或短标签，不将全站按钮做成胶囊。1px 常规边、2px 强调、3px 焦点；低频阴影区分浮层，不用阴影代替轮廓。图标统一一个家族，建议 Phosphor regular，20px 基准；实现时另查官方包许可，不在本轮引入依赖。语义图标必须有文本/名称，避免用 Emoji 传递财务状态。

小于 768px 单列，页面边距 16px；768–1023px 可 8 栏、24px 边距；1024px 起 12 栏、32px 边距，最大内容 1280px。表单最大 560px，正文最大 65ch。320px 下也必须读完要求与金额；1440px 大屏不把主表单拉成通栏。控件至少 44px 高，触控目标至少 44×44px，邻近目标保留间距；这比 WCAG 2.2 AA 某些目标要求更保守，是本系统选择。

桌面审核可 7 栏预览 + 5 栏要求/操作；移动改为简报摘要、预览、审核意见、操作顺序。底部固定动作需计算安全区、留出内容底部空间，键盘打开时不得遮字段或焦点。表格在移动可转带标签卡片，复杂对比保留有名称的横向滚动区域；不要强行隐藏费用、净额或状态列。导航断点取决于真实标签宽度，长马来文可提前折叠；组件变体不改变内容顺序。

## 5. 动作与交互

hover 120ms、一般反馈 180ms、进入 240ms、退出 160ms；只用短位移最多 8px 和透明度，表示层次、反馈和内容到来。禁用滚动劫持、不断循环装饰、数字滚动和庆祝待审核报酬。减少动态偏好下持续信息立即切换，移除位移，保留静态进度和明确状态。进度条只基于真实任务进度，未知用“正在上传”；出错停止动画并展示恢复方式。

z-index 使用 base 0、sticky 10、dropdown 20、scrim 30、modal 40、toast 50、tooltip 60。浮层不在局部 stacking context 下任意加 9999；弹窗内工具提示归属于当前弹窗。关键提醒不盖住确认动作。

组件完整清单在 component-inventory.json。所有交互有 focus/disabled/loading/error；静态容器不因此加入 Tab。默认、hover、pressed 有明确 token；destructive hover/pressed 可保持背景原色并增加 2px inset 边界，保持已验证文字对比，不自行调透明度。selected 用 selection；read-only 保留可复制内容并写明不可修改；错误用 status.danger 和字段说明。焦点态可与任何未禁用业务状态并存。

## 6. 金额、活动与账本语义

这是设计契约，不是最终费率、托管、退款或支付处理政策。生产前必须确认资金服务方、资格、费用、持有条件、税项、审核权、申诉和到账依据；不能从 UI 反向推断这些业务已获批。

### 6.1 首发：品牌直接付款，无平台钱包

当前首发模型来自2026-09-10主会话实时意图：品牌直接向创作者付款。Wringy设计参考展示合作与付款记录，不宣称平台持有、释放、托管或划转资金，也不提供平台可提现余额。

- 提交对象：draft → submitted → reviewing → approved / changes-requested / rejected；修改保留版本。通知已读不会改变审核结果。
- 报酬与付款记录：approved（报酬已批准）→ awaiting-brand-payment（等待品牌付款）→ paid-confirmed（有适当证据确认到账）。审核批准和付款确认是独立事实，不能自动联动成已到账。没有到账证据时保持待确认；品牌表示已转出但未确认银行到账时写“品牌已转出，到账待确认”。
- 首发统一示例：已批准报酬 **MYR 150.00**，付款方“示例品牌 A”，付款状态“等待品牌付款”，到账状态“尚未确认”。不扣示例平台费，不出现提现按钮，不称钱包余额。此款项与下节MYR148.00示例是不同情境。

每笔钱显示币种代码MYR及两位小数，而非“150”“RM150+”或含糊“余额”。预计、待审核、已批准、待品牌付款和已确认到账按事实分别显示；未知不能当作0或paid。截图不能证明资金政策或服务已经实现。发生争议、冲正或记录错误时保留原始记录并独立说明，不静默改写收入。

### 6.2 未来集成路线：仅为独立设计参考

只有另行确认服务方、释放规则、账本、费用与真实资金流程后，才可能采用以下状态；这不是首发承诺。页面及金额示例必须显著标“未来集成路线示例 · 首发为品牌直接付款”。

- 集成报酬对象可参考 estimated → pending-review → approved-held → available → reserved-for-payout → paid。approved-held仅说明审核已批准；available仅在服务方/权威账本确认满足释放条件时出现，不由UI或审核结果推断。
- 集成提现对象可参考 confirming → submitted → processing → paid / failed / cancelled / unknown。状态由服务方及权威记录确认；unknown先核对，不能重复发起。失败是否释放预留款项由核实后的账本结果决定。
- 独立虚构例子：款项总额或账户扣减 **MYR 150.00** − 示例服务费 **MYR 2.00** = **预计净到账 MYR 148.00**。必须标“示例，非实际费率”；不可把该费用套用到首发MYR150.00品牌直接付款示例。

未来确认页逐项显示币种、扣减额、费用、净额、收款目标末四位、已知到账预期与确认动作。缺项时阻止确认；未知ETA写“到账时间尚未提供”。服务方仅接受请求写“已提交”，确认转出但未确认银行到账写“已转出，银行到账待确认”，仅在适当到账确认后写“已到账”。扣减、费用、净额分别成行；金额由可信源给出，UI不以二进制浮点决定账务。兑换须另列币种、来源、汇率、费用及报价有效期。

两条路线共用原则：拒绝、账户限制、付款失败与通知失败各自独立；账户受限不等同付款失败，也不抹去可合法查看的历史或申诉入口。

活动简报必须包含：交付平台与数量、语言、时间与时区、资格、不可用内容、必需/可选要求、使用权与期限、披露要求、改稿规则、审核标准、固定/按表现报酬公式与上限。未确认的字段标待定并阻止发布，不伪造默认。更改已加入活动的关键条件须版本化并由业务规则决定重新同意；设计应展示差异，不能悄悄替换。

## 7. 可访问性、内容安全与隐私

目标为 WCAG 2.2 AA；不是认证声明。优先原生元素，复杂模式参照 W3C APG 并做实际键盘/辅助技术测试。界面设正确 lang，局部外语单独标记；装饰图像空 alt、信息图像有等价文本、视频提供字幕及文字信息；不把重要文案烘焙进图片。

阅读与输入：逻辑标题层级、跳到主要内容、可见 label、错误摘要及逐字段说明；触屏不要求 hover 才见功能；完整键盘顺序可预期，焦点不被固定导航遮挡；颜色、位置和声音都不能单独表达状态。验证 200% 字体放大、400% 页面缩放和 320 CSS px 重排；内容增加和三语长文本不会截断操作。密码管理器、粘贴、显示密码可用；验证过程不依赖记忆谜题。计时流程支持合理延长/保留状态，具体例外由实现方评估。

以下为设计原则而非法律意见或已实现安全保证：最小化个人数据收集；在收集处解释目的与可见范围；公开品牌资料与私有身份/银行资料分开；账户默认遮盖敏感号码，用户主动显示；导出确认字段、范围、权限和保存位置。通知预览不带银行详情；演示素材不放真实个人资料或访问令牌。

多组织界面始终显示当前组织，切换组织后清空不适用缓存与选择；隐藏控件不能替代服务端授权。无权限状态不能暴露其他组织名称、金额、文件或数量。上传界面区分上传和安全扫描，拒绝危险类型时给明确原因；外链预览避免自动加载追踪内容，下载来源可识别。审核拒绝说明可公开的原因，不泄露检测规则或举报人。举报、申诉与必要的客服路线持久可访问。

同意、用途、通知偏好用明确主动选择；不预勾选营销；不使用羞辱式拒绝按钮；删除/撤回要说明影响和业务允许的恢复范围。保留期限、儿童资格、地区披露、税务及使用权由专业与产品负责人确认，设计不得宣称“合规”“银行级安全”或默认适用所有东南亚国家。

## 8. 数据可视化

最多四个主要分类，用 chart.1–4 + 圆/方/三角/菱形 + 直接标签；线图另有实线/虚线/点线/点划线。数据图元与背景已计算 3:1，但相邻系列互相之间未保证 3:1；用留白/清晰分隔、图形和线型冗余，不把紧贴纯色堆叠作为唯一编码。焦点 tooltip 可键盘阅读，提供同值数据表及一句文字结论。

柱图零基线；折线非零纵轴明确标范围；货币不跨币种直接相加；比率同时给分子/分母和统计窗口；状态漏斗说明同一批次与排除项。未知是“暂无数据”，不是 0；陈旧数据标更新时间；部分缺失画断线并说明，不补虚构点；零收入也不写成亏损。避免双轴、3D、夸大面积和无法解释的综合评分。

品牌侧优先活动状态与审核队列，创作者侧优先报酬构成与历史。未经归因确认不把播放数称为销售贡献；示例图全部标“示例数据”。导出带同样币种、时间范围、来源和定义。响应式删减装饰，不删金额或口径。

## 9. 原生库实现交接与验收

### 2026-09-10 实际交付记录
