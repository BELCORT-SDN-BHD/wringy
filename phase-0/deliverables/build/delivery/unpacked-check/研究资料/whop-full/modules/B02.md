# B02｜结账、订阅与账单

证据口径统一见[证据指南](../evidence-guide.md)；演示与真实依赖边界见[共享建设参考](../build-reference.md)；本卡保留的文/API、D/A、营销等本地图例仅作别名，以统一指南为准。API 路径中的 beta 不单独证明预发布；成熟度须依据具体页面正文及版本，未核实则保留未知。

状态：**研究型候选模块，不是已批准规格，也不是 Whop 内部架构。** 核验日期：2026-09-10。此卡是本研究 B02 的规范功能清单；商业讨论及冲突见 [综合报告](../payments-money-trust.md)。所有勾选框表示未来可选择建设的能力，**不是完成状态**。官方文档仅核验正文，未操作账户、接口或交易。

## 目的、角色与边界

帮助买家完成购买，让商家、销售人员和财务人员管理收费及续费。平台开发者可把相同结账能力嵌入自己的产品。

**拥有的业务概念（分析）：** 结账配置、收费计划、订阅账期、扣款尝试、支付方式引用、优惠应用、应收账单、收据、渠道路由结果。商品目录由 B01、交付权益由 B03 拥有；本模块只提供付款及账期事实。钱包余额和银行出款归 B09；退款裁决、税务规则与风险准入归 B10。本模块执行经授权的退款，不自行裁决争议。

## 主流程与失败流程

**正常（分析归纳）：** 商品提供报价基础 → F01/F03 生成收费计划 → B10 提供税务及准入结果 → F04/F05/F11 筛选可用渠道 → 买家确认总额 → F06 扣款 → 确认成功事件 → 通知权益模块、B09 记录资金、F09 出示收据。F10 的首张循环账单成交后转订阅，官方说明后续自动扣款发送收据，并非每期重新寄待付账单。

**失败：** 认证未完成或异步处理中不能先宣布成功；失败续费进欠费状态，按访问设置及五天重试结果恢复/取消；发票按逾期 3/7/14/30/60 天提醒，120 天后自动作废；融资不显示先查资格，不能假设平台宕机；Tap to Pay 不合国家条件回退二维码或网页。见 F06/F07/F10/F11/F14。

## 谁付钱、何时收费

买家支付商品价给卖家交易链路；Whop 收款服务收费由商家或约定承担方支付，费用触发于成功付款及实际启用服务，非单纯浏览。标准卡价 2.7%+$0.30；Billing 0.5%、启用路由 0.8% 等见[定价](https://whop.com/network/pricing/)，不是统一叠加费率。F10 说明买家有 5% 发票服务费，同时提供转嫁处理费开关，叠加关系未知。F12 的 30% 收款人为 Apple。F05 买家换汇费比例及分享未知。自动重试回收率、净利润均未披露。

## 依赖与扩展点（分析）

- **B09**：可用余额、退款资金、到账及出款对账；B02 不直接更改资金余额。
- **B10**：付款资格、税务模式、身份/风险限制及争议决定。
- **B01**：组织、团队权限及商品目录；**B03**：会员与交付权益，依据付款事实调整访问；**B04**：客户视图、通知呈现与通用客服；**B11**：外部开发者接口契约和第三方连接。
- 上述是所需能力，不要求整个模块先完成，也不描述 Whop 实际代码依赖。
- 扩展点：渠道适配器、本地币种展示、财务系统连接器、账期策略；未来马来西亚支付方式须重新验证，现有正文未证明 FPX/DuitNow 已支持。

## 首个纵向切片及验收候选（未批准）

**切片：单商家、单币种、网页一次性购买到收据及账务记录。** 先用模拟合作方，无真资金。

1. B02-A01：F01/F02 创建报价，买家支付前看到单价、费用、税额及总额；完成后存在唯一成功交易和收据。
2. B02-A02：同一成功通知重复到达时只授予一次权益、只产生一次 B09 资金事件。
3. B02-A03：认证取消、失败、处理中均不被显示成成功；可查询最终状态。
4. B02-A04：B10 拒绝交易时不扣款；失败原因可向买家解释且不暴露敏感风控参数。
5. B02-A05：商家可从付款定位收据、费用和账务记录；未授权团队成员不可查看其他商家数据。

后续切片候选：订阅催收 → 发票/会计连接 → 地区渠道 → 移动及实体销售；以上是分析顺序，不是建设承诺。
