# B04｜顾客生命周期、客服与经营分析

证据口径统一见[证据指南](../evidence-guide.md)；演示与真实依赖边界见[共享建设参考](../build-reference.md)；本卡保留的文/API、D/A、营销等本地图例仅作别名，以统一指南为准。API 路径中的 beta 不单独证明预发布；成熟度须依据具体页面正文及版本，未核实则保留未知。

状态：**基于公开研究的候选模块，不是已批准规格，也不是 Whop 内部架构描述。** 核验日：2026-09-10。本文为 B04 唯一功能清单；商业讨论与冲突见[研究报告](../commerce-delivery-operations.md)。

## 目的、角色与边界

把潜客、加入、成交、持续使用、问题解决、退出及回流连起来，使商家知道客户是谁、遇到什么问题、应采取什么行动。角色：潜客、顾客、销售、商家客服/运营、平台 AI 支持及人工处理人员、分析人员。

**拥有概念（未来模块建议）**：潜客与候补个案、顾客关系、会员运营视图、客服会话/一般支持个案/回应，引用 B10 售后案件与证据、欢迎与离开消息策略、经营指标定义和报表。**不拥有**：B01 个人身份/角色/商品、B02 计费合同/支付与退款执行、B09 争议资金账本、B10 退款争议裁定与税务政策、B03 会员访问权益/内容/外部权限/物流执行、B05 消费发现/公开评价、B07 推荐归因及佣金义务、B08 广告归因。API 文档把会员放在 CRM 分类不意味着未来软件应把计费状态复制进 CRM。

## 正常与失败流程

正常：潜客申请 → 商家批准/联系 → B02 成交 → 顾客与会员分别记录 → B03 首次交付 → 欢迎消息 → 报表观测 → 客服处理 → 继续使用/期末取消/回流。买家可直接购买，不强制先成为候补。

欠费：识别欠费 → 提示更新支付方式 → B02 重试 → 成功则 B03 恢复访问，最终失败则取消。**暂停计费不等于停止访问**；期末取消与立即终止也不同。[生命周期](https://docs.whop.com/developer/guides/memberships)

售后：购买异常 → 联系商家/创建案件 → 商家接受、拒绝或补资料 → 超期平台处理 → 可申诉一次 → 终局通知；不是退款请求提交后就到账。[售后规则](https://docs.whop.com/manage-your-business/manage-payments/resolution-center)

同步失败：GHL 可能连错 agency/sub-account 或没有设默认支付；QuickBooks 错误页及重试机制不能证明其他集成同样处理。重复事件、导出权限、消息发送失败和批量误操作回滚是未来必须设计的检查，Whop 全部细节未知。

## 收费、依赖及集成

买家付商品/服务费给商家，经 Whop 处理；运营行为主要影响成交、续费和客服成本。独立 CRM、逐客服席位、Whop AI、报表或欢迎邮件收费未找到。公开费表的 Billing 项为每交易 0.5%，与发票、重试及生命周期相关；这是 B02 的收费边界，不能再给 B04 叠加一次“CRM 费”。外部软件自己的订阅及连接器合同价格未知。[费用](https://docs.whop.com/payments-and-billing/fees/fees)、[卖家条款](https://whop.com/seller-terms/)（文，2026-09-10）。

| 依赖 | 原因 |
|---|---|
| B01 | 用户/商家/团队权限/商品主数据；客服与财务操作权限分离。 |
| B02 | 计费合同和付款状态唯一来源；执行重试/退款/计费取消；B04 展示事实和发起获准操作。 |
| B03 | 会员访问权益及实际学习、预约、物流结果；处理找不到内容等交付工单。 |
| B05 | 接收消费者发现来源和公开评价引用；不复制发现与评价管理。 |

补充依赖：B07 给出推荐归因/佣金数据、B08 给出广告归因、B09 给出账本/到账事实、B10 持有售后裁定与税务口径、B11 持有外部集成合同、B12 提供 AI 支持能力。B04-F09/F10 是工作台接入点，不是这些业务真相的重复所有者。依赖是必需能力，不要求先建完对方模块，也不代表 Whop 内部代码关系。

## 第一个纵向切片与验收提议

**假设未来建设**：“顾客记录＋一条售后会话＋可执行的访问修复”，从真实服务闭环开始，尚未批准。

- B04-A01：同一顾客买两项商品，顾客表一行、会员表两行，客服能定位正确商品。
- B04-A02：未获退款权限的客服可以沟通/请求修复，但无法直接操作财务。
- B04-A03：一个访问故障从创建、回应、B03 修复到关闭全程可追踪；重复事件不创建第二个相同个案。
- B04-A04：期末取消、立即终止、暂停计费在顾客界面有不同文案和访问结果。
- B04-A05：报表先选择一个清晰指标（如首次成功访问率）；导出与页面同口径，并限制跨商家读取。

后续切片：加入/退出消息 → 候补批准 → 退款证据与申诉 → 一个 CRM/会计连接器；不要一次重建完整 HubSpot。

拟测指标：潜客到成交率、首次回应时间、解决时间、重复工单率、欠费恢复率、期末取消率、交付问题占比、同步失败率与人工修复量。全部是测量建议，非 Whop 当前数值。
