## 首批验证与业务验收

实验规模和投入上限唯一来源为[产品命题](product-thesis.md)：20个人日仅用于开发前访谈和无资金静态/可点击原型；最小可用系统建设及付费试点另批预算。付费试点在系统可用且启动检查通过后进行，上限2场首购＋1场另列预算的复购。30天复购指标衡量付费订单，复购实际履约另行核实，不承诺30天内完成建设或交付。访谈记录要包含日期、匿名客户编号、其采购角色、最近一次实际流程、花费/耗时的凭据类型、反对理由及下一步承诺。不得用“觉得不错”替代付费意愿，也不得为试点虚构客户logo。

原型任务：品牌能配置要求和总支出；创作者能解释拒绝/修改和收款状态；运营能处理一次争议和付款未知。真实试点每场先形成签署版活动规则和责任分配，结束后留存逐笔核对记录。改价、加名额或降低验收标准均计入实验偏差，不能与原方案混算。

一个人可参加活动也可属于品牌；每次操作按当前身份和组织授权。组织指独立品牌业务空间，不能跨组织查询数据。

| 角色 | 可以做 | 不可以做 |

## 核心规则：从活动到付款

1. 活动规则版本包含：品牌合同主体、审核负责人、作品要求、指定平台/账号、奖励金额与币种、名额、发布时间和提交/修改/申诉截止时间、审核承诺、取消安排、内容使用范围和期限、披露要求、费用及付款条件。截止显示马来西亚时区与完整日期。没有统一默认时效；每场填齐后才开放。
2. 默认只招成年人；资格按本活动约定人工核验并记录，不把内容审核称作法定身份核验。品牌确认有权提供素材；创作者确认原创、音乐/人物等授权。默认品牌仅取得明确列明的非独占使用权；付费广告使用、转授权、永久买断不自动包含，须另列同意范围。正式法律文本需专业确认。
3. 接受邀请时预留一个名额和该名额最大奖励额度，**预留的是承诺容量，不是银行冻结款**。奖励总上限=固定单帖奖励×名额数。平台服务费、通道费用、税及物流单列，不悄悄从奖励扣除。
4. 同一创作者同一活动最多1个有效名额和1个最终获奖作品。重复链接/同一作品复用进入人工核查；V1不承诺自动识别所有改编抄袭。名额到期或退出需满足合同条件才释放；有待审或争议不得自动释放造成超卖。
5. 先提交私有原稿供品牌预审；修改生成新版本。预审通过只表示该版本可按约定发布。创作者自行发布并提交最终链接、发布账号与时间、必要截图/文件。最终审核检查实际发布与批准版本、披露及权利要求一致；播放量不是计酬输入。
6. 人工最终批准同时且仅一次生成固定奖励义务，并把名额预留转为已承诺奖励。最终拒绝必须选择与既定规则相关的理由，附证据；给出约定申诉入口。不自动批准、不因审核员超时自动拒绝。
7. 到期未审进入运营催审/升级，保留名额和已有权利；超过约定服务期限时按合同进入取消或争议处理，不静默结案。新规则只用于新活动；在途作品不追溯降价、加要求或缩短期限。
8. 风险标记暂停相关付款动作并形成案件，不直接等同作品不合格或奖励取消。品牌处理交付判断，Wringy处理平台风险；不同意见通过证据和约定争议程序解决，不由技术人员裁决。
9. 奖励义务表示“依据合同应付多少”；付款条件满足表示“可以安排付款”；只有经核对的执行结果才显示支付事实。供应商账户入账与银行出款分开显示。不能把服务商收到了指令显示成“已到账”。
10. 活动暂停停止新加入；已有名额按已接受条款继续处理。关闭要求没有未决提交/申诉，奖励与资金余额可核对。取消不抹除已获批奖励；未使用资金退回须独立记录退款执行结果。

## 状态转换与负责人

状态转换指只有满足条件才允许从一个阶段进入下一阶段。正常状态与风险暂停分开，避免“封禁”抹掉旧账。

| 对象 | 正常转换 | 异常及约束 |
|---|---|---|
| 活动 | draft → ready → open → closing → closed | ready要求条款/负责人/预算与资金路径就绪；open可paused，恢复需复核；cancelled须处理存量义务才结案 |
| 名额 | invited → accepted → active → completed | 邀请可declined/expired；接受时原子预留额度；退出/释放须无待审/争议或有已记录裁决 |
| 原稿 | draft → submitted → reviewing → approved_for_publish | reviewing可changes_requested → submitted（新版本），或rejected；原版本和理由保留 |
| 最终作品 | submitted → reviewing → approved/rejected | reviewing可changes_requested；拒绝可appeal_open → upheld/overturned；改判approved只产生一次奖励 |
| 奖励义务 | recorded → payable → settled | 记录后可held；解决后恢复原阶段。settled仅对应已核对清偿证据；冲正用独立adjustment，不修改历史金额 |
| 付款尝试 | prepared → authorized → submitted → processing → confirmed | failed/unknown/returned独立；unknown先查证，不另付；confirmed注明provider_credit或bank_payout及证据 |
| 支持/申诉 | open → evidence_needed → decision → resolved | 超时升级；奖励争议未解决不能无理由释放资金；裁决保留人、依据、时间和涉及金额 |
| 退款 | requested → approved → submitted → confirmed | rejected/failed/unknown；批准退款不表示退款到账 |

义务settled与创作者银行到账不是同义词：是否服务商账户入账已构成合同清偿须在资金关卡确定。未确定时维持“待确认清偿”，显示已经观察到的阶段，不猜测。部分付款时逐笔显示清偿金额和剩余义务，不把全额标已结清。退款、退回和追索按架构定义独立关联。

## 钱的路径与例子

统一对外用语：**内容获批（content-approved）**表示最终发布作品符合活动要求，并生成奖励义务；**奖励符合付款条件（reward-eligible）**表示身份、资金覆盖、约定付款条件与风险核查均通过，可以安排付款；**已付款（paid）**须注明是服务商账户已入账还是银行出款已确认，并附对应核对证据。前两项都不能显示为已付款；“原稿获准发布”甚至还不是最终内容获批。义务的payable对应reward-eligible，不单靠品牌审核决定。

**推荐主路径：**品牌按已批准合同向合格服务商支付 → 服务商提供可核对资金记录 → Wringy开放相应承诺容量 → 最终作品获批产生奖励 → 核验/争议条件满足后发出支付指令 → 服务商管理创作者收款/出款 → Wringy按证据显示不同阶段。服务商路径在活动开放、每次接受新名额及每次付款前必须验证：**经核实且已分配给该活动的可用服务商资金 ≥ 受保护名额金额＋未清偿奖励＋适用费用负债**。接受新名额时按加入该名额后的总额检查并原子预留；同一资金不得跨活动重复分配。冻结、限制、未清算或状态未知的资金不计可用覆盖；付款在途仍计入占用，直到执行结果已核实。覆盖不足或证据过期/不明时阻止开放、新名额和相关付款，转对账处理。服务商能否支持这条链尚未验证；Wringy不自行承诺保管、储值、互转或跨境汇款。

**人工备选（另行批准）：**品牌直接付创作者；Wringy记录付款义务，核对品牌凭证和创作者/银行可确认的收款证据。单张上传截图只到“凭证待核对”。这一路径必须在邀请、规则和奖励页标“未预存资金的品牌付款承诺”，列明品牌债务人及约定到期日；不是托管或资金保障。品牌未付款时显示逾期待处理，由合同指定责任人处理，Wringy不自动垫付。平台服务费单独开票/收取；这条路径不能对外称作平台托管保障。

若以上均不成立，仅运行无真实资金的原型，不开展付费试点。不能自动回退到Wringy私人或公司银行账户代收奖励。

示例仅用于理解：2个名额，每条奖励RM100，奖励承诺上限RM200；品牌另付待议服务费及费用。一个名额获批后，应付奖励RM100，另一个仍预留RM100；此刻银行到账可以仍为0。若首笔付款状态未知，不重新发送第二笔RM100。此金额不是推荐售价或市场费率。服务费未选择；如另用10%举例，只能写“假设品牌在RM100创作者奖励之外另付RM10，创作者不扣平台费”，不能写成实际报价或已批准费率。

## 启动与停止条件

启动真实试点前需同时具备：创始人批准命题/本PRD/架构及现金投入上限；实际品牌和创作者签署条款；支付路径、责任主体、清偿节点、费用和退款/损失处理书面确认；产品权限、对账和回滚验收；上线前具名指定付款经办人与另一位独立复核人，并确认权限、可投入时间和替补安排；同一人不能准备并批准同一笔付款，未落实不得上线；隐私和权利核验完成。支付服务商选择及责任详见[架构决策关卡](architecture-v1.md#支付服务商决策关卡)。运营预算池只是费用占位，没有确认在岗人员；Belcort负责开发不自动代表提供日常审核、财务或独立付款复核。没有批准的设计层，目前只能将页面清单交设计验证，不能把旧稿当冻结设计。

投入与复购门槛见命题。不明资金差异、重复付款、跨品牌数据泄露或无法履行既有义务时立即暂停新活动及相关出款，保全记录、调查并由创始人决定恢复；暂停不得删掉已有债务。尚无上线日期或供应商服务时效承诺。

| AC-03 | 只剩1个名额时两人同时接受，仅1人成功；容量不超限；重复请求不重复预留。服务商资金覆盖小于加入后受保护名额＋未清偿奖励＋费用负债时拒绝加入；不同活动不能重复占用同一资金 |
| AC-04 | 修改活动后旧参与者仍能看到并按原版本执行；不能追溯降价；新增条款需新活动/明确同意 |
| AC-05 | 预审批准不产生奖励；新版本留痕；最终作品不符合批准版本时可说明原因并要求修改 |
| AC-06 | 最终批准重试或两个审核员同时批准只生成1笔义务；单帖金额来自已接受条款，客户端不能改金额 |
| AC-07 | 拒绝必须有规则关联理由；审核超时进入催审；申诉改判记录原决策与新决策且只奖励1次 |
| AC-08 | 展示recorded、payable、供应商入账和银行付款差别；没有银行证据绝不显示“银行已到账” |
| AC-09 | 重复/乱序付款事件不重复记账或将已确认结果倒退；超时unknown先查证，重试不重复付 |
| AC-10 | 付款失败保留义务，退回重新建立待处理金额；部分付款仅冲抵对应金额 |
| AC-11 | 未付奖励撤销需有裁决与独立调整；已付奖励争议进入追索，不能伪造银行退款或扣别场奖励 |
| AC-12 | 有未决作品/申诉/应付款不可释放相关预算；退款批准与执行分开。服务商覆盖低于受保护名额＋未清偿奖励＋费用负债时，活动开放、新名额与相关付款均被阻止，冻结/未清算资金不计可用。直付备选必须显示未预存的品牌承诺和到期日，不显示托管保障 |
| AC-13 | 人工付款凭证需第二人核对，上传者不能自批；unknown禁止切换人工另付；审计可查原文件和复核依据 |
| AC-14 | 社交接口不可用/链接删除进入证据补充或争议；不填假观看量、不自动减少按帖奖励 |
| AC-15 | 内容附件默认私有；泄漏链接失效/撤权可验证；导出权限与原记录一致，审计不包含完整银行/身份秘密 |
| AC-16 | 角色撤销立即影响敏感操作；运营风险暂停不能直接取消应付款；财务与内容审核权限分离 |
| AC-17 | 金额以MYR最小单位计算；输入负数/错误币种被拒；报表总数可追到作品、义务和付款记录 |
| AC-18 | 从邀请到预审、发布、奖励、付款确认及一次退款/退回的完整演练可追溯；测试与真实数据分开 |
| AC-19 | 发布回滚与备份恢复演练后，已发付款不重复发送、历史义务不消失；差异先阻断出款再核对 |
| AC-20 | 手机与桌面均可读清金额、期限、理由和下一步；关键操作键盘可用，错误不清空已输入内容 |

## 上线后衡量：定义先于数字

| 指标 | 分子/分母与来源 | 使用边界 |
|---|---|---|
| 首次付费 | 已实际支付服务费的独立品牌数；发票/收款核对 | 奖励预算和免费试点不是平台收入 |
| 合格提交率 | 最终获批作品数÷至少完成一次有效最终提交的名额数 | 排除重复版本；同步展示待审数量，未审不算拒绝 |
| 履约完成率 | 按约完成作品名额数÷已接受名额数 | 取消/超时单列原因，不藏分母 |
| 审核耗时 | 每次进入审核至有理由决策的时长，中位数及最长值 | 修改等待时间单列；小样本展示原始数量 |
| 30天品牌复购 | 首场关闭后30天内再次付费品牌数÷已有完整30天观察的首场付费品牌数 | 尚未满窗口单列，不提前当流失 |
| 创作者再次参与 | 首场完成后30天内加入另场人数÷满30天窗口的完成者数 | 同场改稿不是重复参与；是否有第二场机会单列 |
| 付款可信度 | 到期仍未核实金额/笔数、unknown时长、差异笔数 | 服务商账户入账与银行出款分别统计 |
| 每场直接贡献 | 确认服务收入－退款－支付费－招募/审核/支持工时成本－直接补贴/损失 | 费用报价与实际分开；不包含创作者本金作收入；开发维护成本另列 |
| 人工依赖 | 每场销售、招募、审核、付款核对及客服工时 | 创始人免费劳动也记录，不把零工资当零成本 |

建议试点目标见命题；不得写成行业标准或承诺结果。指标事件必须带活动、组织、时间、是否模拟和版本，不采集无用的社交个人资料。
