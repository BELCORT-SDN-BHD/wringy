# Wringy 产品命题｜一页建议稿

2026-09-10 · 待创始人审阅；没有产品范围批准、商业验证或上线授权。

**一句话成功定义：**让一家马来西亚品牌愿意再次付费采购创作者原创内容，并让每条获批内容的奖励、实际付款及异常处理都可核对；之后才扩大为东南亚创作者商业平台。

## 为谁解决什么

首批客户候选：马来西亚有持续短视频需求、能提供产品样品、能接触预算决策人的日用消费品品牌；先直接服务品牌，代理商仅可作为介绍渠道。首批供给候选：能够在当地完成产品演示、同意明确内容授权的成年创作者。没有已确认客户、意向合同或客户访谈。假设痛点是品牌用聊天、表格反复追踪要求、修改与付款，创作者不清楚何时算交付合格。例子：品牌要十条产品演示，双方先约定验收清单，发布后的作品合格才产生固定报酬，播放量只作参考。

## 建议第一条完整业务链

邀请制活动 → 明示每条获批帖子的固定奖励和名额 → 创作者接受规则 → 原创内容预审与修改 → 创作者自行发布并提交证据 → 人工最终审核 → 奖励义务记录 → 支付核对 → 争议处理和复购。UGC指创作者为品牌制作的原创内容。**建议采用按获批帖子付费，不承诺观看量或销量；预审通过不是最终奖励批准。** 不用未经验证的社交数据接口决定报酬。建议试点按活动向品牌单独收取明确服务费，创作者不另付平台服务费；金额、税费与通道费承担者须在试点报价中确认，没有默认抽成率。

资金主方案候选：符合双方资格、经合同确认的支付服务商管理资金流，Wringy记录规则和奖励义务；服务商尚未选择。若不可行，可另批准品牌直接付款、Wringy人工核对的试点；不能悄悄改为Wringy代收、储值或钱包。支付义务不等于银行到账，演示数据必须标为模拟。

## 为什么值得验证，而非已被证明

[市场研究§2–5](../deliverables/research/sea-market.md)整理了本地品牌激励案例与已有竞争，支持做实验，不能证明Wringy需求。HEXA仅为研究中记录的公开案例，不是本项目客户。[CR流程研究第5、9、12–15项](../research/cr-v2/product-flows.md)提供按帖、预审及审核的参考；[资金研究第7–13项](../research/cr-v2/money-version.md)提示规则和到账必须分开。这里引用内部研究快照，没有新增供应商能力、价格或法规结论。

## 验证实验与投入边界（全部为建议）

先访谈5位品牌预算负责人、8位创作者，要求看去敏后的最近合作流程、采购依据和实际耗时；用原型测试双方能否说清“获准发布、最终获批、已付款”的差别。再招募2个真实付费品牌，各做1场、最多5位创作者且每人1条内容；同一法人多品牌须单列，不能当独立客户。招募目标不是已拥有名单。原型使用虚拟资金；真实试点必须先通过[PRD启动条件](prd-v1.md#启动与停止条件)。

建议验证投入上限：20个人日，最多2场付费活动；这不是日历交付承诺。现金上限尚缺：奖励预算、服务费、样品/物流、招募、审核支持、支付和专业确认费用须逐项报价，由创始人批准总上限后才能支出。先批准研究投入也不等于批准真实付款。

继续条件建议：2场均完成可核对闭环，至少1个独立付费品牌在其首场关闭后30天内签下一场并实际付费；所有已到期款项已核实或有明确责任人和解决安排；逐场算出服务收入减直接履约成本，区分正常价与补贴。若只有免费参与、无法取得采购依据、资金资格不成立，或投入耗尽仍无付费承诺，暂停扩建并修订假设。小样本只决定是否值得下一轮，不能证明市场规模。

## 长期边界、负责人及缺口

完整Whop的12板块保留在[产品总图](product-map.md)，本试点是排序候选。后续依据复购与需求扩展经营工具、交易交付、再逐国验证，不承诺同时建设12块。产品和商业由Wringy负责；开发由创始人关联公司Belcort承接，不自聘工程团队，合同、资源和知识产权未落实。[蓝图§5](investor-product-blueprint.md)的成本仅是规划估算，不是报价或融资额。

## 核心规则：从活动到付款

1. 活动规则版本包含：品牌合同主体、审核负责人、作品要求、指定平台/账号、奖励金额与币种、名额、发布时间和提交/修改/申诉截止时间、审核承诺、取消安排、内容使用范围和期限、披露要求、费用及付款条件。截止显示马来西亚时区与完整日期。没有统一默认时效；每场填齐后才开放。
2. 默认只招成年人；资格按本活动约定人工核验并记录，不把内容审核称作法定身份核验。品牌确认有权提供素材；创作者确认原创、音乐/人物等授权。默认品牌仅取得明确列明的非独占使用权；付费广告使用、转授权、永久买断不自动包含，须另列同意范围。正式法律文本需专业确认。
3. 接受邀请时预留一个名额和该名额最大奖励额度，**预留的是承诺容量，不是银行冻结款**。奖励总上限=固定单帖奖励×名额数。平台服务费、通道费用、税及物流单列，不悄悄从奖励扣除。
4. 同一创作者同一活动最多1个有效名额和1个最终获奖作品。重复链接/同一作品复用进入人工核查；V1不承诺自动识别所有改编抄袭。名额到期或退出需满足合同条件才释放；有待审或争议不得自动释放造成超卖。
5. 先提交私有原稿供品牌预审；修改生成新版本。预审通过只表示该版本可按约定发布。创作者自行发布并提交最终链接、发布账号与时间、必要截图/文件。最终审核检查实际发布与批准版本、披露及权利要求一致；播放量不是计酬输入。
6. 人工最终批准同时且仅一次生成固定奖励义务，并把名额预留转为已承诺奖励。最终拒绝必须选择与既定规则相关的理由，附证据；给出约定申诉入口。不自动批准、不因审核员超时自动拒绝。
7. 到期未审进入运营催审/升级，保留名额和已有权利；超过约定服务期限时按合同进入取消或争议处理，不静默结案。新规则只用于新活动；在途作品不追溯降价、加要求或缩短期限。
8. 风险标记暂停相关付款动作并形成案件，不直接等同作品不合格或奖励取消。品牌处理交付判断，Wringy处理平台风险；不同意见通过证据和约定争议程序解决，不由技术人员裁决。
9. 奖励义务表示“依据合同应付多少”；付款条件满足表示“可以安排付款”；只有经核对的执行结果才显示支付事实。供应商账户入账与银行出款分开显示。不能把服务商收到了指令显示成“已到账”。
10. 活动暂停停止新加入；已有名额按已接受条款继续处理。关闭要求没有未决提交/申诉，奖励与资金余额可核对。取消不抹除已获批奖励；未使用资金退回须独立记录退款执行结果。

## 状态转换与负责人

状态转换指只有满足条件才允许从一个阶段进入下一阶段。正常状态与风险暂停分开，避免“封禁”抹掉旧账。

| 对象 | 正常转换 | 异常及约束 |
|---|---|---|
| 活动 | draft → ready → open → closing → closed | ready要求条款/负责人/预算与资金路径就绪；open可paused，恢复需复核；cancelled须处理存量义务才结案 |
| 名额 | invited → accepted → active → completed | 邀请可declined/expired；接受时原子预留额度；退出/释放须无待审/争议或有已记录裁决 |
| 原稿 | draft → submitted → reviewing → approved_for_publish | reviewing可changes_requested → submitted（新版本），或rejected；原版本和理由保留 |
| 最终作品 | submitted → reviewing → approved/rejected | reviewing可changes_requested；拒绝可appeal_open → upheld/overturned；改判approved只产生一次奖励 |
| 奖励义务 | recorded → payable → settled | 记录后可held；解决后恢复原阶段。settled仅对应已核对清偿证据；冲正用独立adjustment，不修改历史金额 |
| 付款尝试 | prepared → authorized → submitted → processing → confirmed | failed/unknown/returned独立；unknown先查证，不另付；confirmed注明provider_credit或bank_payout及证据 |
| 支持/申诉 | open → evidence_needed → decision → resolved | 超时升级；奖励争议未解决不能无理由释放资金；裁决保留人、依据、时间和涉及金额 |
| 退款 | requested → approved → submitted → confirmed | rejected/failed/unknown；批准退款不表示退款到账 |

义务settled与创作者银行到账不是同义词：是否服务商账户入账已构成合同清偿须在资金关卡确定。未确定时维持“待确认清偿”，显示已经观察到的阶段，不猜测。部分付款时逐笔显示清偿金额和剩余义务，不把全额标已结清。退款、退回和追索按架构定义独立关联。

## 钱的路径与例子

**推荐主路径：**品牌按已批准合同向合格服务商支付 → 服务商提供可核对资金记录 → Wringy开放相应承诺容量 → 最终作品获批产生奖励 → 核验/争议条件满足后发出支付指令 → 服务商管理创作者收款/出款 → Wringy按证据显示不同阶段。服务商能否支持这条链尚未验证；Wringy不自行承诺保管、储值、互转或跨境汇款。

**人工备选（另行批准）：**品牌直接付创作者；Wringy记录付款义务，核对品牌凭证和创作者/银行可确认的收款证据。单张上传截图只到“凭证待核对”。品牌未付款时显示逾期待处理，由合同指定责任人处理，Wringy不自动垫付。平台服务费单独开票/收取；这条路径不能对外称作平台托管保障。

若以上均不成立，仅运行无真实资金的原型，不开展付费试点。不能自动回退到Wringy私人或公司银行账户代收奖励。

示例仅用于理解：2个名额，每条奖励RM100，奖励承诺上限RM200；品牌另付待议服务费及费用。一个名额获批后，应付奖励RM100，另一个仍预留RM100；此刻银行到账可以仍为0。若首笔付款状态未知，不重新发送第二笔RM100。此金额不是推荐售价或市场费率。

## 启动与停止条件

启动真实试点前需同时具备：创始人批准命题/本PRD/架构及现金投入上限；实际品牌和创作者签署条款；支付路径、责任主体、清偿节点、费用和退款/损失处理书面确认；产品权限、对账和回滚验收；具名运营/财务双人复核覆盖；隐私和权利核验完成。支付服务商选择及责任详见[架构决策关卡](architecture-v1.md#支付服务商决策关卡)。没有批准的设计层，目前只能将页面清单交设计验证，不能把旧稿当冻结设计。

投入与复购门槛见命题。不明资金差异、重复付款、跨品牌数据泄露或无法履行既有义务时立即暂停新活动及相关出款，保全记录、调查并由创始人决定恢复；暂停不得删掉已有债务。尚无上线日期或供应商服务时效承诺。
