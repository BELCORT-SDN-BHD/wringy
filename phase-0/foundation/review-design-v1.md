# Wringy 审核、计量与争议设计草案

2026-09-10｜**提案，未冻结、未开发**。本轮授权补基础稿，不构成产品规则、费率、服务时限、支付通道或正式PRD批准。本文不改写历史PRD与现有deck。

## 意图、依据与地基状态

服务品牌审核员、创作者、平台风险运营及财务。成功标准：任何一笔奖励，都能解释谁按哪版要求审了什么、哪些播放计钱、异常由谁处理、钱处于哪一阶段；全部审核劳动可回流成本模型。

当前商业方向来源：[business-model-v2.md](business-model-v2.md)及[创始人记录](../founder-inputs.md)，按合格播放／约定效果组织奖励；15%及RM算例尚未批准。产品归属：[product-map.md](product-map.md)的B06品牌合作，协同B09资金、B10风险与争议。研究依据：[本轮核查](../research/review-mechanisms-v1/findings.md)与[一手台账](../research/review-mechanisms-v1/source-ledger.md)。

地基检查：问题/方向有记录，但首批客户需求与付费证据不足；当前[历史PRD](prd-v1.md)自注固定按帖规则已不适用新方向；[品牌组件规范](design-v3/brand-components-spec.md)仍为未批准提案。正式计量口径、活动协议及完整实施规格缺失。推荐先补规则和数据权限；本稿在明确记录缺口下继续做已授权的设计讨论，不据此启动工程。粗估补齐讨论2小时、样本和数据字段核对1–2工作日，不含供应商准入与法律审查。

## 事实借鉴与产品选择分开

| 经核实的CR事实 | Wringy提案及理由 |
|---|---|
| 品牌人工终审，客服不能代品牌决定内容；风险标记由CR处理；自动标记不自动拒绝（C §§7、9–10；O §§6、8） | 内容决定与风险裁决分开权限；拒稿复议交品牌重审，管理员记录协调结果；平台治理另立案件，不能冒充品牌批准 |
| 可选草稿审批，草稿通过不等于公开帖子通过（C §8） | 预审是可配置阶段；显示批准的是哪一版、哪个账号。是否首发强制预审待决定 |
| 已公布要求才可用于拒稿（O §§5.6、6.5） | 参与时保存适用要求版本；拒绝选择具体不符项与证据；新版本不得静默覆盖既有义务 |
| 0–100第三方辅助风险分数，私有算法，活动阈值可配（P §6；O §8） | 展示可解释疑点、数据来源及人工结论；Wringy评分范围、供应商、模型与阈值均未选定，不复制数值当设计默认 |
| CPM目前7天计酬＋3天等待，合同可调整且风险暂停（C §7.3；O §6.2） | 活动必须明确自己的时钟；不继承CR期限、不设置任意统一审核承诺 |
| CR保存草稿/讨论证据，同时受隐私保留限制（P §§4、10） | 证据可追溯，但原始接口数据按来源限制保存；可审计不等于永久保存全部媒体或个人数据 |

C/O/P等是[台账](../research/review-mechanisms-v1/source-ledger.md)内官方来源代号。以下页面、状态、字段与验收**全部是Wringy建议**，不宣称CR已提供相同后台或能力。

## 四条状态线，另附风险与活动状态

| 状态线 | 候选状态 | 不可混淆 |
|---|---|---|
| 内容 | 草稿待审 → 需修改/预审通过/预审拒绝；发布后待终审 → 最终通过/拒绝 | 预审与终审各有决定，不合并成一个Approved；批准不代表权利无限转让 |
| 计量 | 待数据 → 采集中 → 待核验 → 已核验；旁支不可取得、需修正、窗口截止 | 计数增长不是已获付款；断连不是零观看或作弊 |
| 奖励 | 估算中 → 资格已确认/累积中 → 待结算 → 可提现应付；旁支风险暂停、未结算逆转 | “可提现”不等于付款已发出；已结算追索另记调整/债务，不改写原流水 |
| 付款 | 未发起 → 已发起 → 处理中 → 到账确认；旁支失败、结果未知、退回 | 付款服务商受理不是银行到账；以可核对凭证确认，保留通道语义 |

风险状态独立存在，一个内容已通过的作品仍可有开放风险，导致奖励暂停。活动的运行/暂停/结束、预算充足/不足/耗尽也独立：停止新稿不自动取消已有应付义务。具体转移条件须进入正式规格；这里不设计数据库或接口。

## 计入播放快照、预算与规则版本

每次计酬应能展开一张“本次怎么算”记录：活动及投稿、规则版本、平台/账号/帖子、发布时间、提交时间、批准时间、计酬窗口起止、采集时刻及时区、原始播放、剔除播放及理由、最终计入数、此前已计入数、本次增量、计酬单价、金额门槛、单稿/创作者/活动上限（仅启用者）、可用预算、毛奖励、费用及净奖励、审核人和生成时间。

“计入播放”是按本次适用规则核算的数据快照，不是永不变化的社交计数。重复计量不得重复计钱。数据修正产生关联的新记录，说明增减及谁批准；原记录仍可核对，具体原始数据可见性遵守来源保留规则。

金额示例仅沿用[商业模式算例](business-model-v2.md)：50,000合格播放×RM5/千次＝RM250，上限和预算可能限制金额。若两稿同时竞争最后一笔预算，不可都显示全额保证；分配顺序、预留时点、补资后的追补规则需先由创始人决定。此处不把旧Whop先到先得直接当Wringy政策。

规则编辑必须保存改前/改后版本、理由、作者、生效时刻与受影响参与者。建议既有提交沿用原接受版本；例外须说明同意、补偿或强制治理依据。新增风险模型可以触发重新复核，但不能静默改掉旧内容要求或按新单价重算已赚金额。活动复盘提出的规则改变生成待批准的新版本，不回溯修改历史证据。

## 证据来源与访问

证据逐件标明来源：官方平台授权数据、公开帖子观察、创作者提交材料、品牌反馈、人工调查、风险服务输出。记录采集者/提交者、时间、对应帖子/版本、使用目的、来源引用及可验证摘要；截图与自报数据不自动升级为已核验数据。未能确认的数据标“未知”，不杜撰算法判断。

创作者看自己的要求、理由、提交与申诉证据；品牌只看本活动履约所需内容及必要计量信息；风险运营按案件授权访问受限证据；财务看核算/执行依据及聚合工作量。银行资料、平台授权凭据、与案件无关的个人资料不进入审核页或成本报表。访问与导出留记录，跨组织数据不得混入。

应保存证据到何时必须按数据来源与适用政策定，不统一“永久留存”。如原始数据需删除，保留允许保存的核算/决策记录和删除说明；不可声称原材料还可验证。导出的脱敏摘要与原证据是不同对象。Wringy具体保留策略待确认，不能把CR对YouTube的声明当作已完成Wringy接口合规。

## 实际工作量回流财务（新增明确要求）

这是Wringy设计要求，**不是对CR经营成本或既有后台的事实描述**。财务模型必须覆盖所有提交，不仅覆盖获批稿、计酬播放或已经付款的作品。

| 反馈项 | 应如何记录/汇总 | 防止失真 |
|---|---|---|
| 总工作量 | 按活动/统计期：全部投稿、独立作品、草稿版本、终审次数、拒稿、开放/已结风险、申诉、复审、退款和付款异常案件 | 稿件数、版本数、操作次数分别统计；拒稿和不成立申诉不排除 |
| 实际处理时间 | 每次人工工作记角色、案件/投稿、处理类别、主动分钟、记录方式（计时/人工估计）、修正记录 | 等待品牌/创作者回应时间另列；页面打开时间不全算劳动；同一工作不重复计时 |
| 质量与瓶颈 | 拒稿率、标记率、申诉率、改判率、每稿/每案分钟、中位及较慢区间、待审年龄、重做轮数、工时缺失比例 | 分母明确；标记率不是欺诈率，改判率不是算法准确率；样本少时提示 |
| 成本输入 | 各角色实际分钟÷60×财务确认的完整小时成本；加已核对的计量、风险、支付通道账单及确认损失 | 单价附来源/日期；分别标已发生、估算、缺失；运营/品牌外部承担成本不混为Wringy成本 |
| 活动贡献反馈 | 活动实际收入与人工、计量、风险、支持、支付等成本对照；可辅列每投稿成本及每千合格播放成本 | 收入与成本期间一致；合格播放为零仍展示总成本；不能除零或隐藏失败活动 |

给财务worker的汇总合同：活动、期间、承担方、总投稿/终审/拒稿/标记/申诉/复审数、按角色与类别实际分钟、工时覆盖率、外部费用与出处、实际收入、确认损失、仍未知项。共享汇总不含作品私密材料。用实际数据逐步替换business-model-v2中的RM600成本占位；本任务不改该源、不发明审核速度或供应商准确率。

## 待创始人及主任务收口

优先决定：什么算合格播放及数据不可得时的处理；何时占预算与预算短缺顺序；品牌不回应的升级路径；已结算追索权限与资金承担；审核劳动由谁支付。再确认预审适用活动、修改/申诉次数、活动各时钟、证据保留及法律文本。**没有预先设置任意SLA（保证处理时限）、付款日期或算法准确率。**

全部是产品/设计基础提案；尚无数据接口证明、已签供应商、真实风险案件、实测审核分钟和客户付款证据。后续正式PRD需要逐项批准、核验数据权限、实际案例试跑及Belcort重新估价。地基缺口已报告，本任务没有部署、冻结或实现任何规则。
