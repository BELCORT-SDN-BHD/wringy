# Wringy 本地化基础 v1 · Belcort 交接

2026-09-11。语言方向已批准；以下实现合同为交接提案，不代表全平台翻译、生产验证或数据库结构已获批准。

## 依据与边界

- 批准依据：[创始人输入](../founder-inputs.md)最新「华语与偏好语言体验｜2026-09-11」：马来西亚首发，面向用户提供 English、Bahasa Melayu 与简体中文；内部设计说明继续中文。
- 设计依据：[设计系统 v2](design-system-v2/README.md)：Linear 页面结构＋官方 shadcn 组件与行为，只调整获授权配色。本地化不重建组件或改变状态表现。
- 业务依据：[领域状态提案](design-system-v1/domain-states.md)：内容、计量、奖励、付款与风险分别表达；其中中文是内部解释，不是生产产品文案。该文档的资金政策、接口与结构仍为提案。
- 当前本地原型范围：由主工作者为颜色／状态演示加入小型语言 Select 与集中管理的三语文案。仅此区域本地化；组件图库及中文设计说明不在本轮全量翻译范围。实现覆盖与测试状态以文末对应报告为准，不代表全平台本地化完成。

主要风险：翻译把「审核通过」或「可提现」简化成「已到账」。三种语言必须保留同一业务事实与证据边界。

## 语言与选择

| 项目 | 交接规则 |
|---|---|
| 语言代码 | `en-MY`、`ms-MY`、`zh-Hans-MY`；简体中文为本轮书写形式假设；语言代码同时指定马来西亚地区格式 |
| 选择器名称 | 始终显示 `English`、`Bahasa Melayu`、`简体中文`，不使用国旗，不把马来文称为 Indonesian |
| 首次显示 | 本地示例暂用 English；未来产品先恢复明确偏好，没有偏好时只把浏览器支持语言作为建议，无匹配则建议 English，再询问用户；不能按姓名或族群推断 |
| 未来产品偏好 | 用户明确选择优先并持久保存，返回应用后恢复；登录用户跨设备偏好与访客本机偏好的同步方案由 Belcort 提交实现规格，不在此批准存储结构 |
| 页面语言 | 独立面向用户的应用根元素设置对应 `lang`；中文内部演示页保持中文根语言，但三语演示区域单独设置 `lang="en-MY"` 、`lang="ms-MY"` 或 `lang="zh-Hans-MY"`，随选择同步 |

按钮、标签、辅助说明、无障碍名称、校验错误、toast（短暂操作反馈）、审核及出款指引均从同一组稳定文案键读取，不在页面散落三套字符串。邮件与页面共用术语和业务规则版本；切换语言不能切换政策版本。面向用户的选择器说明也应属于该语言区域。

长文字允许自然换行，采用适应内容的布局，不靠固定宽度或省略关键条件容纳译文；保持官方组件内部样式。若官方组合无法容纳，记录布局缺口交主工作者处理，不擅自改造组件。

## 日期、金额与单位

- 日期使用 `Intl.DateTimeFormat`，数字与金额使用 `Intl.NumberFormat`，传入选定语言代码；事件展示明确指定 `Asia/Kuala_Lumpur`。金额明确指定币种 `MYR`，交易明细显示币种代码；切换语言只改变格式，不换汇、不改金额、费用或计算精度。
- 事件使用来源的绝对时间戳，展示事件发生时间、数据来源及最后确认／更新时间，避免把页面刷新时间当作业务发生时间。付款与截止时间标明马来西亚时间及 `UTC+08:00`；相对时间可查看完整绝对时间，审计／导出保留原始 ISO 时间与时区信息。
- 使用年月日齐全、月份文字等无歧义展示，避免裸写 `09/11/2026`。纯日历日期按日期处理，不经 UTC 转换造成前一天；窗口开始、结束及是否包含边界由业务规则提供，不能由语言决定。
- 后端金额采用整数最小货币单位是**待批准建议**：例如 MYR 12.34 可表示为 1234 sen 加币种。此例不是已批准数据库结构，也不批准舍入、费率或尾差规则；展示舍入不得反写账务原值。
- 已知零、未知、未填写与不适用分别表达；未知金额／费用不得显示 MYR 0.00。保留负号并写明收入、支出或退款方向，不能只靠红绿颜色说明。
- 指标必须携带单位和定义：`qualified views` 表示按活动规则核验的合格播放，不是原始播放、独立人数、订单或销量；马来文译名须保留此限定并经专业复核。若显示每千次播放单价，三种语言都必须保留「每 1,000 次合格播放」、期间及口径版本，不简写成每次播放价格。换语言不得改变分母、期间或数值。

## 状态、关键说明与内容

- 同一状态在三种语言使用完全相同的颜色、图标和组件变体，只翻译文字；颜色／图标仍须配状态文字。状态语义颜色来自既有设计系统源，不在翻译表中另建配色。
- 服务端状态码、错误码、事件名保持稳定；译后标签只能用于展示，服务端不得把 `Approved` 或马来文标签当作状态码。未知状态不能猜成成功；服务端事实与允许动作不因切换语言变化。
- 保留「预审通过≠终审通过」「内容通过≠付款」「可提现≠到账」「通道受理≠银行确认」。审核、付款、风险说明必须各自指向实际责任方与证据，不能用一个成功提示覆盖多个领域。
- 校验、邮件、toast、审核理由模板、出款步骤与确认文案按稳定键、语言及适用规则版本配对；发布时检查三种语言键完整、参数一致、版本匹配。历史决定继续对应当时规则，不能套入新政策译文。
- 金额、费用、收款方、付款确认、审核与出款条件等关键文案缺译或版本不匹配时，不静默混入另一语言。明确告知当前语言说明暂不可用；需要这些说明才能确认的资金动作暂停，提供重试或由用户明确选择完整可用语言的路径，不改已有付款事实。
- 用户投稿、评论、店铺描述及证据保留原文，不自动翻译或覆盖；平台自己的标签和系统说明仍按所选语言显示。

## 偏好语言体验 · 当前产品设计方案

用户已要求主动询问偏好。以下明确未来产品行为；当前展示库仅有三语选择样例，没有真实账号偏好服务。

| 时机 | 呈现与行为 | 例子／恢复方式 |
|---|---|---|
| 首次进入、没有明确偏好 | 用浏览器支持语言建议初始界面，显示轻量内联选择，不用全屏强制关卡；三项始终用各自语言名称 | 标题「你希望使用哪种语言？」；说明「之后可随时在设置中修改。」 |
| 选择与继续 | 可预览选项；点击继续后才记为明确选择，后续页面与系统消息使用该语言 | English / Bahasa Melayu / 简体中文；不以国旗代替语言名 |
| 暂时跳过 | 继续使用当前建议语言，本次浏览不再反复询问；跳过不记录成明确语言偏好 | 显示「暂时跳过」，保留固定语言入口 |
| 注册／登录 | 注册时带入已明确选择，避免重复提问；若此前跳过，在注册资料中提供可选语言字段 | 同一人使用新设备时恢复账号偏好；当前会话新的明确选择优先，不被旧账号记录静默覆盖 |
| 随时修改 | 设置中有固定Language / Bahasa / 语言入口；明确更改立即更新界面，并按账号／访客范围保存 | 不清空已填写内容，不跳回首页，不重发正在进行的提交 |
| 保存失败或浏览器不允许保存 | 当前界面仍可切换，明确提示偏好尚未保存，提供重试；不显示虚假保存成功 | 区分「已切换语言」与「偏好已保存」 |

未来产品解析顺序：当前会话明确选择 → 已保存账号偏好 → 访客明确保存的偏好 → 浏览器支持语言建议 → English建议。登录后访客选择是否同步，按当前会话的明确选择执行并给可撤销修改入口；不能把共享设备上另一用户的偏好覆写到账号。偏好持久化的数据方案留给实际工程规格。

浏览器语言只用于建议。对于无法明确匹配的中文书写形式（例如繁体），仍展示「简体中文」的真实名称，允许用户自己选，不宣称提供繁体翻译。

### 首次询问文案草案

| 用途 | English | Bahasa Melayu | 简体中文 |
|---|---|---|---|
| 标题 | Which language would you prefer? | Bahasa manakah yang anda pilih? | 你希望使用哪种语言？ |
| 说明 | You can change this anytime in Settings. | Anda boleh menukarnya pada bila-bila masa dalam Tetapan. | 之后可随时在设置中修改。 |
| 继续 | Continue | Teruskan | 继续 |
| 跳过 | Skip for now | Langkau buat masa ini | 暂时跳过 |
| 设置字段 | Preferred language | Bahasa pilihan | 偏好语言 |

马来文与英文产品文案仍需整体一致性审校，以上不是已发布文案。语言切换不自动翻译创作者内容，不改变币种、时区、费率或审核／付款事实。

### 后续流程验收补充

- 首次用户能找到询问和跳过；有已保存偏好的用户不会反复被问。
- 在填写作品说明途中切换语言，输入及附件保持；操作中的请求不被重复发送。
- 浏览器建议马来文、用户明确选中文：刷新和下一次登录采用已保存中文，不能被浏览器覆盖。
- 共享设备、退出登录、存储不可用、保存失败均验证；保存失败后给重试且不假称已保存。
- 三语邮件、校验和系统提示与同一用户偏好一致；用户原文内容保持原样。

依据：[W3C：引导用户访问翻译版本](https://www.w3.org/International/questions/qa-site-conneg.en.html)建议保留易发现的语言切换，让明确选择覆盖浏览器偏好。首次内联询问、跳过及恢复细节是Wringy的设计决定，不宣称W3C规定了具体流程。
