# 第一阶段：商家、创作者与运营可操作原型

2026-09-15 · 规划基线已整理完成；交给下一开发任务按本规格执行，当前任务不启动代码。规格负责人：创办人；文档整理与验收跟进：当前主任务。当前没有原型业务实现或执行结果。

## 一页实施约定

**为谁：** 创办人检查商家投放、creator赚钱与运营处理是否易理解，开发团队获得下一阶段可复用页面与状态契约。

**成功一句话：** 不靠口头补充，创办人能在同一份模拟活动里完成创建、投稿、达标申请、审核、模拟发放，并看懂预算不足和申诉两条分支。

**依据：** [创办人决定](../../founder-inputs.md)已确认三端、仅Google入口、公开活动、三语、无视频上传、通知与运营；[默认业务规则](../campaign-defaults-v1.md)为金额与期限唯一源；[全栈](../full-stack-proposal-v1.md)为技术方向。竞品与投资人认可不是原型用户测试证据；实际体验反馈在本阶段产生。

**投入上限建议：** 采用两周工作时间作为代理规划上限（非创办人工期承诺）；先在3个工作日内给可点击主流程，再扩展三端联动与异常。时间不足先收缩装饰和次要筛选，核心验收缺失须明确报告，不能用静态截图替代交付。

**做什么：** Next.js可运行交互原型，复用现有设计系统，本地模拟数据持久化；三端使用同一活动、投稿及申请记录。角色切换是演示工具，不是生产授权。所有页面显著标“演示数据”，所有金额操作明确模拟。

**不做什么：** 真实Google认证、多人远程数据同步、真实Fastify/DB业务实现、社交OAuth/抓取、实际邮件发送/支付、视频上传/转码、完整营销官网、AI剪辑、商城课程、生产级反作弊。原型保留Google登录UI，点击后进入明确模拟身份；真实Google配置在下一阶段。

**验收：** 下方11项原型验收逐项记录通过/未通过与证据。手机/电脑、三种语言、主流程与关键异常均覆盖；创办人最终确认体验。

**观察：** 首次体验能否独立完成任务、在哪一步犹豫、误认估计奖励或已付款的次数、返回修改活动的原因；不把模拟成交当真实商业指标。

## 页面与操作范围

|用户效果|必要页面/区域|必须可操作|
|---|---|---|
|未登录了解机会|简洁入口、活动目录、公开详情|浏览活动、查看要求/费率/封顶/时限、切换语言、进入模拟Google登录|
|商家发布清楚的活动|商家总览、活动编辑、预览/就绪检查、活动详情|按批准默认新建；修改费率/门槛/封顶/时间；非法组合报错；模拟资金就绪后发布|
|创作者提交并理解收益|creator总览、账号资格、链接提交、投稿详情、申请/付款记录|模拟连接有效/失效；提交URL；缺条件说明；查看可信更新时间、申请截止、估计与确认金额；达标申请|
|商家查看内容与效果|活动投稿列表/详情、报告摘要|内容通过或写理由拒绝；与运营计量结论分开；显示四类预算金额|
|运营处理到结案|工作队列、投稿/申请详情、申诉详情、付款/异常记录|计量通过/暂缓、申诉成立/驳回、模拟发放/未知对账、受控重试；关键操作确认并写演示记录|
|三方知道发生了什么|通知中心、个人/语言设置|同事件通知正确角色，已读状态保持；重要邮件展示“模拟邮件预览”不发送；本人/商家/运营演示切换|

尽量复用列表、详情和侧栏，不为每个状态新建页面。核心控件必须工作；范围外入口隐藏或标明尚未提供，不能伪装成功。创作者与商家可按真实产品位置切换工作区，运营切换仅存在演示工具栏。

## 一条主流程

1. 商家新建活动：奖励池RM2,000，RM5/千合格观看，最低申请RM5，单条累计封顶RM100，其他值从默认源读取。
2. 预览规则与模拟资金就绪后发布。服务费未定，标“待配置，演示未收取”，不能带入投资例子的15%。
3. creator在公开详情点击参加，进入Google模拟登录、语言选择及模拟账号就绪，再提交社交链接。
4. 原型固定模拟时间并记录接受基线。通过独立演示面板推进时间/观看量，不在正式creator界面放“增加观看”按钮。
5. 新增1,000合格观看，对应可申请RM5。申请后商家、creator、运营三端同一记录进入预留/待审核。
6. 内容和计量均通过后确认RM5待付；模拟财务处理后变为已发放。银行到账未知时单独标注，不能暗示真实汇款。
7. 奖励池四栏依次展示：2000/0/0/0 → 1995/5/0/0 → 1995/0/5/0 → 1995/0/0/5（可用/预留/确认未付/已付）。三端一致。

## 必须提供的异常场景

- 空列表、加载、输入错误、权限不足、来源数据暂缺；数据缺失不显示0观看或直接判作弊。
- 最低金额高于封顶阻止发布；高观看门槛配较低封顶可成立，明确显示达到门槛后封顶金额。
- 重复链接或重复点申请不生成第二笔；同视频待处理时提示等待。
- 可领RM60但余额仅RM50：确认具体金额后模拟预留；报价改变须重确认；不足最低金额则候补不占款。
- 拒绝后申诉：保留预留；成立后继续核验，不重排；未决不假装自动结案。
- 付款结果未知：页面只能查看原交易并模拟对账，不能直接再付一次；失败重试须有确认未付证据。
- 活动结案：仍有申诉或确认未付款时，不显示全部结清；低于门槛的未确认尾额按既有规则提前披露，退款显示待核定，不编造自动退款路径。
- 时间推进到计量终点/申请截止：新增观看不再计；及时申请保留；受阻延期显示原因、新截止，内容保留覆盖该截止及已有案件。

无需生成真实作弊判断或外部证据。所有模拟金额与状态来源于同一数据模型；原型状态约束用于演示，M3须重新在服务器事务中验证，不能以浏览器实现代替资金安全。

## 设计和技术约束

沿用[设计系统](../design-system-v2/README.md)和当前tokens；不另做一套品牌，不全站重造组件。Next.js项目结构预留可替换的数据访问层，但不开发通用插件框架。浏览器持久化只存演示记录，不存凭据/真实个人资料；同浏览器刷新保留进度，提供明确“重置演示”动作。不同设备不承诺同步。

语言沿用既有EN/MS/简体中文规范（此前BM为马来文俗称），不独立发明新locale映射；首选语言可修改，切换保留表单。最低检查手机390px与电脑1440px，并抽查320px不出现关键操作被遮挡；表格可受控横向滚动，主要操作不依赖hover。键盘焦点、弹窗返回焦点、表单错误和降低动效设置遵循现有组件规范。

首版原型不要求完成全部营销内容或最终SEO集成；公开活动页面需有合理标题/描述，但无公网部署时不声称已验证Google索引或WhatsApp抓取效果。代码复用与上线能力分开验收。
