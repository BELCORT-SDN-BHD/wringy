# Wringy 品牌与设计系统基础 v1

2026-09-10 · 完整可审阅建议草案 · 未获批准 · 非生产实现

## 品牌建议

**定位草案：Wringy 让品牌与创作者用清楚的要求、可追溯的审核和奖励记录完成内容合作，从马来西亚走向东南亚创作者商业平台。**

**主张草案：让好创作，有清楚的回报。** “清楚”指条件和进度透明，不保证收入、播放量或银行到账。英文产品界面是 PRD 中的建议，仍待确认；本次是中文审阅原型，不宣称已经支持中英马来文三语产品。

| 对谁说 | 他们要看清什么 | 推荐文字示例 |
|---|---|---|
| 创作者 | 能否参加、交什么、为何通过或修改、何时进入付款阶段 | “原稿预审通过，可按约定发布。此时尚未产生奖励。” |
| 品牌 | 买到什么、怎样核对、承诺多少、谁负责 | “先核对已公布要求，再作最终决定。” |
| 运营与财务 | 谁欠谁、依据是什么、异常下一步 | “付款结果待核实。先查证，避免重复付款。” |
| 投资人 | 候选入口与长期范围、已经做了什么和还未证明什么 | “邀请制内容合作是首发候选；尚无客户或交易验证。” |

语气：年轻、直接、尊重专业，不喊口号，不制造抢名额压力，不用“轻松赚钱”“保底爆款”“即时到账”。错误文案解释发生了什么和下一步，不责怪用户。字段少而明确，使用“原稿预审”“最终作品审核”“奖励待结算”等完整名称，不能把所有阶段统称“成功”。

临时字标使用小写 `wringy.` 的文字排版，句点取主强调色；正式品牌名仍是 Wringy。它不是已注册或已批准的标志。最小展示建议沿用 h3 字号；四周留至少一格 space-4，不压缩、不描边、不渐变。不要把装饰性句点当状态图标。后续标志需要独立确认、商标检查和导出资产；本稿不伪造这些成果。

图像策略：未来优先使用已获授权的真实创作者作品与工作过程，展示作品上下文。不得使用库存人像冒充客户、虚构品牌标识或下载社交内容作为已授权素材。当前预览只有明确标注的文字占位图，无真实视频与作品文件。

## 统一设计值与维护方式

[design-tokens-v1.json](design-tokens-v1.json) 是本轮唯一规范数值来源。tokens 指颜色、字号、间距等可重复使用的命名值。共享主色已按主会话的设计建议与 deck 对齐；不是继承历史品牌批准。文档引用名称，不另造第二套颜色表。

JSON 包含颜色原值、语义引用、字体、字号、字重、行高、间距、圆角、边框、布局、断点、动效、状态词汇与共享 RM100 示例。`semantic` 把“用在哪里”指向“取什么值”，例如 `actionPrimary → color.accent`，避免组件分别猜蓝色。

HTML 的 `GENERATED TOKENS` 区域是 JSON 的生成快照，附完整 JSON 字节的 SHA256 校验值。SHA256 是用于确认文件内容一致的指纹。HTML 单文件离线可读，无读取相邻文件的运行时依赖。修改流程：先改 JSON → 用相同命名生成 CSS 变量及语义引用 → 同步媒体断点 → 更新指纹 → 重做截图。不要只改 HTML 的颜色；deck 也应读取此 JSON 或引用同一版本。版面结构不是业务计算来源；HTML 中示例文字是静态快照，调整共享例子时同步截图与数值检查。

| 角色 | token | 使用规则 |
|---|---|---|
| 页面与面板 | page / panel | 暖白底、白色工作区；不靠大面积彩色卡片切分每句话 |
| 主要与辅助文字 | textPrimary / textSecondary | 主要文字近黑；日期、解释等用辅助文字，保持可读对比 |
| 装饰与交互边界 | borderDecorative / borderInteractive | 轻线仅作分隔；输入框用更清晰边界，不拿轻线充当唯一控件轮廓 |
| 主操作 / 悬停 | actionPrimary / actionPrimaryHover | 一个区域一个主按钮；钴蓝是唯一品牌强调色 |
| 焦点 | focusRing | 外轮廓加间隔，不靠颜色填充变化表示键盘焦点 |
| 信息 | infoText / infoSurface | 等待审核、进度说明等非成功状态 |
| 成功 | successText / successSurface | 仅表示该层级完成，不能跨层替代银行到账 |
| 注意 | attentionText / attentionSurface | 需修改、暂停、待核实；必须附文字 |
| 错误 | errorText / errorSurface | 校验失败、明确拒绝或明确付款失败 |
| 不可用 | disabledText / disabledFill | 附原因，不仅调透明度；不能藏掉用户已有记录 |

绿、琥珀和红是小面积状态语义色，不是额外品牌强调色。设计值尚未批准，若无障碍检查失败，优先调整对应语义值并同步 deck，不逐屏局部补丁。

## 字体、布局与响应式

系统字体优先，中文优先 PingFang SC / Microsoft YaHei / Noto Sans CJK SC；拉丁字标可以 Avenir Next 配合回退字体。未捆绑字体文件，不保证不同系统字形像素完全一致。需要最终跨系统一致输出时再确认可授权字体，不把某个系统字体当成已购授权。

采用 display / h1 / h2 / h3 / lead / body / small / caption 命名层级；正文使用宽松行高。正文不以小字换取一屏塞满；重要金额与错误不能降为脚注。金额采用等宽数字，按币种对齐；`—` 表示未知，并附未取得原因，不能用零替代。

间距用 JSON 的 space 标尺；面板与控件各有统一圆角，不使用每层都套圆角卡片。桌面最大内容宽度使用 layout.maxWidth，长段文字用 readingWidth。互动区域最低高度用 controlMinHeight；手机按钮可以铺满，桌面按文字宽度。

| 尺寸范围 | 设计行为 |
|---|---|
| 大于 tabletMax | 核心画面两栏：列表与详情、提交与进度、作品与审核；标题与说明并列 |
| mobileMax 以上至 tabletMax | 缩短标题字号与边距；组件库变两列；检查中文换行 |
| 不大于 mobileMax | 单栏自然阅读；邀请列表在详情前；提交信息在进度前；主操作不挤压；表格保留字段并在有名称的区域内横向滚动 |
| 打印 | A4，隐藏依赖交互的表达；核心画面分别开启打印章节，长内容允许续页；不强缩成难读的一页 |

内容必须适应 320px 窄屏和 200% 放大；表格的局部滚动不应变成整页横向滚动。正式产品可把审核表转为逐条卡片，但所有字段、金额与原因必须保留，本次不实施该行为。语言变更会改变文字长度，英文产品版需重新检查按钮、表头与错误信息。

动效仅保留 fast / standard 的短过渡建议。资金确认、错误、表格更新不使用庆祝动画；尊重系统减少动效偏好。当前参考 HTML 没有动画、网络请求或模拟点击行为。

## 角色与信息边界

权限以 [PRD 角色表](prd-v1.md#角色权限与关键页面) 为上游；以下为界面表达，不证明后台授权已实现。

- 创作者：我的邀请、自己的名额、原稿版本、最终作品、奖励与申诉。不能看到其他创作者的私人材料。
- 品牌负责人：本品牌活动、规则、名额、预算与团队。审核员只看被分配活动；不展示银行资料或付款按钮。
- Wringy 运营：催审、风险与争议，显示案件依据。风险暂停不等于取消应付奖励。
- 财务复核及第二复核人：核对义务和付款，准备与批准分开。不同权限使用明确的动作词，不统称管理员。
- Belcort：关联公司开发维护，限时授权排查；不是默认可访问所有生产数据或决定奖励的角色。

一个人可切换角色，但切换后必须明确当前组织与工作空间。未授权页面使用中性提示，不泄露另一个组织的活动名称或附件。邀请失效、活动暂停、名额已满、只读历史分别有解释，不显示没有意义的空白。

## 候选完整链路与状态

推荐默认：邀请制、品牌原创内容、一个活动一个指定社交平台与账号要求、一个创作者一个名额、先原稿预审、通过后自行发布、最后人工审核。固定单帖奖励按最终合格作品计算，不按播放量，不承诺可取社交指标接口。以上均为待批准试点建议，不是正式售价或上线功能。

**四个必须分开的事实：原稿准许发布 → 最终作品合格 → 符合付款条件 → 银行到账。**

| 对象 | 屏幕标签与后续 | 不能推断 |
|---|---|---|
| 原稿 | 草稿 → 已提交 → 预审中 → 预审通过，可按约定发布；或需修改/未通过 | 预审通过不产生奖励，也不保证最终发布内容通过 |
| 最终作品 | 已发布并提交 → 最终审核中 → 最终审核通过；或需修改/未通过/申诉 | 链接已提交不等于已验证；超时不自动批准 |
| 奖励义务 | 最终通过后待结算 → 符合付款条件，待安排付款 → 根据证据清偿 | 欠付金额不等于平台钱包余额；可付不等于已经付 |
| 付款尝试 | 待复核/已授权 → 处理中 → 经核对已付款 | 发出指令不等于成功；服务商账户入账不等于银行到账 |
| 银行出款 | 单独显示待发起/处理中/已核实银行出款/结果待核实 | 缺银行或可靠服务商证据时，禁止显示“银行已到账” |

“已付款”在生产界面必须注明证据阶段，例如“已转入服务商账户”或“银行出款已核实”，不要只留模糊绿勾。奖励是否已清偿取决于待确认合同节点；尚不明确时显示“待确认清偿”。JSON 的状态是显示词汇，不是替代 PRD 的数据库状态或状态转换。

异常完整性：付款失败保留奖励义务；未知先查证，不重复发起；风险暂停附原因、责任人和更新渠道；部分付款显示已核对金额与剩余义务；退回与冲正保留关联历史。申诉不得用删除旧审核记录处理；取消活动不抹除已批准奖励。退款批准与退款执行另列，不混入创作者奖励。

金额示例唯一基准：JSON example.rewardMinor 为 MYR 最小单位，界面显示 RM100.00。它仅是共同讲解例子，不是建议市场定价。品牌活动服务费另议；本设计不使用收费比例，也不从创作者奖励扣平台服务费。支付通道费、税及承担者待定，不能用视觉省略作出财务承诺。

## 组件交付约定

| 组件 | 内容与变体 | 行为与异常要求（未来实现） |
|---|---|---|
| 页头 / 工作空间 | 字标、当前空间、组织或身份 | 切换时重新核对权限；手机换行，不缩掉组织 |
| 邀请行 / 详情 | 邀请状态、品牌、内容要求、固定奖励、截止、平台、条款 | 仅受邀列表；过期或暂停解释原因；加入前确认规则版本 |
| 按钮 | 主、次、危险、不可用、焦点、处理中 | 一个主要动作；防重复发送；不可用说明原因；本 HTML 用静态 span，不冒充可用按钮 |
| 输入 / 文本域 | 可见标签、值、辅助文字、错误 | 不以占位符代替标签；错误与字段关联；失败保留输入；本 HTML 只读 |
| 文件 / 链接 | 文件名、版本、大小、上传/校验状态、访问原因 | 链接失效要求补证，不伪造观看数；附件私有；本 HTML 仅占位文字 |
| 状态标签 | 文字＋语义色 | 每个对象注明层级；不用单独颜色或绿勾表示成功 |
| 进度记录 | 谁、时间、动作、理由、版本 | 预审与终审分别记录；空值解释；不显示虚构百分比 |
| 审核清单 / 反馈 | 规则版本、逐项依据、理由、下一步 | 未通过需关联理由；修改生成新版本；不暗中加验收条件 |
| 表格 / 金额 | 标题、列标题、记录、币种、状态 | 金额右对齐；小屏局部滚动；排序/分页仅在真实实现后出现 |
| 提醒 / 空态 / 加载 / 错误 | 原因、下一步、上次更新时间 | 不把加载当零金额；不把没权限当暂无客户；保留既有内容 |
| 确认与危险操作 | 决定、对象、规则版本、金额、影响、取消 | 最终批准明确仅生成义务；付款复核独立；本稿规范有定义，未画完整弹窗 |
| 支持与无权限 | 案件状态、所需材料、负责渠道 | 不暴露其他组织信息；超时升级不静默结案 |

组件为可实施讨论的基础，不是可复制的生产组件库。未展示的上传交互、确认弹窗、通知、分页、完整角色切换与运营后台仍须原型验证与逐项规格，不标作本稿已画完。

## 三张核心画面与一致性

[design-preview.html](design-preview.html) 是自包含静态中文审阅稿。样例按钮不会执行，输入只读；表格允许真实浏览器滚动，浏览器打印可用。这些浏览功能不是业务交互。

1. **我的邀请 / 活动详情**：只展示受邀可参与活动。样例晨间咖啡活动固定 RM100，指定 Instagram，先交原稿、预审后发布。展示规则需补齐的事项，不伪造已签条款。公开市场明确不属于候选 V1。
2. **提交 / 进度**：同一创作者与同一活动；原稿预审通过、创作者自行发布、最终作品审核中。RM100 仅为条件满足后的金额，尚未生成奖励义务。
3. **品牌最终审核**：同一最终提交仍待审；每项清单标待人工核对，反馈是未发送的文案示例。最终批准与付款明确分开，没有伪造视频播放或自动识别。

所有商业活动、名字、日期、平台选择、条数、金额与文件均标为示例。主张与流程标草案；没有真实客户徽章、业绩图或批准记录。设计值本身是规范候选，不用“示例”掩盖版本来源。

## 可访问性与验证目标

无障碍意味着使用键盘、放大页面或辨色困难的人仍能获取信息。目标参考 [W3C WCAG 2.2文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)及[必要控件对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)，2026-09-10核查：正常文字对比至少 4.5:1；大字和必要控件边界至少 3:1。此处是设计验收目标，不宣称完整合规审计已完成。

检查普通文字、辅助文字、白字主按钮及状态文字配对；辅助分隔线不承担必要控件轮廓。焦点可见且不被遮挡；表格有 caption、表头与命名滚动区；只读输入有可见标签，错误用 aria-describedby 关联。标题按 h1 → h2 → h3 组织，顺序与视觉一致。图像占位以文字说明，不增加装饰朗读。

需交给生产实现的验证：键盘顺序、弹窗焦点回归、屏幕阅读器通告、上传进度、异步错误与 200% 放大。静态页无法证明这些未来行为已通过。

本轮实际浏览器检查、颜色对比、截图路径与打印页数见 [verification.json](design-preview-assets/verification.json)。验证仅覆盖本设计文件，不表示 PRD 验收或真实业务测试已完成。
