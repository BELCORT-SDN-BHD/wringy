# Belcort设计系统交接

版本1.0 · 2026-09-11。这里交付的是设计依据、共享值、组件行为和本地展示；不是已上线的软件包，也没有真实付款、鉴权或数据平台连接。

## 从哪里开始

先打开交互目录，查看“基础”和“组件”；再在[module-coverage.md](module-coverage.md)找到正在开发的板块。组件ID是规范与展示的稳定关联，不以截图文件名建立依赖。金额、审核和出款还必须读[domain-states.md](domain-states.md)。

| 文件 | 用途 | 维护方式 |
| --- | --- | --- |
| tokens.json | 基础、语义及组件共享值 | 修改源文件后生成CSS；禁止只修改生成CSS |
| catalog.json | 组件清单、适用状态、交互与使用契约 | 新增/调整组件先改此处，再同步详细规范与展示 |
| components.md | 组件逐项规格 | 作为设计与工程验收依据，结合实际页面任务核对 |
| domain-states.md | 业务事实与转换约束 | 规则批准后更新；不要用颜色或动画决定业务状态 |
| module-coverage.md | 12板块与组件关系 | 产品功能变化时核查新增组合，不随意复制基础组件 |
| brand-foundations.md | 视觉角色、内容、响应、动效原则 | 改变全局规则时由创始人审阅 |
| index.html / app.js / styles.css | 可交互设计展示 | 示例代码可供理解，不直接宣称可复用生产SDK |
| tests/ 与 verification.json | 实际运行的检查及限制 | 不把单次浏览器检查称为所有环境认证 |
| sources.md | Mobbin、W3C及产品来源 | 静态截图只证明外观，不证明键盘或动画 |

## 完成度怎么判读

**规范**说明应该如何表现；**视觉样例**展示特定外观；**交互演示**允许本地操作；**生产组件**还需要工程实现、服务契约及真实环境验证。四者不能混称完成。

目录中的适用状态是设计验收清单，展示的本地操作不是后端规则引擎。不要把任意切换五轴状态的演示控制器放进真实运营页面：它用于观察组合，生产转换必须校验权限、前置事实和审计记录。

## 组件接入契约

无论Belcort最终使用哪种框架，共用组件都应满足以下边界；本次不替Belcort虚构技术栈已选定。

| 层 | 输入 | 输出／事件 | 不能负责 |
| --- | --- | --- | --- |
| 基础交互 | 标签、值、可用性、错误关联、描述、事件回调 | 选择、提交意图、展开/关闭 | 不发起付款，不检查业务权限 |
| 表单组合 | 初值、字段规则、服务器错误、保存状态 | submit、dirty-change、cancel、retry | 不把请求发出当保存成功 |
| 数据组件 | rows、stable-id、排序/筛选、分页总数或unknown、selection | 排序/筛选/分页/选中变更 | 不把客户端过滤当服务器权限 |
| 业务展示 | 有版本的事实快照、允许动作、下一责任人、更新时间 | 明确动作意图及对象ID | 不推算余额、不自动通过审核、不伪造银行到账 |
| 应用服务 | 用户身份、权限、业务规则、请求ID、服务返回 | 权威事实、合法动作、错误类别 | 不把内部敏感错误直接暴露给用户 |

`loading`与`disabled`不能只有视觉效果；请求进行中应拒绝重复提交。客户端锁按钮不能代替服务端防重复处理。筛选变更取消或忽略旧响应，避免先发后到的旧结果覆盖新查询。表单保存冲突必须保留用户草稿并提供比较／重新载入，不静默覆盖别人的工作。

## 优先接入顺序

1. **公共地基**：颜色、文字、间距、焦点、按钮、字段、选择、导航、弹窗、反馈、表格。用一条能保存且能失败恢复的真实设置流程验证。
2. **Creator Rewards组合**：活动要求、素材、提交、证据、审核、数据新鲜度、奖励计算明细。先把数据不可用、修改要求版本、拒绝理由和申诉入口做对。
3. **资金与风险组合**：预算、奖励义务、可用余额、出款、退款、风险限制。等支付与风控规则冻结后接服务，不以本地样例默认值上线。
4. **全平台扩展**：商品、结账、课程、社群、联盟、广告、连接器、AI等按module-coverage复用公共层；具体交付顺序在产品规格决定。

这只是接入建议，不缩减12板块范围，也不改变已委托Belcort开发的关系。

## 必须在生产规格里回答的产品问题

| 决策 | 为什么影响设计 | 当前处理 |
| --- | --- | --- |
| 首发计酬方式、取整和平台费 | 决定金额明细、预估与最终值文案 | 显示模拟数值；不写成正式价目表 |
| 预算预留、超额与不足 | 决定参加、继续计量及停止奖励的合法状态 | 分开余额、预留、义务和剩余可用；规则待冻结 |
| 播放数据权限与刷新频率 | 决定来源、过期、断连、复核 | unknown/stale/disconnected有独立表达；不冒充API已接通 |
| 内容审核与申诉责任 | 决定谁能操作、为什么、多久处理 | 权限与证据契约是提案，期限不自行承诺 |
| 资金保管、出款与退款优先级 | 决定锁定、可用、处理中和实际到账 | 不把品牌资金当平台营业收入；真实路径待服务商确认 |
| 地区语言、货币、税务与核验 | 决定字段、披露和支持区域 | MYR及中文为演示；未启用的国家/渠道不显示可付款 |

## 每个组件的交付检查

先对照catalog中的适用状态，检查状态组合而不只是单张常态图。至少核查error+focus、selected+focus、busy+重复点击、读取失败+已有数据、无权限+现有数据缓存。敏感数据在权限撤销后不能仍留在屏幕或导出中。

键盘完成正常与恢复路径；弹窗关闭后焦点返回；确认危险动作时没有默认误触。触控有可点击的替代方式，不能只靠拖动或hover。移动屏幕、放大文字、长语言、空值、长ID、极大/负金额都不能遮住主要信息。

上线前用真实浏览器、手机、键盘与读屏检查，并把金融/权限/审核动作接入服务级和端到端验收。本地目录的自动检查仅覆盖记录中的演示，不代替以上检查。

## 版本与维护

设计值与组件使用同一发布标签。补充文案/无破坏修正用patch；兼容的新组件/变体用minor；删除、改名或改变默认行为用major。命名只是维护约定，本次没有发布npm包。

一个变更记录应包含：问题、受影响组件与页面、规范变化、迁移方式、验证、批准人。旧组件先标弃用并给替代入口，待使用方迁移后再移除。不要在新页面另造一个“差不多的按钮”。

建议由创始人批准品牌与业务语义；Belcort指定一个实际的设计维护人和工程维护人，可以由同一人承担。本稿没有虚构这些人已经就位。视觉变更回到token，业务变更回到领域规格，页面只消费结果。
