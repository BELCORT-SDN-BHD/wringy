# Wringy品牌与设计基础

版本1.0 · 2026-09-11 · 基于已认可的deck视觉继续扩展。新组件与具体参数是可审阅设计交付，尚非生产发布批准。

## 1. 品牌表达与产品表达

Wringy让品牌与创作者看清合作机会、成果和收入的来源。表达应年轻、直接、有创造力，同时对要求、费用、证据和处理进度保持准确。这是品牌提案，不是已证明的市场定位。

品牌页、投资材料：一句主要观点配一张有解释作用的图；宽松留白、显著标题、少量酸柠黄。应用：连续工作面、稳定对齐、明确对象和下一步。审核列表使用可扫读的行；活动详情围绕内容、要求和证据展开；手机创作者页面按任务单列。

例如“让内容，带来可衡量的结果”可用于品牌叙事；审核页面必须叫“水瓶使用演示 · 提交详情”，不能用口号替代对象名称。

## 2. 字标、摄影、图形与图标

正式拼写为 **Wringy**。当前采用文字字标，不把此前AI概念图上偶然生成的W标识当作正式logo。字标保持本来比例，净空至少一个小写x的高度；数字最小24px是本稿提案。浅底使用深色字标，森林底使用白色；不使用酸柠黄细字标，不加阴影或描边。专门绘制的标志与商标验证属于后续独立工作，不伪装已完成。

摄影优先真实的制作过程：人物怎样拍摄、剪辑、展示产品。照片须有授权与来源；概念图在对外证据语境标注“概念场景，非真实客户”。不得拿虚构头像、品牌或播放数充当客户成果。裁切保留动作主体；手机可换裁切，文字和状态不能烘焙进装饰图片。

示意图只解释一条关系。例如“品牌预算 → 合格成果 → 创作者奖励”，旁列“平台服务费”；不画成平台可任意花用创作者预算。连接线要有方向和明确标签。

图标沿用现有Tabler outline资产及许可证；尺寸与描边引用token/原SVG，不混用多套风格。装饰图标隐藏于读屏；只有图标的按钮具有操作名称。颜色与图标共同辅助文字，不能单独表示拒绝或已付款。没有图标时使用准确文字，比随意的emoji更可靠。

## 3. Token：一次修改、统一生效

Token就是共享设计值的名字。唯一新源为[tokens.json](tokens.json)，[tokens.css](tokens.css)是生成物。

三层关系：基础值（例如品牌原色）→语义值（主按钮背景、错误文字）→组件值（按钮高度、输入框边界）。页面使用用途名；不把某个色值直接散落在每个页面。示例数据不属于颜色token，不以旧按帖样例继承业务规则。

| 决策 | 规则 |
| --- | --- |
| 品牌色 | 酸柠黄用于重要行动或品牌表达，不意味着成功、收益或审核通过 |
| 文本 | 白底用深色正文与可读辅助色；酸柠黄底用深色字，禁止白字 |
| 状态色 | 成功、警告、错误、信息各自有前景与背景；始终附对象明确的文案 |
| 边界 | 淡线用于分隔；必须靠边界识别的输入控件使用可辨识边界 |
| 焦点 | 统一外轮廓，不能只改变背景；不让sticky工具条遮住焦点对象 |
| 图表 | 文字、线型或纹理辅助区分；零与缺失不同，不靠tooltip提供唯一数据 |
| 主题 | 本版交付浅色主题；森林色品牌章节不是完整暗色应用主题。新增暗色必须重新审核所有语义组合 |

具体色值、字号、间距、圆角与时长在交互目录“基础”页和JSON中读取，本文不再维护第二份可漂移的数值表。

## 4. 排版、密度与响应

中英混排使用现有系统字体方案，中文回退清楚；金额和连续数字用等宽数字特性。正文不使用极细字重，不将关键提示压成很小的灰字。一个页面只有一个顶层标题，模块层级依次降低，不以全部大写英文小标签承载必要说明。

品牌与工作区是不同密度模式。手机不把桌面整屏缩小：导航可收起，属性移到正文后，次要表格列转为明细；比较任务确需表格时，仅表格容器横向滚动并提示。主动作保持触控尺寸，44px为Wringy主要触控目标。长标题换行，ID可复制；金额的货币与数值尽量不拆行。

真实重排目标包含320px窄屏、平板和桌面；200%文字缩放、400%页面放大要检查焦点与内容可达。自动截图通过不等于所有真实手机和辅助技术通过。

## 5. 状态的层级

| 情况 | 表达方式 |
| --- | --- |
| Hover | 提示可以交互；只在支持悬停的精确指针上启用 |
| Focus | 键盘位置；与selected、error、loading可以同时存在 |
| Selected | 当前选择；不是当前焦点，也不是成功 |
| Disabled | 当前不能操作，旁边说明原因；不能只依赖无法触发的tooltip |
| Read-only | 可以阅读、选择和复制，但不修改；不能使用一律灰掉的禁用外观 |
| Loading | 说明在做什么，保持已有内容和布局；防止重复请求，未确认不能先显示成功 |
| Error | 说明问题、影响及恢复动作；输入保留，关键失败不只出现在短暂Toast |
| Empty | 区分首次无内容、筛选无结果、没有选择、没有权限、读取失败 |

“全部状态”以每个组件的适用清单为边界，不是把所有状态机械套给每个元素。例如图标本身没有付款失败状态，付款结果组件有；只读文本不需要pressed。

## 6. 文案、数字、时间与国际化

规范和演示使用中文；这不是确认产品仅有中文。布局预留英文和马来文长度，不拼接不可翻译句子。产品的默认语言、完整翻译和货币支持需在发布规格中决定。

错误文案采用“发生什么＋如何恢复”：如“暂时无法读取播放数据。上次更新于14:32，可稍后重试。”不要写“播放量0”；“出款请求已提交，等待确认”不能简化为“已到账”。可追踪客服编号应可复制，不向普通用户显示堆栈。

金额始终带货币，示例用MYR；同屏多币时不只写$。计算使用最小货币单位或可靠十进制，展示由本地化格式器完成；组件不自行决定四舍五入的计费规则。负数、退款、部分支付与未知都需明确文案。未知用“尚未确认”，不是RM0.00。

时间显示用户时区，并让活动截止/计量区间注明时区。相对时间附可获得的绝对时间；日期输入不要让03/04承担歧义。区间写起止、是否包含边界和最后更新时间。用户看见的倒计时不替代服务器截止判断。

## 7. 动效规则

按Emil规则，键盘启动的动作即时响应；频繁切换的列表、命令菜单不安排出入场表演。指针按压使用轻微缩放反馈；焦点变化不缩放。弹窗、浮层偶发开合才使用短过渡；浮层围绕触发点，模态围绕中心。

动画优先transform和opacity，避免transition:all。具体曲线与时长从token读取。需要频繁中断的过渡可重新定位；不为卡顿加入更长动画掩盖。减少动态效果时取消位移与缩放，信息仍立即可见。

Toast不接管焦点；次要成功可自动收起，鼠标悬停、焦点停留或标签页不可见时暂停计时。重要错误、出款结果与撤销机会不能仅靠稍纵即逝的提示传达。Tooltip先等待，连续查看相邻说明时更快；键盘获取说明即时，且说明不能承载唯一操作入口。

## 8. 使用与变更

先查[组件目录](catalog.json)与[逐项规范](components.md)，再做页面。相同意图使用相同组件；只有新的意图、角色或数据结构才需要新增变体。颜色调整先改源值，语义规则调整先改规范，再同步展示与检查。交接和版本规则见[handoff.md](handoff.md)。
