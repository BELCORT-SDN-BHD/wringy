# Wringy：投资叙事与产品基础蓝图

2026-09-10 · 讨论稿 · 中文 · 研究支持的建议，不是批准的PRD或融资承诺

## 1. 先确定我们要证明什么

建议定位句：**Wringy 让品牌与创作者在同一个平台完成内容合作、效果确认与奖励结算，从马来西亚开始，逐步建立东南亚创作者商业平台。**

这是待验证的投资假设。长期完整Whop范围保留在[产品总图](product-map.md)，第一阶段以Creator Rewards作为候选入口。首批付费客户、计酬模式、收费比例、资金处理方式尚未确定。

“独角兽方向”应体现为扩大市场与收入的机制：品牌持续购买 → 创作者持续参与 → 更可靠的履约记录 → 更多重复交易 → 扩展交易产品和国家。每个箭头都需要证据；目前不能声称已经存在网络效应、垄断优势或十亿美元估值。

例如：一家马来西亚品牌第一次活动完成后愿意再次付费，平台才有理由开发复购工具。若每次活动都依赖创始人重新找人、手工审核全部材料，增长同时也会增加服务成本。平台化的目标是让单位交易所需的人工逐步下降。

基础核查：已有创始人输入、完整Whop研究和当前CR流程研究；没有获批的首发规则、客户访谈结论、正式PRD和架构。本稿补投资假设与研究这一层，不能直接当成Belcort开工规格。当前目录不是Git仓库，尚无工程交付检查；代码阶段再建立，不把搭建工程仓库算成本轮研究已完成。

## 2. 主deck建议14页

这是针对Wringy的编辑建议，并非融资机构统一规定的页数。专业依据见[一手融资指南研究](../research/investor-deck-guidance-2026.md)。每页标题应陈述一个结论；未验证的结论在草稿中明确标成假设。讲述版本保留主要证据，完整口径和推算进入附录。

| 页 | 投资人要理解什么 | Wringy内容与证据要求 | 最适合的画面 |
|---|---|---|---|
| 1 公司定位 | 你做什么、为谁做？ | 一句话定位、Malaysia → SEA；避免“下一家Whop”作为唯一解释 | 品牌名、一句话、克制的产品局部 |
| 2 用户问题 | 谁的问题值得花钱解决？ | 品牌组织合作、核查效果与结算的具体障碍；创作者获得机会与确定收入的障碍。需要访谈或真实流程证据 | 一个真实工作流的前后对照；未知时标“问题假设” |
| 3 为什么现在 | 为什么现在值得进入？ | 当前内容合作和分发变化，使用带日期、地区和定义的市场数据；不能把所有电商GMV当作收入机会 | 一个主要趋势图，最多两个辅助事实 |
| 4 首发产品 | 第一版怎样解决？ | 从活动、参与、提交、审核到奖励的完整链路；明确哪些需人工辅助 | 一条五步用户旅程和关键画面 |
| 5 核心体验 | 用户实际如何使用？ | 品牌创建活动、创作者提交、双方看进度；界面是概念原型须标注 | 三幅大尺寸产品画面，不塞全部功能 |
| 6 市场空间 | 足够大且可以进入吗？ | 从目标付费品牌/代理商数量 × 年可服务预算推导；区分交易额与平台收入；SEA扩张单列假设 | 从Malaysia首批客群向区域扩张的分层图 |
| 7 收入与经济性 | 每笔生意怎样赚钱？ | 收费对象、抽佣或订阅假设；扣除支付费、退款损失、审核支持等后剩余多少 | 一笔示例交易的资金分解图 |
| 8 获客与启动 | 两边用户如何开始交易？ | 先人工获得少量付费品牌，再围绕真实活动招创作者；首批行业尚未选择 | 两侧供需如何汇合，不画无证据的自动增长飞轮 |
| 9 验证进展 | 现在有什么证据？ | 有付费、复购才展示真实数据；当前可展示研究、原型进度和待验证计划，明确未产生商业验证 | 已完成/待验证的简洁清单，禁止假logo和假收入 |
| 10 竞争与选择理由 | 为什么选Wringy？ | 比较Whop/CR、代理商、人工协作及本地替代方案；按本地履约、透明结算、可重复操作等已核查维度 | 3–4列比较；不靠编造轴线宣称“唯一” |
| 11 扩展路径 | 如何从入口长成大平台？ | Rewards验证后，依据用户需求扩展品牌工作台、创作者商业工具及更多国家。长期12板块在附录 | 三阶段路线图，每阶段注明进入条件 |
| 12 团队与交付 | 谁负责把它做成？ | 创始人真实经历；Belcort关联公司负责开发，不自聘开发人员；产品决策、交付资源与知识产权约定待补 | 清楚的责任图，不冒充已有内部工程团队 |
| 13 资金与里程碑 | 这一轮钱买到什么进展？ | 开发、维护、获客与运营分别列；本稿只估技术预算，融资总额等待商业运营预算 | 资金用途对应可验收里程碑 |
| 14 长期愿景与邀约 | 你希望投资人记住什么？ | 回到SEA创作者商业平台；明确期望融资/合作讨论，金额未定就不填伪精确数字 | 一个有力定位句，加联系方式 |

附录建议：市场来源与计算；完整Whop范围；计酬与结算规则；客户访谈记录；竞争证据；成本敏感性；Belcort交付及关联关系说明。内容随证据补齐，不追求固定页数。

## 3. 用deck反推产品，不让愿景替代需求

| 投资假设 | 第一版必须能做什么 | 如何证明 | 对基础工作的要求 |
|---|---|---|---|
| 品牌愿意为这件事付费 | 明确活动要求、预算和结果 | 实际付费活动，而不只是注册或点赞 | PRD先定义活动目的、规则及验收 |
| 创作者愿意参与并再次参与 | 发现活动、看资格、提交、查看审核与收益 | 合格提交率、重复参与、退出原因 | 设计优先呈现资格、状态、拒绝原因 |
| 合作可重复且不靠创始人逐单推动 | 复用活动、审核队列、通知与支持记录 | 品牌复购、每次审核/活动人工耗时 | 后台与异常流程属于首发核心范围 |
| 奖励可以可信结算 | 计算依据、待结算/可支付/已支付记录、纠错 | 金额可核对、失败可解释、争议可追溯 | 架构先区分内容状态与资金状态；不由UI按钮直接代表到账 |
| 单位经济能改善 | 收费及服务成本记录 | 平台净收入与每笔直接成本 | 支付、奖励、退款、收入分开记录 |
| 可以进入下个细分市场 | 可配置而可追踪的规则 | 同一流程服务新客群的复购与运营成本 | 先保留语言/币种等边界，不先实现所有国家支付 |

指标定义：复购率必须规定观察窗口、合格客户群和分母；创作者重复参与需排除同活动重复提交；可支付奖励不等于银行到账。没有客户数据时，不自设“行业标准”门槛。

建议验证顺序：问题访谈与真实合作流程 → 可点击原型验证双方理解 → 小规模付费试点 → 复购及单位成本 → 更大规模产品开发。Belcort可并行确认技术可行性；原型测试不等于真实交易已经完成。

## 4. 干净简洁的视觉规则

以下为本稿提出的新方向，不继承已撤回PPT的视觉批准，也不冻结产品品牌系统。

- 16:9；以白色或暖白为主，近黑文字，一个强调色。颜色暂用功能角色描述，待品牌方向确认后在统一tokens中定值。
- 一页一个观点。结论标题约一行，正文最多三组短信息；图表直接标出重点，避免把报告段落缩小塞入幻灯片。
- 建议标题32–40pt、主要正文22–26pt、注释不小于12–14pt。实际字体以中文渲染和投影可读性测试调整，这些是Wringy设计建议，不是行业硬规范。
- 固定页边距、标题位置、图表配色和来源脚注。用留白建立层次；不采用每页大量圆角卡片、渐变光晕或装饰图标。
- 数字必须有单位、时间和地区。实际值用实线，预测用虚线并明确标注；不给假精度。
- 产品页面只突出需要理解的局部，并注明“概念原型”或实际状态；不用小到无法辨认的整屏拼贴。
- 年轻感来自短而有力的语言、鲜明但有限的强调色、创作者内容的真实质感。品牌方信任来自清楚的规则、真实证据与稳健排版。

三种页面母版草案：

1. **结论＋证据**：上方结论，左侧一句解释，右侧一张主图，下方来源。
2. **产品演示**：左侧一句用户价值，右侧放大一个关键操作；另两步用简短标记连接。
3. **数字说明**：一个主数字占视觉中心，下方拆解公式和口径。暂无可靠数字时保留问题与待补证据，不放装饰性增长曲线。

验收：缩略图扫读能理解故事；正常演示无需放大读正文；每张图都有用途；每个外部数字可追溯；真实与预测不混淆。正式deck前先以封面、产品、经济性三页检验方向。

## 5. Belcort开发安排与市场预算

创始人已确认Belcort也是自己的公司，Wringy不自聘开发团队。公开[Belcort官网](https://www.belcort.com/)展示网站与商业体验、业务流程系统和企业AI服务，页脚主体为BELCORT Sdn. Bhd.。未发现公开Wringy报价；官网展示不是已承诺的项目资源或同类平台业绩证明。

### 估算范围：可运营的Creator Rewards Web首版

假设：响应式Web，品牌/创作者/运营三类工作区；一套计酬规则；活动和提交；人工审核为主；收益及支付状态记录；一家支付服务商的标准接入可获批；基本通知、统计、审计、测试和部署。活动金额与结算规则仍要在PRD确认。

不含：原生iOS/Android、完整Whop12板块、持牌自建钱包、多国支付、保证可取得的社交平台播放量接口、高级反作弊算法、复杂自动广告归因、长期持续加功能。第三方准入与数据接口能力尚未核验；若改成自动CPM计量，多平台数据接入和反作弊须重新估算。

以下工时与费率是本项目规划假设。外部资料仅提供项目价区间，并未证明这些工时或RM100–150/小时是行业统计。设计、工程、测试可并行；工时不可直接当日历工期。

| 工作包 | 估计交付工时 |
|---|---:|
| 范围梳理、规则与架构可行性 | 80–120 |
| 核心体验、基础设计规范与原型 | 160–220 |
| 账号、角色、工作区和活动设置 | 160–220 |
| 创作者参与、提交、审核与通知 | 220–320 |
| 收益记录、标准支付接入、对账与异常 | 180–280 |
| 运营后台、基础分析与支持 | 100–160 |
| 测试、安全基础、部署、文档与交接 | 180–240 |
| **合计** | **1,080–1,560** |

低情景：1,080 × RM100 = RM108,000；加15%预备金 = **RM124,200**。

高情景：1,560 × RM150 = RM234,000；加15%预备金 = **RM269,100**。

规划基准情景：1,320 × RM125 = RM165,000；加15% = **RM189,750，deck可暂记约RM190k**。建议预算表达为**约RM125k–270k**，不把基准值伪装成Belcort报价。

范围梳理和核心设计已包含在表内，后续不能再重复加一笔Phase 0费用。若Belcort复用现成能力，减工时；若新增计酬方式、原生App或实时跨平台数据，增加对应工作包。暂估12–20周交付窗口，取决于人员分配和接口准入，是规划假设，非供应商承诺。

### 上线后技术支出与融资总额分开

暂以维护RM2k–4k/月、云与工具RM1k–3k/月做可调整占位，未获供应商或用量报价。维护仅指基础监控、修复和安全更新，新功能另估；云费用随内容存储和数据调用变化。

开发加**上线后完整12个月**基础技术费用：低RM160,200，高RM353,100；基准约RM249,750（约RM250k）。这是“建设＋上线后一年”的口径，不是从今天起12个月，也不是公司一年总预算。

融资需求还须加创始人/运营、品牌销售、创作者招募、活动补贴、审核客服、专业服务、交易费及营运缓冲，再扣可依赖现金收入。用户资金不能直接当公司收入或免费营运现金。旧自聘开发团队runway已失效，本轮不沿用。

### 投资人团队页如何写

推荐文字：**“产品与商业由Wringy负责；开发由创始人关联公司Belcort承接，按项目市场价编列预算。实际费用及交付资源将在范围确定后确认。”**

后续报价明确Wringy取得的代码及使用权、代码库与部署账号归属、里程碑验收、维护范围和变更价格。这是让资金用途可解释的交付安排；不能仅凭同一创始人就写成协议已经签署。

## 6. 下一层基础交付

首先补一页产品命题：首批付费用户、具体问题、首发完整链路、验证证据和投入上限。然后用上述14页形成有证据状态的内容稿；再把首发链路展开为PRD（产品需求及验收规则），用关键页面确定设计方向，并让Belcort按同一范围校准架构与费用。

需要创始人随后参与的重点只有三组：首批品牌类型与可接触资源；第一种奖励模型；商业验证阶段可投入的钱与时间。此稿没有替创始人回答，也不阻止先完成研究、内容结构和预算框架。
