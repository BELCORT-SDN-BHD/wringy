# 数据与付款接入建议

**2026-09-14最新执行顺序：** 先依据官方文档准备TikTok、Instagram／Meta、YouTube与付款接口、模拟数据及内部测试；真实授权和联调放在上线前，不阻塞设计及模拟开发。规格冻结审批独立保留；模拟成功不解除生产数据、资金和准入门槛。见[外部接口内部契约](external-interface-contracts-v1.md)。

2026-09-14，文档审阅后的优先验证方向，非选型冻结、开发启动或资金操作授权。目标是减少自建账号授权、身份和银行资料表单，同时让Wringy保留活动规则、计量口径、申请、审核与奖励账本。没有新增费率、预算或收益预测。

## 先验证这两条路径

**数据先验证TikTok官方OAuth。** OAuth是账号主人向平台明确授予读取权限的流程。先用获授权的自有账号和视频，验证身份、视频归属及观看数据能否连续读取。这是研究优先级，不排除YouTube，也不表示TikTok已批准Wringy或奖励用途。[Display API入门](https://developers.tiktok.com/docs/en/display-api-get-started)要求开发者账号，以及Login Kit和TikTok API相关批准；读取视频需对应授权范围。既有Query核对支持授权用户视频归属与`view_count`，详见[架构文档核对记录](architecture-content-rewards-v2.md)。

YouTube作为第二条验证路径保留：已有文档支持统计与频道ID，但频道ID不证明请求者控制账号，也不是观看者地域。没有实际授权测试前，不开放相应活动数据能力；不能因看到总观看数便承诺地区计费。

**付款先验证Stripe Connect托管入门，并评估托管Checkout收款。** 候选目标是商家一笔付款、向多名创作者分别分配奖励；不是现在批准平台收款、托管或垫付。Connect托管入门可由Stripe按国家和所需能力收集身份及经营资料，减少自建表单；从返回网址回到Wringy不代表账户已具备所需能力，必须核对账户状态。[官方托管入门](https://docs.stripe.com/connect/hosted-onboarding)

官方“Separate charges and transfers”入口说明平台收款后向多个账户转移资金，值得作为该结构的候选。[官方页面](https://docs.stripe.com/connect/separate-charges-and-transfers) 本轮完整地区变体未能读取；马来西亚支持仅在官方搜索摘要出现，**仍须以实际经营主体和账户验证**。Checkout只是待验证的托管收款候选，未在本轮证明其与所需Connect结构、币种、退款及创作者所在地组合均适用。转移到连接账户也不等于已到创作者银行。

## 哪些交给提供方，哪些留在Wringy

提供方负责其授权、身份核验和银行资料流程；Wringy不复制这些敏感表单。托管页面明确标示外部服务，与Wringy界面区分，不强行套用Wringy设计系统。Wringy三角色页面仍使用统一Linear＋shadcn规范。

奖励规则、预算预留、申诉、确认应付和对账继续由Wringy负责。提供方付款成功不能替代奖励批准；未知结果先查原支付尝试，不能重付。还需核对资金责任、退款和争议扣款如何影响已分配奖励。

## 开始实际验证需要什么

|路径|输入与通过证据|
|---|---|
|TikTok|获批开发者应用、所需授权范围、明确获授权账号及自有视频；保存归属、基线、增量、撤权及读取失败结果，不把缺失记零|
|Stripe|实际马来西亚经营主体的Connect资格与账户状态；获授权沙盒及测试连接账户；核对托管入门后能力、收款与分配、重复通知、未知对账及退款|

**目前只有文档审阅，没有API请求、沙盒交易或实际PoC。** PoC指用受控样本验证路径能否工作。仅使用明确获授权的测试环境；沙盒通过不等于商用准入或真实到账。当前先按文档准备接口及模拟，生产开放前完成上述核验再确认真实接入，不因推荐而改变[已确认默认配置](campaign-defaults-v1.md)或[PRD草稿](prd-content-rewards-v2.md)。
