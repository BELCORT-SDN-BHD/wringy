# Wringy Content Rewards：机制研究与社交数据可行性方法

研究日期：2026-09-13（Asia/Kuala_Lumpur）。状态：研究建议，未冻结、未批准为产品规格。范围：沿用既有研发上限 RM50,000、2–4 个月约束，研究可行性取舍；不是代码逆向、安全测试或新产品实现。

## 研究结论与证据边界

最先验证的不是竞品有多少按钮，而是“哪些投稿的数据能合法取得，且足以解释为什么支付这笔奖励”。**目前不能承诺三平台任意公开视频的马来西亚真人观看核验。** TikTok 普通 Display API 是发布者授权路径；YouTube 有独立的公开统计及所有者授权分析路径；Instagram 专业账号路径成立，但本轮未完整读到现行 Insights 字段文档，不能宣称逐帖地区播放已可用。[T01][Y01][Y03][I01][I02]

本轮完成：官方文档阅读、公开网页文字观察、机制拆解、有限试验设计。未完成：Clipping 登录后流程、社交授权、API 实际调用、平台应用审核、充值、投稿、付款或到账核验。文档支持字段不代表 Wringy 应用已获权限，更不代表这个奖励用途已获平台许可。

证据分四类：**事实**（本轮一手文档或直接观察支持）、**假设**（可被试验推翻）、**Wringy 提案**（自己的规则选择）、**未知**（缺少权限、证据或可复现样本）。来源清单见 [sources.json](sources.json)，每条包含支持范围及不能证明的事；网页读取失败也记录，不用第三方转述填成事实。

旧报告 [whop-wringy-blueprint-v1/report.md](../../whop-wringy-blueprint-v1/report.md) 只提供问题与来源指针。当前目标是 Clipping（clipping.net）；Content Rewards（contentrewards.com）及其中名为 Clipping 的活动不能混同。初始搜索还读到了 clipping.io，但未核实它与 clipping.net 的关系，故排除其资料作为目标产品证据。每一行必须标明产品、域名、角色、日期与版本。

基础检查：本工作目录不是 Git 仓库；本轮仅在指定研究目录新增两份文件。研发基础、客户需求批准和完整平台许可未在本轮验证；关闭这些缺口所需的工作量、报价与审核等待时间仍待核实，本稿不另设研究预算或固定排期。按照本轮“不实现、不冻结 PRD”的授权继续研究，后续建设仍须另行确定。

## 怎样观察黑箱而不猜后台

黑箱观察指分析可见输入与结果，而非查看私有实现；它本身也不豁免平台使用限制。**本轮边界是公开文件的机制重建、已合法取得记录的分析，以及 Wringy 自有测试环境；不是反编译、平台私有路由访问或探测。**

2026-09-13 用户明确补充：主审未接受相关协议，认证开户探索已暂停，等待用户处理。本轮独立读取 clipping.net 条款，页面标示 2026-01-01；第4节明确禁止自动工具访问、逆向/反编译及竞争分析。[C04] 因此本稿不把“正常 UI”“有账号”或用户提出“methodology”当作继续 Clipping 认证研究的许可，不再安排其登录、Continue、投稿、商家角色或付款试验。这里记录操作边界，不判断合同是否成立；未点击接受也不等于可以忽略访问条款。

已取得、可复查的观察：
- 主审保存的 Clipping 入门记录显示 Continue 关联协议；Dashboard 导航返回入门页。研究工作者读取了记录，没有重做操作；这只证明该账号当时的路径，不证明所有角色的权限规则。[C05]
- 主审保存的公开品牌页/FAQ 声称按观看付费、设置预算上限及过滤虚增观看；它们是公开声明，不是商家后台、资金守恒或反作弊准确性证据。[C06][C07]
- 本轮直接读取的 Content Rewards 创作者页展示发现活动、发帖、获得奖励的步骤和收益估算输入框。没有输入视频或提交；它是另一个产品的参照，不支持 Clipping 的实现结论。[C03]

后续只从已取得公开材料选最多3个活动例子，按创作者/品牌/运营三种视角提出问题；各条路线的输入/结果试验在 Wringy 自有离线环境最多重复两次。缺少的 Clipping 品牌、运营及认证路线保持未知，不为补全报告继续进入。未来平台研究若要超出此范围，须先解决许可边界，不由本稿自动恢复。

每个观察记录：观察编号、原始 URL、产品与角色、账号是否授权、时间和时区、前置状态、一个正常 UI 动作、结果文字/截图、等待时间、另一种解释、是否重复成功、证据文件位置。隐去个人资料和令牌；没有截图时标“文本观察”。报错不证明业务规则，隐藏按钮不证明服务器权限正确。

不枚举编号、不猜隐藏接口、不重放私有请求、不采集他人登录态，不绕过登录、验证码、地区或速率限制；也不以合法社交 API 研究为由调用 Clipping 私有路线。不可用页面记录失败后停止。并发、断网、回调重放、余额争抢等故障案例只在 Wringy 自有离线模型或获授权的服务商沙盒验证，不在竞品上制造。

## 机制分解与状态：作为分析坐标，非 Clipping 内部状态

| 用户关心的结果 | 待区分的状态 | 最小证据及转换条件 |
|---|---|---|
| 我能否参加任务 | 浏览、申请中、获准、退出、活动关闭 | 活动规则版本、参与资格及决定时间 |
| 这是不是我的投稿 | 未连接、已授权、归属匹配、授权失效、归属待查 | 平台稳定账号 ID、作品 ID、授权范围与时间 |
| 内容是否达标 | 草稿、待审、需修改、通过、拒绝、申诉中 | 原规则、审核理由及操作者；草稿通过不自动代表发布稿通过 |
| 播放量能否使用 | 未取数、有效快照、延迟、过期、部分缺失、不可访问 | 指标定义、时间窗、字段、最近成功时间 |
| 是否存在争议 | 未审查、风险待核、补证中、放行、不予认可 | 风险理由和反证；异常增长不是造假的裁决 |
| 奖励是否确定 | 估算、待确认、已确认、调整、取消 | 规则版本、可用证据、预算约束；具体合同条件待选择 |
| 钱是否到账 | 未发起、处理中、结果未知、成功、失败、退回 | 服务商交易号、最终状态、账单对账；“发起”不是“成功” |
| 活动能否结束 | 开放、停止新投稿、处理在途、可结清、关闭 | 未决投稿、已承诺款、退款与余额解释 |

建议把上述状态分开研究。例如内容已通过但授权过期，表现为“内容通过、数据待恢复”，而不是一颗含糊的“失败”标签。这是 Wringy 的可解释性提案；UI 上看到相似文字仍不能证明竞品采用相同的数据模型。

## 平台数据：所有者授权与任意公开视频

API 是平台公开允许的软件取数入口；OAuth 是账号主人在平台同意授权、无需把密码交给 Wringy 的连接方式。

| 路径 | 播放与账号归属 | 地理观众信息 | 马来西亚可行性判断 |
|---|---|---|---|
| TikTok 发布者授权 Display API | video.list 权限；query 验证视频属于授权用户；字段含 view_count。最多 20 个作品 ID/请求。[T01][T02] | 已核字段表没有逐帖国家观看字段；不能据此承诺马来西亚播放 | 值得做授权小样本；应用审核及奖励用途仍未获证实，不可直接宣布已可商业上线。[T03] |
| TikTok 任意公开 clip | 同一路径不是任意视频查询器。页面公开可看，不等于可自动取数 | 本轮未找到可用于 Wringy 普遍计酬的普通接口 | Research API 明确不接受商业用户；不能把“我们做研发”当成资格。[T04] |
| TikTok Research / Business 特殊路径 | Research 准入与非商业限制明确；Business 需要另核具体产品、授权及合同 | Research 的 region_code 查询示例用于创作地区，不能代替观看地区。Business 搜索结果中的主要受众国家也不能推出逐帖地区观看数。[T05][T06] | Research 排除出商业关键路径；Business 仅作为待确认选项，不列入首版能力或预算依赖 |
| Instagram 所有者授权 | 官方集合确认 Business/Creator 专业账号路线；Facebook Login 路线要求关联 Page，不支持普通消费者账号。[I01] | 逐媒体 views、账号受众 country、时间窗、门槛的现行字段表未完整取得，本轮只能列验证项，不能写成已验证 | 先核准账号类型、登录路线、Insights 权限、外部用户准入；本轮没有马来西亚生产授权证据 |
| Instagram 任意公开 clip | 官方说明只承诺对其他专业账号有限的基本元数据/指标；不能推成任意账号的播放和私有 Insights。[I01] | 未证明可取他人逐帖马来西亚观看 | Business Discovery 详情读取 429；不采用未经核验的字段清单作兜底。[I03] |
| YouTube 任意可访问公开视频 | Data API 项目凭证可访问公开资料；videos.list / statistics.viewCount 与 snippet.channelId 支持计数和发布频道识别，但不证明提交者控制该频道。[Y01][Y02] | 公开视频统计没有等价的国家观看拆分 | 公共统计技术路径有文档支持；平台许可、计酬用途和存储政策仍是独立关卡 |
| YouTube 频道所有者授权 | Analytics 只读权限；channel==MINE 指向授权频道，可按其视频过滤。[Y03] | Channel Reports 支持 country 维度与 video 过滤；可研究 MY 行。ZZ 是未知国家；低流量可能缺行。[Y04][Y05][Y06] | 三者中本轮证据最清楚的逐视频地区数据候选；仍须马来西亚外部账号授权实测，且不保证完整、实时或真人 |

**Instagram 待证字段不是承诺。** 后续应逐项查当前版本的 media insights/views、user insights/follower_demographics、engaged_audience_demographics 与 country breakdown 是否存在及可组合；“少于 100 粉丝受限”“只给 Top N”“只支持某时间窗”等说法在本轮未读到完整现行一手字段表，均不得写死。即使账号级地区受众可用，它也不等于某条 Reel 在活动期间的地区播放。Facebook Login 与 Instagram Login 的前置条件和权限不能混用。[I02][I04]

**归属也分层。** 公开频道 ID 只说明谁发布；OAuth 匹配说明当时获得平台授权；简介验证码最多说明当时能改简介。三者都不独立证明剪辑素材版权、银行收款人身份或每次观看真实。优先匹配稳定平台 ID，显示名和 handle 仅用于展示，账号更名须重新核对关系而非直接判作弊。

**不能用地理代理变量付款。** 马来西亚注册账号、MY 手机号、内容语言、发布时间、粉丝国家占比、创作者住址，均不能替代逐帖观看发生地。若某账号有 60% 马来西亚粉丝，某帖 10,000 views，乘成 6,000 “马来西亚核验播放”没有证据依据。平台给出的 country 也不是国籍、公民身份或真人证明。

**技术许可与商业许可分开。** YouTube 的互动奖励条款禁止 API 客户端奖励用户观看、点赞、订阅等互动。**这不能直接推出“禁止按作品表现向创作者支付报酬”**：奖励观众互动与支付创作者内容绩效报酬并非同一个事实情形，具体适用仍需解释。应按 Wringy 的实际参与者、奖励触发条件及数据用途，向平台或合适的专业顾问核实；不能仅凭字段存在断言获准，也不能仅凭观众互动条款断言被禁。另需分别核查派生指标和存储限制，尤其是把 views 用于奖励计算、扣减或质量评分的方式。未澄清前继续研究原始数据可得性和 Content Rewards 计量条件，相关商业用途保持待确认，不自动改为按帖付费。[Y07]

马来西亚准入试验须记录：Wringy 主体及应用所在地区、外部测试者账号地区与类型、请求权限、审核状态、返回字段、允许用途、配额与存储要求。三平台文档均不等于授予 Wringy 个别许可。人工由主人展示官方分析只能作为较低强度补证；第三方服务也必须提供合法授权链与具体字段证明，不能用采购掩盖抓取来源。

## 有界试验：可观察结果 → 假设 → 区分性测试

以下全部为**未执行**的研究矩阵；支持文档不算测试通过。建议总计最多 12 个自愿授权账号，每平台最多 4 个、每账号最多 3 条已有作品、观察 14 天；不购买观看或组织刷量。允许不同成熟度/低流量样本，样本不足如实报告。非所有者样本仅按官方公共接口许可读取，或在文档明确验证归属的接口上用两位已同意的参与者做一次错配测试。

| 要回答的问题 | 可观察结果 → 假设 | 有界测试与通过证据 | 失败或不能执行时 |
|---|---|---|---|
| 界面流程是否真的到达下一步 | 显示加入入口 → 可能直接加入，也可能申请 | 比较已取得记录与公开规则；在 Wringy 自有模型推演两种路径 | Clipping 认证测试暂停，标未知，不补画“实测流程” |
| 谁能证明作品归属 | 公开链接可读 → 不代表投稿者拥有 | 每平台一组自己/另一位参与者作品；核对授权身份与作品关系 | 无稳定匹配就不能标已验证归属 |
| 外部马来西亚用户能否接入 | 开发者账号成功 → 可能仅限内部角色 | 每平台至少两名非应用管理员，记录审核模式及最小权限 | 只能测内部角色时，商业准入未通过 |
| 播放字段是否可重复取得 | UI 有播放 → 官方接口可能不同口径 | 同一作品同一时间记录 UI 与允许的 API；初次及第1/3/7/14天 | 差异记日志，不判其中之一是假 |
| 任意公开与授权数据差在哪里 | 本人作品返回值 → 不代表公开接口通用 | 对照平台文档及允许的公开调用；不探索隐藏端点 | 缺接口就去掉该覆盖承诺 |
| 能否证明单帖 MY 播放 | 账号受众地区存在 → 可能非单帖观看 | YouTube 单视频 country 报告；Instagram/TikTok 先证明字段，再测试同窗 | 没字段/没行=未知，不乘粉丝比例 |
| 低量/时间窗会否隐藏数据 | 返回空/总数不等于各国和 → 可能隐私或延迟 | 同一授权作品比较7/14天窗及无地区总量；不反推被隐藏个体 | 标部分可用，不能把缺行作0 |
| 断授权后是否仍被当新数据 | 页面保留旧数 → 可能缓存 | 主人主动撤销一次并重连，记录失效与恢复时间 | 旧值带时间；停止新增计酬资格 |
| 数据是否可修正 | 计数下降/帖子不可访问 → 可能修正或删除 | 真实自然观察；删除/私密仅由同意者操作测试作品一次 | 保留原因未知；不自动罚款 |
| 内容通过是否等于可付款 | 通过标签 → 可能仍等计量/风险 | 仅分析已取得公开文件；Wringy 桌面推演交叉状态 | 不根据标签推导私有规则；不恢复 Clipping 认证探索 |
| 两份奖励是否争用同一余额 | 两稿接近预算上限 → 可能超额 | Wringy 离线账目模型两笔顺序互换、重复事件各一次 | 余额不守恒就不能进入实现验收 |
| 付款超时是否会重复打款 | 无响应 → 可能已支付 | Wringy/支付沙盒用同业务键，推演超时、晚到/重复通知、退回 | 先查询对账；结果未知不盲重付 |

每项结果只能填“通过、失败、受限、未执行”，附证据与影响。通过标准是取得相应字段/许可/可解释账目，不是达到某个播放量。12 个账号、14 天没有统计能力证明反作弊准确率或市场代表性；报告分子/分母，不宣传“全平台成功率”。

## 数据质量、时间戳及失败处理（Wringy 研究提案）

每个快照至少区分：平台与 API 版本、作品及授权账号 ID、指标原名及单位、是否 lifetime、报告起止日及平台时区、抓取开始/完成时间、最近成功时间、平台提供的数据截止时间（没有就明确未知）、请求结果、缺失原因、来源证据及授权状态。不得用本地“刚取到”代替“平台已更新到现在”。

YouTube Analytics 返回到所有请求指标均可用的最后一天；日期采用美国太平洋时区，会有夏令时变化，不能直接当作马来西亚自然日。[Y03][Y05] TikTok Research FAQ 的 48 小时新内容入库、统计最多 10 天更新属于 Research 产品，**不能移植成 Display API 的延迟承诺**。[T04]

建议研究采样：公开累计统计每 6 小时最多一次，分析报表每日一次；这是成本假设，不是竞品刷新周期或平台 SLA。36 条作品 × 每日4次 = 144 次作品读取需求/日，14天为2,016次；另有每日分析最多504次。不把作品数等同请求数：批量大小、账号授权边界、分页、额度成本和重试另计，先测控制台实际配额，不穷举账户。

| 情况 | 保存/显示 | 后续动作 |
|---|---|---|
| 明确返回0 | 0、字段与时间 | 正常记录，区别于缺失 |
| 字段缺失/不支持/隐私抑制 | unknown + 原因，保留最后有效值但标旧 | 不猜数；需要地区证据的候选奖励等待 |
| 401/403、授权撤回 | 授权失效或权限不足 | 停自动取数；重新授权/人工核对，不无限重试 |
| 429/配额不足 | 延迟、下次计划 | 尊重 Retry-After；降低频率；不换账号绕配额 |
| 网络/5xx | 尝试失败，旧值带时间 | 有限退避，建议最多3次；进入人工队列 |
| 部分成功 | 单条作品成功/失败分别记 | 不让一条成功掩盖批次失败 |
| 负增量、换口径、删除或私密 | 记录修正/不可用及前后证据 | 冻结待确认部分；对已付款调整另立决定，不静默改历史 |
| 达到结算日仍未完整 | “数据待补齐”，列缺失范围 | 按事先选择的延后/争议流程处理，不偷偷换数据源 |

如采用快照差值，必须先验证同一字段、同一口径和基线可得；晚提交不能凭一份 lifetime 数倒推出活动期间播放。YouTube 派生使用仍受 [Y07] 的独立许可关卡约束。

存储不能以“对账”为由永久保留全部社交数据。YouTube 对授权/非授权数据、30天复核或刷新、删除请求有不同要求。[Y07] 研究应分开最小业务付款记录与受平台限制的社交证据，并核查撤权后的处理；不是用哈希或截图规避删除规则。证据最小化、访问限制、同意及到期删除要列入马来西亚上线前的隐私评估，本稿不提供本地法律结论。

## 预算争抢与支付对账（仅为 Wringy 建议设计）

这部分用于验证钱是否能解释清楚，**不是 Clipping、Whop 或 Content Rewards 的后台事实**，本轮不建账本、不连接真实资金。

候选账目应区别：品牌已确认入金、可分配奖励余额、暂留预算、已确认未付奖励、已支付奖励、退款中/已退款，以及独立列明的平台费和外部费用。一个金额不能同时占两格。活动关闭前仍有待决投稿时，应先按选定规则处理，不可把全部可见余额退完。

离线例子：奖励池 RM1,000，已支付 RM300，已确认未付 RM200，暂留 RM100，可分配 RM400；合计仍为 RM1,000。两位创作者同时各请求确认 RM300，不能各自读取 RM400 后都获批。候选规则可以是“按明确顺序只确认一笔，另一笔等待”或事先约定的限额分配；不能事后秘密按比例削减。品牌/创作者需理解预算何时算已占用，再选择规则。

最低模型检查：
1. 相同投稿/事件重复处理，只形成一次义务；并发顺序不同仍不超池。
2. 暂留转已确认只转移金额，不重复扣；拒稿释放暂留需留下理由。
3. 支付发起必须引用同一笔已确认义务；业务唯一键（重复请求识别号）保持不变。
4. 服务商超时进入“结果未知”；先查原交易及账单，成功后不能再次支付。
5. 通知重复、乱序及迟到不倒退最终状态；退款/退回用独立调整记录。
6. 对账匹配业务义务、服务商交易、余额变动、银行/服务商结算文件；毛额、费用、净额、币种与日期逐项说明，不能只对“总额差不多”。
7. 付款失败不自动释放创作者已确认应付款；未付义务或结果未知时不能把对应款退给品牌。

风险审核是单独的人工决定链：异常、补证、理由、复核、申诉。平台汇总计数不能给出逐次真人清单，增长峰值、低互动或地区异常都不能单独证明刷量。竞品宣传的“验证”也不证明算法、供应商、召回率或误判率。本轮不训练反作弊模型，不承诺“100%真人观看”。

## 在既有研发约束内判断可行性

沿用既有 **RM50,000 研发上限、2–4 个月**，不新增预算分配、停损金额或逐周交付承诺。本轮研究要识别哪些依赖会影响该约束，而不是用未经报价的数字替代可行性证据。前文的小样本数量和观察窗口只是有界试验建议，不是已批准项目排期。

| 可行性关卡 | 需要取得的证据 | 对既有约束的影响与待报价项 |
|---|---|---|
| 合法取得所需数据 | 实际账号类型、权限、允许用途、外部马来西亚账号授权及字段返回 | 应用审核时间不可由研发保证；第三方数据服务须提供授权链、覆盖范围、报价及限制 |
| 能解释合格播放 | 作品归属、指标定义、时间窗、缺失/修正处理；若承诺地区观看，须有同粒度地区证据 | 用样本判断可自动取得的范围与人工复核量；集成和运营支持工作量待估，不先分配金额 |
| 能解释奖励和付款 | Wringy 自有模型的预算守恒及重复事件处理；候选服务商的状态、账单及对账资料 | 支付接入、失败处理、费用与测试环境需据实际方案报价；不把服务商口头承诺当完成 |
| 能在现有额度和期限内完成 | 对上述依赖的实际工作量估计、外部报价、审批等待及现有研发承诺的合并核对 | 如不能证明适配 RM50,000／2–4 个月，报告缺口并缩减承诺或暂停相应能力，不自行增加预算或重排批准范围 |

报价须说明包含哪些接入、验证与支持工作，哪些持续服务费或试点支出另计；其是否纳入既有额度须沿用项目已批准口径，口径未明确就记录待确认。本稿不自行排除费用以制造“预算内”的结论。

建议以三个结果收敛：
- **可以继续验证**：至少一个平台、至少两名外部马来西亚账号能合法授权；身份、作品、字段与时间能够对应，允许用途和保留规则有可核对依据。试验通过不自动等于商业上线获准。
- **缩小观看口径，保留 Content Rewards 意图**：如只能取得全球播放，在品牌明确同意且平台允许用途已核实的前提下，研究有限的“全球合格播放”奖励试验；合格条件、计量窗口与证据限制须写清，仍不保证真人观看。否则暂停“马来西亚地区观看”承诺，不能用粉丝比例或人工截图补成地区核验。按帖／固定报酬 UGC 仅是超出现有范围、需另行明确选择的替代方案，不是默认退路。
- **暂停相应能力**：若计量依赖不可获得的地区字段、未获许可的使用方式或真人保证，就保留缺口；应用审核等待及样本失败不能靠抓取、推算或工程承诺掩盖。此时不把 Content Rewards 自动改成另一个产品方向。

本研究交付的验收点：机制与未知分开；每个平台比较所有者与非所有者路径；每项地理指标说明粒度与限制；所有试验有边界及失败去向；钱的方案明确属于 Wringy；来源可复查；不含私有后台断言或实施代码。当前剩余关键缺口是 Instagram 现行字段全文、三平台马来西亚外部账号实测、奖励用途许可及真实服务商对账能力，均未宣称完成。
