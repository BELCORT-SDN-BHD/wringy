# 早期投资人 Deck：内容与极简设计研究

核查日期：2026-09-10。仅采用下列五篇机构官网一手资料；年份代表本次核查，不代表资料均发表于 2026 年。不采用旧文中的估值、薪资或融资金额作为当下马来西亚行情。

任务边界：仅研究，不制作 PPT。Wringy 的 Malaysia-first Creator Rewards 初始假设、长期向 Whop 类平台发展、尚无已验证 traction（真实客户采用或交易进展），以及旧稿视觉被否决，均来自本次用户交代，未独立核查。未检查旧稿，不能诊断其具体缺陷；以下 Wringy 文案和页面安排均为研究建议，非获批产品规格。

## 1. 五个一手来源与可核查结论

| 来源 | 关键证据 | 适用边界 |
|---|---|---|
| [S1 · Sequoia — Writing a Business Plan](https://sequoiacap.com/article/writing-a-business-plan)（2019） | 公司一句话、问题、方案、为什么现在、市场、替代方案、商业模式、团队、已有财务、五年愿景。Sequoia 以 Airbnb 为例，强调清晰思考与抱负。 | 内容骨架；并未规定必须十页，也没有要求虚构财务。 |
| [S2 · YC / Geoff Ralston — A Guide to Seed Fundraising](https://www.ycombinator.com/blog/how-to-raise-a-seed-round/)（2016） | 大多数创始人需要产品及客户采用证据；融资额应关联可信计划与下一里程碑。材料应能供投资人转交合伙人独立阅读；顺序没有固定格式。 | 种子轮建议；不能据此保证无进展项目能融资。 |
| [S3 · YC / Kevin Hale — How to Design a Better Pitch Deck](https://www.ycombinator.com/blog/how-to-design-a-better-pitch-deck/)（2015） | 大字、简单字体、高对比、一页一个意思；结论直接写出。反对过量文字、复杂截图及装饰性动画。 | 5–7 页建议针对 Demo Day 短讲，不能硬套到完整融资材料。 |
| [S4 · YC / Dominika Blackappl — Practical Design: Pitching](https://www.ycombinator.com/blog/practical-design-pitching/)（2016） | 150 秒短讲用于争取后续会面；市场宜自下而上估算。进展可以说明开始时间、已建内容及真实客户意向；增长数字必须真实。 | 演讲辅助页不等于完整阅读材料；可按故事调整或省略页面。 |
| [S5 · NFX — The Non-Obvious Guide to Fundraising](https://www.nfx.com/post/the-non-obvious-guide-to-fundraising)（页面未核定发布日期） | 主张短而清晰的首次会面材料；示例列出 15 项，包含附录。标题应传达结论；附录备好难题与数据；模型假设须清楚。 | 单家基金的指导，非统一页数标准。 |

## 2. 阶段决定证据，不靠轮次名称装成熟

- **假设／pre-seed：** Wringy 当前按此证据状态组织。解释谁遇到什么问题、团队为何有资格解决、准备怎样验证。没有已核验访谈、原型或试点，就注明尚待开展；不能把验证计划标题写成“市场验证”。这是针对当前资料状态的判断，非正式融资轮次认定。[S1](https://sequoiacap.com/article/writing-a-business-plan)
- **已有产品的 seed：** 增加真实采用、付费、重复使用等证据，并交代时间范围与分母。YC 明确指出仅有故事能融资是少数情况，不能把“早期”理解成无需证据。[S2](https://www.ycombinator.com/blog/how-to-raise-a-seed-round/)
- **进入扩张阶段：** 应以重复购买、获客方式及每笔业务的收入成本证明可复制性，而非只增加愿景页面。这是据证据要求作出的应用建议，不是本研究核实过的 Series A 统一门槛。[S5](https://www.nfx.com/post/the-non-obvious-guide-to-fundraising)

Wringy 可用的诚实表述示例：“我们计划从马来西亚的 Creator Rewards 场景切入；本阶段要验证谁愿意付费、创作者是否持续参与，以及交付能否重复。”其中“奖励谁、按什么结果、由谁付款”仍须产品定义支持，本研究不代填。

## 3. 主材料与附录：研究备选阅读顺序

主审说明：以下是研究备选骨架。当前Wringy逐页建议统一见[投资叙事与产品蓝图](../foundation/investor-product-blueprint.md)，采用14页；本研究不作为第二套页数规格。

建议先以 **约 11–13 页主材料**组织；这是本项目编辑建议，不是机构标准。骨架综合 [Sequoia](https://sequoiacap.com/article/writing-a-business-plan) 与 [YC](https://www.ycombinator.com/blog/how-to-raise-a-seed-round/)，可按证据强弱调整顺序。

| 主材料要回答的问题 | Wringy 应呈现的内容 |
|---|---|
| 1. 做什么、为谁 | 一句具体定义；Creator Rewards 须解释，不能只有行业标签。 |
| 2. 客户为何需要 | 首批付费方与参与者各自痛点；区分访谈事实与团队假设。 |
| 3. 为什么现在、为什么马来西亚 | 有出处的变化或团队优势；未经研究不写“市场空白”。 |
| 4–5. 方案如何运转 | 一个具体使用场景及简单流程；概念图明确标“拟议流程”。 |
| 6. 当前证据与下一验证 | 已完成、尚未知、如何验证分开；不造增长曲线。 |
| 7. 如何获得首批用户 | 招募／获客假设、试点方法与成功条件。 |
| 8. 如何赚钱 | 谁付钱、收费对象、主要成本；费率标假设，奖励总额不能冒充收入。 |
| 9. 市场能有多大 | 首批可触达客户与支出假设，再解释更大市场；避免直接套全球创作者总人数。 |
| 10. 为什么能赢 | 真实替代方案与差异；不能用未经核验的竞品叉号表。 |
| 11. 团队为何合适 | 可证明的相关经验与能力缺口。 |
| 12. 长期方向 | 当前切入口如何可能通往更广平台；扩张以验证成功为条件。 |
| 13. 融资请求 | 待确认金额、可支持时长、用途、下一轮应拿到的证据。 |

**附录负责追问。** NFX 明确建议把可预见难题与数据放入附录。[S5](https://www.nfx.com/post/the-non-obvious-guide-to-fundraising) 对 Wringy，建议收纳访谈记录、市场计算、竞品出处、预算情景、详细产品流程，以及奖励审核、防作弊、争议处理等待验证机制。影响商业模式是否成立的关键风险仍应在主材料简述，不能藏进附录。未有资料的项目标“待研究”，不为凑页数编造。

**演讲版与阅读版可以共享叙事。** 现场版减少字数；发送版保留必要定义、日期、单位和来源，让缺席者也能理解。无需把附录全部讲完。[S2](https://www.ycombinator.com/blog/how-to-raise-a-seed-round/)

## 4. Venture scale 为什么不等于宣称独角兽估值

Venture scale 指业务有潜力成长到足以支持风险投资回报的规模；估值则是融资中对公司价值的定价。前者需要市场、收入路径与扩张机制，后者不能由一句宏大愿景推出。这个区分是综合推论：Sequoia 分别要求市场潜力和未来愿景；YC 单独讨论估值，并指出高估值不提高成功概率。[S1](https://sequoiacap.com/article/writing-a-business-plan)、[S2](https://www.ycombinator.com/blog/how-to-raise-a-seed-round/)

Wringy 可论证：“先验证马来西亚奖励场景；若付费与参与能重复，再测试相邻客户、地区及更广的创作者商业服务。”每一步须说明复用什么能力、还缺什么证据。Whop 类平台是用户指定的远期方向，不能充当 Wringy 已有需求、收入或估值的证据。

市场页建议采用“可服务付费客户数 × 年均可实现收入”的假设模型，并展示假设来源；若按交易收费，区分交易总额与平台收入。YC 的自下而上方法支持这种思路，但公式中的 Wringy 数值尚待研究。[S4](https://www.ycombinator.com/blog/practical-design-pitching/)

## 5. 极简设计：先建立可读性，再确定审美

**来源支持的原则：** 一页一个意思、标题写结论、大字与高对比、减少复杂截图及无关装饰。[S3](https://www.ycombinator.com/blog/how-to-design-a-better-pitch-deck/) **本项目建议：** 统一网格与页边距、单一字体家族、克制的强调色、稳定的标题位置；这些具体选型并非 YC 或 Sequoia 的规定，也不宣称等于其品牌风格。

- 标题示例：“本阶段先验证付费与重复参与”，比“Traction”更准确；市场尚未测算时，不写强结论式大数字。
- 产品页只放一个可辨识场景或三步流程；若没有真实产品截图，显著标“概念示意”，避免高保真画面暗示已上线。
- 图表保留单位、期间、来源；把假设与实测视觉区分。缩小字号不是解决拥挤的方法。
- 真实案例：YC 文中用 Shred Video 展示如何把难读的小字说明改成醒目描述，也用 SparkGift 的简单步骤替代复杂界面。[S3](https://www.ycombinator.com/blog/how-to-design-a-better-pitch-deck/)
- 验收建议：请不了解项目的人快速看每页并复述主旨；检查整套缩略图的一致性与正常阅读尺寸下的可读性。旧稿具体失败原因仍未核实，新稿应先验证少量代表页的审美方向，再批量排版。

研究完成边界：内容与设计依据已整理；客户需求、市场规模、费率、团队履历及融资金额均未由本研究验证。本文件没有创始人审批记录，不应被视为获批 Deck 规格。
