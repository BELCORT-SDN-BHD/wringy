# Whop 全业务地图与分板块建设参考

研究基准日：2026-09-10。面向 wringy.com 创始人；马来西亚优先，卖家群体待验证。当前授权是完整拆解 Whop，尤其品牌与创作者关系，暂不选择首版产品范围。[创始人输入](../../founder-inputs.md)

**本包把目前发现的 Whop 公开业务版图分成 12 个板块、166 个功能与边界条目。** 每块都有功能清单、参与者、正常及失败流程、收费触发、责任边界、依赖、未知项与未来验收候选。覆盖不是“把首页按钮列完”：同时盘点了官方文档索引、消费者与商家流程、企业产品、开发接口、行业方案和专项条款。

“完整”在这里指**有边界、有遗漏登记、可追踪来源的公开业务地图**。不是全部后台实测、993 篇文档逐字段审核，也不是 Whop 私有财务或内部架构的复原。12 块是我们的研究分类；不是创始人已经批准的建设范围。文档冲突和未公开能力保留在卡片中，不能用猜测补齐。

## 一、先看整门生意

Whop 的公开业务可以概括为：**帮助人开始经营，销售和交付产品，获得客户，再处理这门生意中的付款、奖励和出款；也把这些能力提供给外部平台。** 官网把店面、广告、结账、钱包与 AI 经营入口并置；开发者文档同时支持“接入自己的软件”和“开发安装到 Whop 的应用”。这说明其范围超过付费社群或品牌合作撮合。[Whop 官网](https://whop.com/)、[开发者两种模式](https://docs.whop.com/developer/start.md)

| 参与者 | 希望完成什么 | Whop 提供的公开路径 | 关联板块 |
|---|---|---|---|
| 创作者、知识经营者、服务商、软件及商品卖家 | 把能力或商品变成可收款、交付、续费的业务 | 店面、结账、内容应用、经营后台 | B01–B04 |
| 买家与会员 | 找到商品、付款、取得交付、管理购买、获得支持 | Discover、会员空间、付款及退款流程 | B02–B05、B10 |
| 品牌和任务发起方 | 组织内容生产、传播或其他可验收任务 | Content Rewards 与 Bounties；两者条款和流程分别研究 | B06 |
| 内容创作者与任务参与者 | 发现活动、提交成果、获得认可和奖励 | 活动参与、提交审核、奖励与出款 | B06、B09、B10 |
| 推广者、商家推荐伙伴、模板发布者 | 因带来销售或经营者而得到奖励 | Affiliate、Partners、Blueprints；归因与奖励基数各不同 | B07、B12 |
| 广告主 | 获取流量、查看转化、管理预算 | 广告与像素、事件和归因报告 | B08 |
| 开发者及外部平台 | 在自己的产品里收款、代付，或把工具分发给 Whop 商家 | API、嵌入组件、连接账户、应用安装、企业服务 | B11，调用其他板块 |

上表是对官方产品的商业归纳，具体来源与角色限制见[商店与交付](commerce-delivery-operations.md)、[创作者与增长](distribution-creators-growth.md)、[企业与 AI](platform-ai-enterprise.md)。角色可以重叠：一个创作者可以卖课程，也可以参与品牌活动，但课程收入与活动奖励必须分别记录。

**商业循环（分析，不是已证实的增长效果）：** 创业工具和模板吸引经营者 → 经营者销售并交付 → 创作者、推广者和广告带来新交易 → 支付及出款能力处理资金 → 外部平台也接入这些服务。更多供给可能增加发现价值，更多交易可能增强支付规模；真实转化率、留存和网络效应强度没有公开数据可核实。

## 三、你关心的「品牌 + Creator」在哪里

它的中心是 B06，但一条能运行的业务链会调用其他板块：

**品牌建活动 → 设预算与规则 → 创作者报名/参与 → 产出并提交 → 核验内容或任务 → 形成奖励 → 入账 → 提现 → 异议与复核。**

其中 Content Rewards 的内容传播活动与 Bounties 的可验收任务应作为 B06 的两个子领域。前者可能按播放、单条内容或合作周期安排报酬；后者公开指南描述按获批任务提交支付奖励。它们不能共用一个未经核对的费率、时间窗或审批接口。[Content Rewards 研究及条款差异](distribution-creators-growth.md)、[Bounties 官方指南](https://docs.whop.com/developer/bounties/run-a-bounty-program.md)

例如，一家马来西亚品牌计划用 RM10,000 邀请创作者制作短视频——这只是未来产品的假设例子，不代表 Whop 已支持该 MYR 流程：

| 环节 | 哪块负责 | 哪些责任不能混入 |
|---|---|---|
| 品牌、创作者、品牌员工账户 | B01 | 注册账号不等于通过出款核验 |
| 活动规则、提交、审核、奖励义务 | B06 | 审核通过不等于钱已到账 |
| 充值或收款、资金记录、提现 | B02／B09 | 预算池及创作者所得不是平台收入 |
| 准入、身份核验、造假/争议政策 | B10 | 规则判断与实际资金执行分开 |
| 活动发现、支持、分析 | B05／B04 | 报表读取事实，不另造一套奖励账 |
| 推荐奖励、付费广告 | B07／B08，按需启用 | 是不同的获客机制，不是活动上线的必备条件 |

**关键发现：** Whop 的 Content Rewards 项目条款与当前 CR 品牌条款存在主体和规则差异。当前 CR 条款写 Content Rewards Inc，Whop 为支付服务方；不能把 CR 收取的每一笔费用都记作 Whop 收入，也不能把两套费用叠加。对应来源、费率基数和审核/计酬差异已分别保存在 B06 及增长报告中。[Whop 项目条款](https://whop.com/content-rewards-terms-of-service/)、[CR 品牌条款](https://b4e0vdqv6zgqeqj4pfgm.apps.whop.com/brands-terms)

## 四、收入从哪里来，哪些钱不能当收入

公开价表能说明收费事件，不能告诉我们实际净收入和利润。不同账户、支付渠道、国家与合同也可能不同。精确费率及冲突只在[资金研究](payments-money-trust.md)和各模块卡中维护；未来融资材料不能拿宣传交易量乘一个费率，冒充 Whop 的真实营收。

| 经济机制 | 谁付钱／什么触发收费 | 研究结论 |
|---|---|---|
| 收款与账单服务 | 成功交易及启用的附加服务 | 有公开处理费、国际卡/换汇、账单等收费条款；合作方成本及净留存未知 |
| 钱包、出款与平台支付 | 提现、资金处理或特定资金服务 | 收费随方式变化；平台客户的代付款不一定是商城销售额 |
| 风险及税务服务 | 适用的认证、争议、风控和税务事件 | 服务费与税金、准备金分开；税务覆盖及费率存在文本冲突 |
| 品牌内容奖励 | 专项活动规则触发服务费 | Whop 项目与 CR 公司条款分开；不是统一平台抽成 |
| 广告 | 广告预算和适用服务约定 | 广告媒体费不自动属于 Whop 收入；“无平台费”文档与保留收费权条款要区分 |
| 消费融资、卡和兑换 | 第三方融资支付、卡消费、资产兑换 | 有相关费用与交换费分享证据；利息、价差及 Whop 自留未知 |
| AI 媒体与公司成立 | 生成媒体扣余额、付费公司注册服务 | 有公开收费事件；AI 全套价格、供应商成本和利润未知 |
| 企业定制 | 大客户按量/国家及商务合同 | 有定制报价和专属服务入口；合同最低消费、实施费及利润未公开 |
| 开发者应用／蓝图 | 第三方应用商业化、蓝图带来后续交易 | 第三方卖家的收入不是平台收入；蓝图的奖励基数是 Whop 利润，不是商品销售额 |

本表依据[官方定价](https://whop.com/network/pricing/)、[资金研究](payments-money-trust.md)、[增长研究](distribution-creators-growth.md)及[企业/AI 研究](platform-ai-enterprise.md)。没有确认独立收费的功能不擅自新增“订阅收入线”。

必须分别统计：**商品成交额、品牌预算、广告预算、创作者奖励、商家余额、税款、准备金、外部平台的应用费、Whop 服务费与 Whop 净收入。** 同一笔钱经过支付、余额、转账、提现，不能算四次收入。退款和佣金冲正也要保留原交易关联。

商业计划还需要以下结构；这里给出研究判断而非财报事实：

- **获客渠道：** 创作者自带受众、商城发现、推广伙伴、广告、应用/模板生态、企业销售，以及迁移与创业教育。[增长研究](distribution-creators-growth.md)、[企业/AI 研究](platform-ai-enterprise.md)
- **客户关系：** 自助经营和购买、客服与争议处理、企业专属支持、University/WhopX 成长关系。具体支持承诺依产品和合同。[客户模块](modules/B04.md)、[经营支持](modules/B12.md)
- **核心工作与资源（分析）：** 支付接入及可靠账务、产品与内容交付、活动审核、风险处理、平台分发、开发者契约和客服。公开产品证实这些能力的重要性，不披露其内部团队配置。
- **关键合作关系：** 支付/银行、融资、发卡、核验、数字资产及广告平台；内容商家、创作者、开发者和推广者也是生态参与者。具体合作方和地域限制见资金、增长报告，不能认定全球同一供应链。
- **成本结构（分析）：** 支付和出款供应商成本、争议与欺诈损失、云与 AI 计算、客服审核、获客与激励、人力及合规。规模、谁承担损失和各项比例未公开。
- **可能的竞争优势（待验证假说）：** 经营者少接几套工具；支付/交付/增长数据能协同；应用和伙伴扩大供给。不能仅凭功能多，就认定已经形成不可复制的壁垒。

## 六、以后怎样按板块做，避免十二个孤岛

以下是建设组织建议，尚未批准为架构。**每种原始事实只由一块负责**，其他板块通过它获取结果；客服界面可以显示退款，不代表客服另存一套支付状态。

| 原始事实 | 责任归属 | 其他板块怎样使用 |
|---|---|---|
| 主体、团队权限、商品目录 | B01 | 活动、交易、客服引用主体及商品 |
| 价格方案、付款和订阅收费状态 | B02 | B03 根据收费及规则处理访问，B09 对应记账 |
| 访问资格与实际交付 | B03 | 客服、纠纷证据与经营分析读取 |
| 活动奖励义务 | B06 | B09 结算；B10 提供适用政策或复核结果 |
| 推荐归因与佣金义务 | B07 | B09 结算；退款后按规则冲正 |
| 广告预算、投放与营销归因 | B08 | B09 处理相应资金；B04 显示分析 |
| 账务、余额、资金移动 | B09 | 所有财务视图引用同一流水和状态；卡返现义务也归此处 |
| 核验、风险、争议和税务决定 | B10 | 交易与出款执行限制；不自行伪造“已退款”状态 |
| 客户视图、支持及导出任务 | B04 | 聚合以上事实，不改变原始交易/权益记录 |
| 外部接口、安装与授权契约 | B11 | 暴露各业务能力，不能另造一套资金或会员体系 |
| AI/网站/蓝图/迁移工作流程 | B12 | 调用其他板块；蓝图关系归 B12、佣金归 B07、钱归 B09 |

商城发布有意分成商品生命周期与市场审核/可发现状态：B01 管商品，B05 管商城上架和发现。两者不该共用一个含义不清的“已发布”。

**按一条完整业务链推进，而非先做完整 B01，再做完整 B02。** 一条业务链只拿每块必要的能力，并包括失败处理。例如：

| 可以选择的业务链 | 涉及能力 | 完成时必须能看见的结果 |
|---|---|---|
| 品牌活动到创作者收款 | B01、B06、B09、B10 的必要部分，按收款路线使用 B02；支持 B04 | 提交→审核→奖励→出款可追溯；拒绝、预算不足、争议、出款失败有明确状态 |

## 正常与失败流程

正常：创建商家 → 邀请运营人员 → 建商品与法律文件 → 引用 B02 价格方案 → 关联 B03 内容 → 预览并发布 → 将目录交给 B05、将顾客关系交给 B04。实际开户与商品说明见 B01-F01/F07/F09；这条跨模块切分是我们的分析。

失败：邀请未接受留在待处理；移除团队成员后其权限应消失（文档如此说明，未测试）；资料不足可能无法申请融资或高价结账；有历史关联的商品删除被阻止。**候选实现必须验证**私有链接不等于访问授权、取消发布不等于撤销已购权益、法律文件更新不应改写旧交易接受记录；后面三项是设计检查，不是已证实的 Whop 内部机制。

## 谁付给谁、依赖与接口

买家购买时向商家购买商品，通过 Whop 支付服务处理。卖家条款把商品描述、交付和客服责任留给卖家。没有找到本模块逐席位、逐商品、逐店面的独立收费表，不能写成不存在收费或永久免费。交易费触发和资金归属交 B02。[卖家条款](https://whop.com/seller-terms/)、[费用](https://docs.whop.com/payments-and-billing/fees/fees)（文，2026-09-10）。

| 依赖 | 原因及边界 |
|---|---|
| B02 | 商品引用价格/结账状态；团队付款权限不是实际付款执行。 |
| B03 | B01 定义商品包含什么；B03 保存内容并落实可访问范围。 |
| B04 | B04 用商品和个人身份建立顾客/候补记录；不要让顾客身份自动获得团队权限。 |
| B05 | 接收公开商品资料用于发现与评价；B01 不拥有推荐排序。 |

补充能力依赖：B09 提供提现/支付团队资金动作；B10 提供开户验证与风险状态；B11 提供外部开发者授权合同；B12 提供商品文案 AI 能力。依赖指所需能力，既不是全模块建设瀑布，也不是 Whop 内部代码调用关系。

集成接点：商家及商品 API；HubSpot 读取商品与方案进入其产品库，属于外部 CRM 连接，详见 B04-F12。[HubSpot](https://docs.whop.com/third-party-integrations/hubspot)（文）。

## 第一个纵向切片与验收提议

**假设未来建设**：一个商家、一个运营角色、一个有期限的付费商品，连接既有 B02 测试支付及 B03 一份文件。并非现在开发或上线授权。

- B01-A01：所有者创建商品；运营账号可以编辑获准字段，不能执行提现或跨商家修改。
- B01-A02：公开页、结账摘要、交付清单的商品名称与访问期限一致。
- B01-A03：移除团队成员后，其旧会话再次请求受限资源失败。
- B01-A04：已有购买记录时，删除被阻止；停止新销售仍保留已购用户合法访问。
- B01-A05：记录交易实际接受的法律文件版本，而不是仅保存现行文件链接。

拟测指标：完成首个商品的商家占比、从开户到可售用时、邀请接受率、越权操作拦截数、购买前后内容不一致投诉率。均为建议指标，无 Whop 实测数值。

## 主流程与失败流程

**正常（分析归纳）：** 商品提供报价基础 → F01/F03 生成收费计划 → B10 提供税务及准入结果 → F04/F05/F11 筛选可用渠道 → 买家确认总额 → F06 扣款 → 确认成功事件 → 通知权益模块、B09 记录资金、F09 出示收据。F10 的首张循环账单成交后转订阅，官方说明后续自动扣款发送收据，并非每期重新寄待付账单。

**失败：** 认证未完成或异步处理中不能先宣布成功；失败续费进欠费状态，按访问设置及五天重试结果恢复/取消；发票按逾期 3/7/14/30/60 天提醒，120 天后自动作废；融资不显示先查资格，不能假设平台宕机；Tap to Pay 不合国家条件回退二维码或网页。见 F06/F07/F10/F11/F14。

## 谁付钱、何时收费

买家支付商品价给卖家交易链路；Whop 收款服务收费由商家或约定承担方支付，费用触发于成功付款及实际启用服务，非单纯浏览。标准卡价 2.7%+$0.30；Billing 0.5%、启用路由 0.8% 等见[定价](https://whop.com/network/pricing/)，不是统一叠加费率。F10 说明买家有 5% 发票服务费，同时提供转嫁处理费开关，叠加关系未知。F12 的 30% 收款人为 Apple。F05 买家换汇费比例及分享未知。自动重试回收率、净利润均未披露。

## 首个纵向切片及验收候选（未批准）

**切片：单商家、单币种、网页一次性购买到收据及账务记录。** 先用模拟合作方，无真资金。

2. B02-A02：同一成功通知重复到达时只授予一次权益、只产生一次 B09 资金事件。

## 正常与失败流程

数字内容：B01 关联商品与体验 → B02 告知付款及计费合同状态 → B03 计算会员权益并核验访问 → 学习/聊天/下载 → 进度和交付事件交 B04。外部软件：有效会员 → 绑定外部身份 → 授权 → 失败进入再同步 → 查看后台结果；再同步文档明确异步执行并记录会员日志，Telegram 排除。

服务：预约或申请 → B04 跟进 → B02 成交 → B03 私有项目空间或外部服务 → 交付材料。实物：B02 支付确认 → 外部仓配收到订单信息 → B03 记录追踪 → 到货或异常交 B04。此处模块分工是分析，不是官方内部调用图。

失败路径必须区分：未付款/权益失效；找错账号；Discord 已绑定其他账号；应用未包含在该商品；上传尚未 ready；课程被删除；测验未达标；物流 unknown、退回、failure 或 error。前述状态有对应 F 行来源。预约冲突/爽约、退款后已下载文件、外部服务宕机后的补偿规则**尚无完整证据**，不能编造自动处理。

## 第一纵向切片与验收提议

**假设未来建设**：先完成“买一份有访问期限的文件＋会员交流区”，比同时搭课程、视频会议和仓储范围更小；来自 Whop 自身商品组合例子的分析，不是批准。

- B03-A01：测试付款成功且权益有效才可下载文件/进入聊天；同商家未购买其他产品的用户不可串访。
- B03-A02：付款事件重复到达不重复授权；取消期末续费不提前断开现有访问，到期后撤销。
- B03-A03：文件上传未完成不显示成功交付；授权失败可重试，并有客户可见状态。
- B03-A04：客服可定位交付失败并修复；每次动作留记录；修复不修改支付金额。

再扩展切片：课程与进度 → 活动/预约 → 一个外部身份连接器 → 一个运单跟踪连接器。每次先验证访问边界与异常恢复，不把整个家族一次做完。

# B04｜顾客生命周期、客服与经营分析

## 目的、角色与边界

## 正常与失败流程

正常：潜客申请 → 商家批准/联系 → B02 成交 → 顾客与会员分别记录 → B03 首次交付 → 欢迎消息 → 报表观测 → 客服处理 → 继续使用/期末取消/回流。买家可直接购买，不强制先成为候补。

欠费：识别欠费 → 提示更新支付方式 → B02 重试 → 成功则 B03 恢复访问，最终失败则取消。**暂停计费不等于停止访问**；期末取消与立即终止也不同。[生命周期](https://docs.whop.com/developer/guides/memberships)

售后：购买异常 → 联系商家/创建案件 → 商家接受、拒绝或补资料 → 超期平台处理 → 可申诉一次 → 终局通知；不是退款请求提交后就到账。[售后规则](https://docs.whop.com/manage-your-business/manage-payments/resolution-center)

同步失败：GHL 可能连错 agency/sub-account 或没有设默认支付；QuickBooks 错误页及重试机制不能证明其他集成同样处理。重复事件、导出权限、消息发送失败和批量误操作回滚是未来必须设计的检查，Whop 全部细节未知。

## 收费、依赖及集成

买家付商品/服务费给商家，经 Whop 处理；运营行为主要影响成交、续费和客服成本。独立 CRM、逐客服席位、Whop AI、报表或欢迎邮件收费未找到。公开费表的 Billing 项为每交易 0.5%，与发票、重试及生命周期相关；这是 B02 的收费边界，不能再给 B04 叠加一次“CRM 费”。外部软件自己的订阅及连接器合同价格未知。[费用](https://docs.whop.com/payments-and-billing/fees/fees)、[卖家条款](https://whop.com/seller-terms/)（文，2026-09-10）。

## 第一个纵向切片与验收提议

**假设未来建设**：“顾客记录＋一条售后会话＋可执行的访问修复”，从真实服务闭环开始，尚未批准。

- B04-A01：同一顾客买两项商品，顾客表一行、会员表两行，客服能定位正确商品。
- B04-A02：未获退款权限的客服可以沟通/请求修复，但无法直接操作财务。
- B04-A03：一个访问故障从创建、回应、B03 修复到关闭全程可追踪；重复事件不创建第二个相同个案。
- B04-A04：期末取消、立即终止、暂停计费在顾客界面有不同文案和访问结果。
- B04-A05：报表先选择一个清晰指标（如首次成功访问率）；导出与页面同口径，并限制跨商家读取。

后续切片：加入/退出消息 → 候补批准 → 退款证据与申诉 → 一个 CRM/会计连接器；不要一次重建完整 HubSpot。

拟测指标：潜客到成交率、首次回应时间、解决时间、重复工单率、欠费恢复率、期末取消率、交付问题占比、同步失败率与人工修复量。全部是测量建议，非 Whop 当前数值。

## 正常与失败流程

CR：品牌预存→发现/申请→可选草稿→社交发帖及提交→审核→有效表现计酬/交付结算→冻结结束→可用余额→Whop 提现。CPM 当前合同为批准后 7 天计酬再冻结 3 天；不是所有历史活动通用。[创作者条款](https://b4e0vdqv6zgqeqj4pfgm.apps.whop.com/terms)

CR 失败：不符公开要求被拒；刷量标记暂停结算；断开授权影响跟踪；未结算收益可逆转；预算耗尽/封顶停止继续计酬；未清待审不能退款。实际申诉时效与支付到账未测试。

Bounty：创建/定时到期→资金锁定→open→执行者提交→submitted→人工批准→支付→名额全满 completed。拒绝为 denied；取消有在途时先 closed，处理完才 canceled；scheduled 为未发布草稿。空证据、无发布时区、资金权限不足、越权投稿均属于失败面。[指南](https://docs.whop.com/developer/bounties/run-a-bounty-program.md)、[对象](https://docs.whop.com/api-reference/beta/bounties/bounty.md)

## 钱、依赖和切片（分析）

CR 品牌支付平台费：标准 10%、Verified 8%，另支付处理费；创作者 CPM 扣 10%，按篇/周期预算低于 $5,000 扣 10%，达门槛为 0%。这些是 CR 费用，不可记成 Whop 收入。[品牌定价](https://b4e0vdqv6zgqeqj4pfgm.apps.whop.com/pricing)、[创作者合同](https://b4e0vdqv6zgqeqj4pfgm.apps.whop.com/terms)。Whop 自身另存 10% Content Reward Fee 合同，适用关系须独立核对。[Whop 条款](https://whop.com/content-rewards-terms-of-service/)

Bounty 发起者负担毛奖励；平台费和推荐份额从中扣，不另加在名义奖励上；统一费率未核得。例：$25×4 份=$100 锁定，执行者总到手不必等于 $100。[指南](https://docs.whop.com/developer/bounties/run-a-bounty-program.md)

依赖 B07：任务执行者推荐奖励；B08：经许可的内容可能复用于广告，但不能自动视为销售归因。B01 提供身份/组织/团队，B02 提供充值付款执行，B03 提供社区与内容交付，B04 提供一般支持及报表，B09 提供锁定、转账、提现，B10 提供风险验证与退款争议裁决，B11 提供开发者契约。这些归属是研究分类，以上仅为所需能力，不是整模块建设顺序。B12 AI 工具不是固定报酬任务首片的必要依赖；若以后加入 AI 辅助审稿，由 B12 提供建议，本模块保留交付审核决定。B05 商品评价不属于任务证明；完成课程的积分奖励也不属于品牌采购。

首个切片候选：固定报酬文件任务，单一币种、公开要求、单名额、人工审查、取消退款。假设验收：未锁足资金不可发布；一份交付不能付两次；有在途任务时不能直接全额退；拒绝保留理由；金额可对账。之后独立加周期任务，再考虑带验证窗口的 CR 型活动。指标建议：首份合格交付时间、获批率、净时薪、预算利用率、复投率、申诉改判率、履约付款时长。

未知：新 CR 的公开开发 API、全部后台操作、实际报价基数与税费、平台利润、Whop/CR 股权沿革、真实防作弊效果、Bounty 调度充值失败补救/仲裁细节、数据采集设备全流程。不能视为马来西亚可直接照搬的法律或支付方案。

## 流程、收入与失败

买家推广：商家定规则→推广者取链接/素材→买家付款→按当时有效条款归因→等待→佣金可结算→B09 支付。战略 revenue share 不需要“推广链接点击”，应是单独的合同义务。

商家伙伴：报名→分享→商家加入→商家发生合格活动→awaiting_settlement→pending→completed；可 canceled/reversed。费率与佣金在底层交易结算前可为 null，不能当成零收入。[Partners 指南](https://docs.whop.com/developer/partners/overview.md)

失败：无链接或追踪失败、费率到期/关系 removed、退款/拒付/欺诈触发取消或追回；结束计划后的合格款和账号保留要求另受条款约束。[Earnings Terms](https://whop.com/earnings-terms/)。奖励链接名额耗尽时，尚在冲量不等于名额已预留。[Reward Link](https://docs.whop.com/api-reference/beta/partners/retrieve-a-partner-reward-link.md)

钱：买家 affiliate 由卖家按 offer 承担；revenue share 由卖家交易分配。Partners 是 Whop 向伙伴支付。2026-08-18 官方文章营销报价为最高 30% Whop 毛利及合格广告支出 1%；实际值应读每个关系的费率、期限和账单。[伙伴文章](https://whop.com/blog/whop-partners/)。旧 Earnings Terms 仍写招募商家前六个月分 Whop revenue，与新 API 毛利口径不同；不能承诺永久或全部商家销售额的 30%。

## 依赖、首片与待验证事项（分析）

所需能力：B01 身份、组织及商品；B02 成功付款/续费事实；B06 执行者推荐的触发事实；B08 合格广告支出事实与奖励额度应用；B09 支付及账本；B10 退款/争议裁决；B04 报表展示；B11 对外接口。这些是能力依赖，不是整模块串行建设。佣金归因和广告归因可能不同，B07/B08 不能共用一个“获客来源”覆盖彼此。

首片：一商品、一个推广者、首笔付款百分比佣金。假设验收：同一付款不重复生成义务；使用付款当时费率快照；归因不成立不生佣金；退款只按裁决冲销并留痕；金额与 B09 账本对齐。后续再加续费、自定义、revenue share、商家多来源伙伴。

建议指标：活跃推广者占比、有效转化率、每个获客的佣金成本、推广客户留存/退款率、伙伴引入商家激活率、佣金等待时长。未知：cookie 时长、归因抢占与跨设备优先级、自购/既有客户条件、部分退款比例、总分成超过可分配额的处理、代理对外服务费、私人商务分成、毛利定义的完整成本项。

## 主流程与失败流程

正常：B10 完成收款人核验 → B02 销售结算或 F03/F09 注资 → F01/F02 显示资金 → F07/F08 按业务义务转给收款账户 → F04/F06 确认外部目的地、报价 → F05 完成出款并记账。企业平台亦可只买代付能力，不必使用 Whop 商城。

失败：转出未验证、余额不足、收款人不能收款时先解决原因再重试；出款被合规审查则不展示“即时”；审核中取消退回资金，处理中不可取消；银行退回与原成功出款不同，需保留活动链。卡消费被锁卡、额度、余额或 B10 风险规则拒绝时返回对应状态，不能当提现失败。以上流程依据 F04–F08/F11；账务一致性处理是分析要求。

## 谁付谁与收费触发

销售款及平台注资属于客户资金，不是 Whop 收入。提现按实际方式计费；充值 API 的免费不能外推银行、链上、外汇及合作方所有成本。[提现定价](https://whop.com/network/pricing/)

企业平台可以对其连接商家收 application fee；这笔平台收入不等于 Whop 收入。直收模式由连接账户负责 Whop 费用、退款和争议；平台收后再转模式由平台负责原订单的费用、退款和争议。[企业收款](https://docs.whop.com/developer/platforms/collect-payments-for-connected-accounts.md)

融资交易定价页列成功交易 15%，是支付方式收费，并不证明 Whop 收取买家全部利息或自行放贷。F12 有交换费分享公开依据，但比例未知。F14 无证据可确认管理费、利差、收益分成。未取得 Whop 自有商家贷款/营运资金垫款产品的充分一手证据，不能把消费融资、待结算提前可用和 Treasury 拼成“Whop Capital”。

## 依赖及扩展点（分析）

- **B02**：销售付款、退款执行和账单，提供资金来源与交易引用。
- **B10**：KYC/KYB（个人/企业身份核验）、风险控制、冻结释放决定、税款归属。
- **B01** 提供账户和团队权限；**B06/B07** 分别提供奖励及佣金应付义务；**B08** 提供广告支出义务；**B11** 拥有外部接口契约。本卡不决定奖励审核、推荐或广告归因。这些是所需能力，不是整体模块建设先后。
- 扩展点：合作方出款适配、余额用途策略、按国资格、财务连接器、发卡提供方；收益与贷款另成资格门控子域。

## 首个纵向切片与验收候选（未批准）

**切片：已核验商家从一笔模拟销售到可用余额、银行出款及退回。** 不包含真实托管、发卡、crypto、收益或贷款。

1. B09-A01：销售、费用、可用及待结算金额能追溯到同一来源；待结算资金不能进入普通提现可用额。
2. B09-A02：准备金被 B10 持有时不可提现，释放后只增加一次可用额。
3. B09-A03：出款请求重复提交不重复扣款；审核中取消完整恢复相关资金；处理中明确拒绝取消。
4. B09-A04：银行退回生成可追溯事件，金额与余额恢复一致；财务记录不会把充值/内部转账再次记为销售收入。
5. B09-A05：未核验、目的地不符合国家规则及余额不足均被拒绝；显示可处理的原因。

后续候选：企业代付门户 → 受控分账 → 合作发卡 → 单独评估 crypto/收益/融资。不是 Whop 内部实现顺序。

### 发卡合同补充

[美国商务卡条款](https://whop.com/us-card-business-terms/)与[国际商务卡条款](https://whop.com/intl-card-business-terms/)描述以链上抵押品保障的卡账户；美国文本将 Issuer 定义为 Third National，Whop 声明自己不提供信贷。不能据消费页的“花余额”就把所有卡归类为普通借记卡，也不能据它认定存在 Whop 自营贷款。F11 的后续候选切片须涵盖抵押品、偿付、清算及欠款状态；这些本轮只核合同，未测试。

指标候选：到账准确率、出款成功率/耗时、退回率、账务差异、重复资金事件数、受限余额占比、卡拒付原因分布、返现冲正率；收益产品未确认开放前不以 APY 为目标。

地区证据分级：虚拟卡有创建 API 正文；定制品牌和实体卡还有[零工企业页](https://whop.com/network/solutions/gig-economy/)营销佐证，但本轮未核实体寄送、制作费、补卡、开户地区。该页也再次宣传无最低金额的 Treasury 收益，未补足 F14 的资格、资产及收入缺口。

## 正常与失败流程

**准入：** B01 账户 → F01 核验 → F02 补件或审查 → 通过后向 B02/B09 输出具范围的资格；状态变更通知后重新读当前结果，不能把一条通知当作永远通过。

**纠纷：** 买家对 B02 某笔付款提退款 → F09 案件、证据及商家响应 → F08 裁决 → B02 执行退款、B09 记账、B03 调整相应权益。未响应七天升级平台，支持文档所述一次申诉。银行拒付走 F10 单独流程，收到拒付即暂扣原争议金额及适用费，胜诉返争议款，败诉落实损失。[平台案件](https://docs.whop.com/manage-your-business/manage-payments/resolution-center.md)、[拒付](https://docs.whop.com/manage-your-business/manage-payments/manage-disputes.md)

**失败：** 补件驳回回到 action_required；高风险可延迟提现、增加准备金或暂停融资；余额不足无法完成退款时必须显示未完成，不能仅凭裁决通知买家“已到账”。Apple 内购及 Coinbase Commerce 的案件路径不能照搬银行卡。税务覆盖之外不能显示“Whop 已代缴”。F01/F02/F06/F08/F12 及综合报告有来源。

## 收费及责任

正常核验和平台案件未取得统一独立收费证据。风控有事件/交易收费：3DS $0.03、Radar $0.07、拒付 $15、早期预警 $29；按实际事件/开关而非每单必叠加。高风险处理费可出现但未核统一金额。[定价](https://whop.com/network/pricing/)、[风险控制](https://docs.whop.com/trust-and-safety/account-health/controls.md)

卖家承担适用退款及拒付损失；持有准备金不是 Whop 收入。税务帮助页对两种托管模式写 2%，但平台报告 C08 记录 Fees 文档为 0.5%；这是待核的跨来源/抓取差异，不能作为通用报价。见[综合报告税费冲突](../payments-money-trust.md#tax-fee-conflict)及[平台报告 C08](../platform-ai-enterprise.md)。税金另算；代算模式税款交卖家，代缴模式向税务机关缴纳。实际覆盖及合同边界见[税务正文](https://docs.whop.com/payments-and-billing/fees/taxes.md)。没有证据据此推算反欺诈利润、实际坏账或税务业务利润。

## 依赖（分析；能力依赖，不是整体模块先后）

- **B01**：组织、持有人、团队权限、商品分类与政策资料；B10 只存核验与审查事实。
- **B02**：原付款、费用、账单、认证及退款执行；税务规则由 B10 定，收费计算执行由 B02 调用。
- **B03**：交付/访问证据和退款后权益动作；不由 B10 再建会员状态。
- **B04**：客服消息、统一案件入口和数据呈现；本模块拥有财务纠纷决定。
- **B09**：冻结、准备金、负余额、退款资金及账务结果。
- **B11**：第三方核验、处理商与税务接口契约和事件交付规范；接口契约不能改写裁决事实。

## 首个纵向切片及验收候选（未批准）

**切片：单笔模拟网页卡付款的退款申请 → 人工决定 → 唯一退款 → 审计记录。** 同时使用模拟核验及风险结果，不实施真实资金处理。

1. B10-A01：案件必须关联授权可见的付款；已全退付款不能重复开案，买家与商家只能访问有关案件。
2. B10-A02：批准、拒绝、补证有操作者及时间；逾期进入升级队列，不能静默消失。
3. B10-A03：同一批准重复送达只触发一次 B02 退款；B09 资金不足时显示“待执行”，非“完成”。
4. B10-A04：退款成功后可追溯原付款、决定、资金记录与 B03 权益处理。
5. B10-A05：平台退款与银行拒付状态分开，发生并行案件时避免双重赔付，保留人工处理路径。

扩展点：核验提供方、按国家/合作方规则、税务计算商、证据收集、自动裁决阈值与申诉；所有新政策应有生效时间与依据。指标候选：核验完成率、补件率/耗时、误拒率、案件首响与结案时长、按成熟购买批次争议率、追偿回收率、准备金占用天数、税额对账差异；均为未来衡量建议，无 Whop 实际值。

## 正常流程与失败流程

**正常 A：站内开发者产品。** 注册应用 → 配置成员／经营视图和所需权限 → 商家安装同意 → 按商家建立内容实例 → 成员身份和购买权益检查 → 交付应用功能 → 新版本发布。依据 F01–F07；应用收费模式单独约定，不能由“已安装”推出“已付费”。

**正常 B：企业自己的平台。** 平台接入凭证 → 关联卖家注册并完成必要验证 → 选择直接收款或先收后转 → 买家在企业界面付款 → 服务端确认并交付 → 平台及卖家依约获得款项 → 嵌入门户查看／提现。依据 F08–F12。

**已见失败语义**：新权限未重批导致拒绝；OAuth 到期／撤销；身份有了但权益不满足；关联账户验证未完成、余额不足或收款方不可收款使转账失败；Webhook 重复／乱序／停用导致本地状态落后；支付界面结束不等于款项成功；连接器选错企业／子账户导致关联失败。以上有 F04、F05、F07、F09、F14 正文支持。

**未来设计必须补齐、不是已证实 Whop 流程**：应用下架／卸载后的保留数据与退款责任、发行审核拒绝原因和申诉、连接器重放／冲突修复界面、企业退出和迁出计划。不得把这些建议写成现有 Whop 功能。

## 谁向谁付费

- 外部商家向 Whop 支付交易服务费；公开标准页写无设置费／月费，国内卡成功交易 2.7% + US$0.30，并有额外条件收费；企业定制价格由销售报价。该标准不是马来西亚报价，亦不是“任何产品都免费”。[定价](https://whop.com/network/pricing/)（M，2026-09-10）
- 关联商家直接收款时：买家支付交易总额，平台收 application fee，关联账户承担 Whop 费用／退款／争议；先由平台收款再转账时，原支付费用与争议由平台承担。文档的 merchant-of-record 用语不能替代合同确认。[收款模式](https://docs.whop.com/developer/platforms/collect-payments-for-connected-accounts.md)（D）
- 商家向应用开发者付安装费、订阅或分成是官方介绍的商业模式；列出的金额／百分比是例子，**不是 Whop 统一开发者结算政策**。发布费、平台应用抽成、退款时开发者追回规则、免费应用补贴均未核实。[应用商业化](https://whop.com/blog/whop-app-store/)（M/H）
- API 调用、OAuth、聊天、SDK 本身是否另按调用量／活跃用户收费，及连接器是否额外订阅收费：本轮公开正文不足，标记未知。不能从支付标准价推导其为永久免费。

## 首条纵向切片与验收建议

**建议首片：一个测试商家安装一个只读会员工具。** 从开发者登记、最小权限同意，到商家实际看到自己的有效会员；卸载／撤销后不能继续读取。先验证完整的安装边界，再接真实资金。以下仅是假设未来开发的检查，不是批准：

- B11-AC01（F01/F04/F05）：商家 A 安装后只能读取 A；使用 B 的 ID、到期令牌或未授予范围时失败，不泄露记录。
- B11-AC02（F03/F04）：成员不能访问管理视图；拒绝可选权限不阻断核心工具；新增权限必须重新同意。
- B11-AC03（F07）：模拟重复／乱序事件不会重复更新权益；签名不符不处理；停用后能通过补查恢复。
- B11-AC04（F02/F06）：安装、撤销、版本回退有明确可观测结果；日志隐藏凭证。

后续切片候选：单一外部 checkout → 单个关联卖家开户与分账 → 扩展钱包／聊天 → 一个账务连接器 → 企业服务管理。每片都需要自己的批准与当地适用性确认。

## 建议衡量及未知

建议衡量：首次成功接入耗时、安装到首次有效使用率、权限重批完成率、事件补偿完成率、活跃安装留存、关联账户注册到首次到账率、连接器对账差异、企业接入工时。均为拟测指标，没有 Whop 实际值。

未知：应用审核时效及退出全生命周期、实际开发者协议费表、企业最低消费／SLA／容量承诺、嵌入组件各平台功能对等、连接器供应商主体和独立收费、Malaysia 可用范围、API 与 UI 发布不同步程度；本轮无账号、无安装、无沙盒／生产调用。

## 正常与失败流程

**创业正常链**：描述业务／选择蓝图 → 选择或建立商家业务 → 审核商品、价格、站点配置 → 发布独立网站 → checkout 收款 → 使用数据和人工反馈继续修改。前半链来自 F01/F07/F08；“审核后再发布”是未来产品建议，不是声称所有 Whop AI 操作都有该关卡。

**经营自动化链**：授权外部 AI → 指定业务 → 读取状态／准备操作 → 用户同意 → 相同参数与确认令牌执行 → 查询真实结果。F05 文档明确要求重要操作分两次执行；不能把权限广度误写成“只读”。

**迁入正常链**：连接 Stripe → 预览订阅 → 完成支付方式转移准备 → 排除不迁项目 → 确认 → 迁移报告 → 下一个续费周期验证。F10 的“单击”营销不包含全部前置人工步骤。

**已证实限制与失败**：MCP 授权过期／无效、确认参数变化失败；站点自动注入权限不能发起转账／提现；媒体生成要等待就绪。Stripe 迁移仅卡支付、active／trialing 状态、客户有邮箱、金额不少于 US$1；转移后更改支付方式不包含在旧快照中。失败项目可通过报告识别；重跑跳过已成功项目。[MCP](https://docs.whop.com/developer/guides/ai_and_mcp.md)、[Hosting](https://docs.whop.com/developer/websites/hosting.md)、[媒体](https://docs.whop.com/api-reference/beta/media/generate-media-asset.md)、[迁移限制](https://whop.com/blog/migrations/)（2026-09-10）

**建议链限制**：B12-F14 的 executed／redirected 记录只说明客户端步骤被记录，不能代替 B01 商品、B02 交易或 B03 交付的真实成功状态；它不是 F05 MCP 已确认业务操作的替代物。

**未来待设计的失败链**：AI 误定价／误选业务的恢复、蓝图部分创建失败补偿、生成失败退款、网站所有权争议、注册被拒／撤单、WhopX 收入回落／异常交易资格申诉、教育内容过期和项目结束退出。公开资料不足以确认 Whop 已怎样处理。

## 依赖关系与正式所有权

以下为所需能力，不要求先完成整个依赖模块，也不声称 Whop 实际这样拆代码。B12 拥有 AI 业务工具和经营项目编排。

| 依赖 | 所需能力与不重复拥有的事实 |
|---|---|
| B01 | 用户、组织、团队、商品；蓝图创建商品时写回正式目录。 |
| B02 | 价格计划、付款、发票执行；AI 不能另存一份收费计划。 |
| B03 | 网站购买后的会员权益和交付；University／WhopX 的访问执行也复用它。 |
| B04 | AI 经营查询所用数据、分析、通用支持及教学辅导问题记录。 |
| B05 | 蓝图发现、排序及评论通用能力；B12 仅拥有蓝图内容和部署关系。 |
| B07 | 蓝图推荐来源和佣金义务；B12 提供“部署副本来自哪个蓝图”事件，不自行维护佣金账本。 |
| B08 | 网站像素、广告及转化归因；B12 建站时配置接入，不另算广告收益。 |
| B09 | 媒体费用扣款、注册付款对应资金记录和 WhopX 收入资格读取。 |

## 首条纵向切片与验收建议

**建议首片：一个经人工校验的本地业务蓝图，生成一个可预览、可测试结账的网站。** 例如马来西亚导师把一个明确价格的课程卖给测试买家。不要在同一首片承诺自动注册公司和全能 AI 经营。

- B12-AC01（F01/F08）：蓝图清楚显示将创建的商品、价格、网站和来源；确认前不创建正式售卖对象；蓝图作者不能读取副本商家客户数据。
- B12-AC02（F07/F08）：两家测试商家得到隔离副本；其中一家改价不影响另一家；支付入口读正式商品价格，不能和页面文案分叉。
- B12-AC03（F07）：发布失败显示可操作原因，保留上次可用版本；恢复旧版不重复创建商品或删除有效订单。
- B12-AC04（F05）：若加 AI 编辑，先展示业务和影响；改参数使旧确认失效，重复执行不重复创建／收费。
- B12-AC05（F08）：用模拟销售验证蓝图来源归因；奖励基数明确标注待确定，不把 Whop 的 10% 条款自动作为 Malaysia 平台承诺。

后续切片：只读 AI 经营问答 → 一种可确认修改 → 迁移预检和人工协助 → 完整迁移 → 教学项目 → 收入资格社群。公司成立服务需单独业务／合作方方案，不作为普通表单功能附送。

## 建议衡量与未知

建议衡量：想法到可预览站点时间、蓝图部署成功率、发布后首次成交率、AI 操作纠正率、确认取消率、迁移合格率与首次续费成功率、教学参与到真实开店转化、WhopX 合格成员参与／留存。均为未来拟测，没有声称任何 Whop 实际数值。

未知：Whop AI 具体模型／训练／成本；建议链未来是否具有服务端执行（当前 Execute 明确没有）；跨账户操作隔离实测；网站托管额度；蓝图版权许可及奖励结算；迁移全量支持矩阵；LLC 被拒后的责任与退款；University 当前服务承诺；WhopX 收入计算周期、退款扣减及降级；马来西亚经营者适用条件。所有当前 UI 仅由公开文字或官方图文核实，未登录体验。
