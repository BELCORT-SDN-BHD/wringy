# B11｜开发者平台、可安装应用与企业嵌入服务

证据口径统一见[证据指南](../evidence-guide.md)；演示与真实依赖边界见[共享建设参考](../build-reference.md)；本卡保留的文/API、D/A、营销等本地图例仅作别名，以统一指南为准。API 路径中的 beta 不单独证明预发布；成熟度须依据具体页面正文及版本，未核实则保留未知。

状态：**研究型候选模块，不是已批准规格，也不是 Whop 内部架构。** 核查日期：2026-09-10。这里是 B11 唯一规范功能清单；商业讨论、版本冲突见 [分组研究报告](../platform-ai-enterprise.md)。所有勾选框表示未来候选工作，均不表示已经实现。

## 目的、参与者与边界

让外部软件使用平台的交易、身份、社区能力；也让独立开发者把应用分发给平台内商家。这是两种不同产品关系。参与者：平台运营方、开发者、企业技术团队、应用安装商家及管理员、终端买家／成员、关联商家／收款人、外部连接服务商。

**本模块拥有的业务概念（分析建议）**：开发者应用、安装关系、安装授权、授权范围、应用视图、发行版本、集成连接、外部身份映射、事件订阅、关联账户的平台注册关系、平台附加收费配置、企业接入方案。API 是软件调用入口；SDK 是接入工具包；嵌入组件是可放进其他产品的界面。

**范围内**：接入、分发、授权、版本管理、嵌入界面、关联账户接入、连接器、企业交付支持。**范围外**：支付账本和结算规则、身份审核最终裁决、课程和聊天内容自身、广告竞价与投放引擎、第三方应用内部算法。B11 对这些能力提供入口，不复制其业务所有权。Whop Websites、Blueprints、CLI 的创业编排在 B12；应用发行基础设施在 B11。

## 正常流程与失败流程

**正常 A：站内开发者产品。** 注册应用 → 配置成员／经营视图和所需权限 → 商家安装同意 → 按商家建立内容实例 → 成员身份和购买权益检查 → 交付应用功能 → 新版本发布。依据 F01–F07；应用收费模式单独约定，不能由“已安装”推出“已付费”。

**正常 B：企业自己的平台。** 平台接入凭证 → 关联卖家注册并完成必要验证 → 选择直接收款或先收后转 → 买家在企业界面付款 → 服务端确认并交付 → 平台及卖家依约获得款项 → 嵌入门户查看／提现。依据 F08–F12。

**已见失败语义**：新权限未重批导致拒绝；OAuth 到期／撤销；身份有了但权益不满足；关联账户验证未完成、余额不足或收款方不可收款使转账失败；Webhook 重复／乱序／停用导致本地状态落后；支付界面结束不等于款项成功；连接器选错企业／子账户导致关联失败。以上有 F04、F05、F07、F09、F14 正文支持。

**未来设计必须补齐、不是已证实 Whop 流程**：应用下架／卸载后的保留数据与退款责任、发行审核拒绝原因和申诉、连接器重放／冲突修复界面、企业退出和迁出计划。不得把这些建议写成现有 Whop 功能。

## 谁向谁付费

- 外部商家向 Whop 支付交易服务费；公开标准页写无设置费／月费，国内卡成功交易 2.7% + US$0.30，并有额外条件收费；企业定制价格由销售报价。该标准不是马来西亚报价，亦不是“任何产品都免费”。[定价](https://whop.com/network/pricing/)（M，2026-09-10）
- 关联商家直接收款时：买家支付交易总额，平台收 application fee，关联账户承担 Whop 费用／退款／争议；先由平台收款再转账时，原支付费用与争议由平台承担。文档的 merchant-of-record 用语不能替代合同确认。[收款模式](https://docs.whop.com/developer/platforms/collect-payments-for-connected-accounts.md)（D）
- 商家向应用开发者付安装费、订阅或分成是官方介绍的商业模式；列出的金额／百分比是例子，**不是 Whop 统一开发者结算政策**。发布费、平台应用抽成、退款时开发者追回规则、免费应用补贴均未核实。[应用商业化](https://whop.com/blog/whop-app-store/)（M/H）
- API 调用、OAuth、聊天、SDK 本身是否另按调用量／活跃用户收费，及连接器是否额外订阅收费：本轮公开正文不足，标记未知。不能从支付标准价推导其为永久免费。

## 依赖关系与正式所有权

以下是未来所需能力，不是整模块先后顺序，也不是 Whop 内部代码依赖。依照 2026-09-10 本次任务最新边界，B11 只拥有外部开发者合同、应用接入／安装授权和集成关系；平台附加收费在 B11 定义合同配置，扣费执行归 B02，资金记账归 B09。

| 依赖 | 所需能力与不重复拥有的事实 |
|---|---|
| B01 | 身份、组织、团队、商品目录；B11 外部身份映射不得另建用户／商家事实。 |
| B02 | 收费计划、付款和发票执行；应用价格或 application fee 的合同条件在 B11，执行引用 B02。 |
| B03 | 会员访问权和交付；B11 输出界面与授权入口，不独立裁定购买权益。 |
| B04 | 经营数据／分析／通用支持；B11 提供连接和数据导出，支持事实仍归 B04。 |
| B05 | 发现和评论能力；应用特有开发者安装契约归 B11，检索／排序／评论能力复用 B05。 |
| B06、B07、B08 | 分别提供奖励义务、推荐归因与佣金、广告与归因的外部调用；API 暴露不转移业务所有权。 |
| B09 | 余额、转账、提现、账本事实；平台关联关系归 B11，钱的归属变更归 B09。 |
| B10 | 验证、风险、退款争议裁决和税务政策；B11 只承接审核会话、所需资料和结果呈现。 |
| B12 | AI／CLI／Blueprints 使用 B11 的合同、授权、应用发行能力；B11 不重复创业编排。 |

边界提醒：B11-F10 的附加收费究竟对应交易费用还是推荐佣金，须逐合同确定；不能一概挪入 B07。企业接入支持的交付承诺可归 B11，普通客服工单归 B04。

## 首条纵向切片与验收建议

**建议首片：一个测试商家安装一个只读会员工具。** 从开发者登记、最小权限同意，到商家实际看到自己的有效会员；卸载／撤销后不能继续读取。先验证完整的安装边界，再接真实资金。以下仅是假设未来开发的检查，不是批准：

- B11-AC01（F01/F04/F05）：商家 A 安装后只能读取 A；使用 B 的 ID、到期令牌或未授予范围时失败，不泄露记录。
- B11-AC02（F03/F04）：成员不能访问管理视图；拒绝可选权限不阻断核心工具；新增权限必须重新同意。
- B11-AC03（F07）：模拟重复／乱序事件不会重复更新权益；签名不符不处理；停用后能通过补查恢复。
- B11-AC04（F02/F06）：安装、撤销、版本回退有明确可观测结果；日志隐藏凭证。

后续切片候选：单一外部 checkout → 单个关联卖家开户与分账 → 扩展钱包／聊天 → 一个账务连接器 → 企业服务管理。每片都需要自己的批准与当地适用性确认。

## 建议衡量及未知

建议衡量：首次成功接入耗时、安装到首次有效使用率、权限重批完成率、事件补偿完成率、活跃安装留存、关联账户注册到首次到账率、连接器对账差异、企业接入工时。均为拟测指标，没有 Whop 实际值。

未知：应用审核时效及退出全生命周期、实际开发者协议费表、企业最低消费／SLA／容量承诺、嵌入组件各平台功能对等、连接器供应商主体和独立收费、Malaysia 可用范围、API 与 UI 发布不同步程度；本轮无账号、无安装、无沙盒／生产调用。
