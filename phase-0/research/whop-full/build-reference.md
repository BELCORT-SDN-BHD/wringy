# 从研究板块到可建设的一条业务链

本文件是候选验证方式，非实施规格、非已选择首版。板块依赖指所需能力，不要求先做完整个板块。模块卡的验收候选也不必全部进入各自首片。

演示或测试时，可用明确标注的模拟供应商结果验证流程；**不能把模拟核验、模拟出款显示成真实通过或真实到账**。真实运营前还须验证实际渠道和资格。

| 所需能力 | 内部流程原型可怎样验证 | 接真实业务前需要什么 |
|---|---|---|
| 账号、角色与跨商家隔离 | 测试账号和权限；越权被拒绝必须实际成立 | 真实登录与权限控制，不能用界面隐藏代替 |
| 活动规则、提交和审核 | 测试活动、内容和评审记录；状态转换实际可追溯 | 可执行且获批的活动规则、证据留存及复核路径 |
| 预算、奖励义务与账务 | 测试资金单位；余额约束、锁额、重复请求不重复记账必须实际验证 | 真正资金记录、对账、冲正与异常处理 |
| 身份/企业核验 | 模拟待处理、补件、通过、拒绝事件；明确是测试结果 | 合格供应商、正式准入规则、真实结果校验 |
| 充值、付款、出款 | 模拟成功/失败/延迟或使用供应商沙盒；不移动真实钱 | 正式开户、国家/币种资格、回调核对、费用及失败处理 |
| 活动发现、广告及推荐 | 可先用直接活动链接或测试归因 | 仅在选中的业务链需要时接入；不强制先完成全部增长模块 |
| 蓝图来源与佣金 | B12 的副本关系与 B07-F14 的奖励义务做联合测试 | 来源、基数、退款冲正与 B09 结算一致；跨模块验收不是 B12 建站首片的自动前置 |

例如测试品牌活动链时，可以模拟创作者核验和银行出款结果，但应实际验证：同一提交不能重复奖励、预算不能被超额承诺、拒绝/争议/失败状态能追踪。它验证业务逻辑，不等于可以上线处理真实资金。

选定业务链后，每个切片再记录目标用户证据、成功条件、时间投入、明确非目标、规则与责任、模拟/真实边界、异常、验收及上线衡量。经创始人批准后才能成为实施依据。研究没有替创始人选择 B06 或任何其他首版。
