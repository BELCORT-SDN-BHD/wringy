# YC 指定文章来源审计

核查日期：2026-09-10。工作者独立执行，无进一步委派。范围：公开来源研究与故事稿，不制作 PPT。

## 结论与身份

已取得创始人指定的[YC 原文](https://www.ycombinator.com/library/2u-how-to-build-your-seed-round-pitch-deck)全文及其全部 **10 张**模板图片，并逐张目视检查。作者字段是 **Aaron Harris**。正文背景为 Winter 2018 Demo Day 前一周，图片原始路径为 2018/03；因此能确认 2018 年背景，但本次没有确认精确首发日。不能写成 Anu Hariharan 的 2016 年文章。Library 元数据中的录入日期也不应替代首发日期。

原文是一套带幽默占位内容的种子轮故事模板，不是 YC 自己的融资实绩，更不是某家公司的成功融资原稿。文章说用途是 Demo Day 后与投资人继续交谈的较长材料。不能把它包装成已验证融资成功的 Wringy 模板，也不能沿用 v3 的 Sequoia 来源标签。

## 取证路径与可复现文件

1. 网页读取工具打开指定地址返回 0 行，不能由此断定全文不存在。
2. 公开 HTTP GET 成功取得 75,962 字节 HTML。正文存在于 `data-page` 属性中的 JSON：`props.article.content`，不是可直接抽取的静态正文节点。
3. HTML 解码后得到完整 Markdown、作者及其他文章字段。按 Markdown 中的图片出现次序提取 URL，共 10 个。
4. 原图片主机 `blog.ycombinator.com/wp-content/uploads/2018/03/` 自动跳转至 `www.ycombinator.com/blog/content/images/wordpress/2018/03/`。10 张全部成功下载、解码及目视检查，均为 **2000 × 1125，16:9**。
5. 两种官方博客文章地址均返回 404；已经取得指定 Library 本身全文，无需拿非官方转载填空。搜索结果中的第三方摘要未作为证据。

复现：下载同一官方 URL，用 HTML 解析器取 `data-page`，JSON 解码后读取 `props.article.content`，按图片标记出现顺序下载。原文件后缀为 2–11，Markdown 图片 alt 为 template-3–12；两者都不能充当页数。本文按出现顺序编号 01–10。未发现原文提供可编辑 PPTX、PDF 或 Google Slides 下载链接；文章字段 `slides` 与 `link` 均为空。已取得的是官方提供的模板图片，不能宣称取得源演示文件、母版或字体定义。

版权处理：快照仅作为本项目内部参考，保留原地址和校验值；不把原文全文或模板图片加入对外投资材料。不在聊天复述长段原文。后续 Wringy 使用原创文案与视觉。

## 实际结构与作者允许的灵活度

实际出现顺序：**封面、问题、解决方案、使用增长、补充指标、独特见解、商业模式、未来增长／市场、团队、资金需要。** 详细观察见逐页映射。

作者明确表示：封面只用一页。其他示例页可作为一组页面的起点，尽量一页，有必要可增加，一组最好不要超过三页。业务模型和独特见解段再次允许展开。增长数据的展示以已有数据为条件；第二张指标页的图是用户通过模板募到的钱，作者指出这里用收入更好，不能把该图误认作模板公司的收入。

**未在全文找到“按最强证据任意重排”或类似页序授权。** 不能把其他 YC 文章、第三方建议或记忆里的说法归给本篇。本文保留剩余主题的相对顺序，依据“有数据时展示”的条件删去两张经营数据页，再把解决方案、市场各展开为两页。这是 Wringy 的透明编辑决定，不声称 YC 指定所有公司必须做十页。本文没有独立的 Why now、Competition 或 Vision 章节；这些内容若有必要，应融入相关主题或明确标为新增。

## 视觉原则：原文、观察与改编分别记录

原文要求清楚、简短，以叙事为主；脚注明确模板故意采用简单设计。现场观察：白底、黑色大标题、灰色正文、宽松留白，标题多居中在上方，正文左对齐。两张数据页以左侧大折线图配右侧少量解释；团队页以三张照片和角色说明构成。无重复页脚、无页码、无图标系统、无品牌装饰栏。字体呈无衬线外观，无法从 JPEG 确认字体名称或原始字号，不报伪精确值。团队图片和夸张数字是模板占位内容，不是可借用的履历或业绩。

脚注链接的 [Kevin Hale 设计文章](https://www.ycombinator.com/library/4T-how-to-design-a-better-pitch-deck)也已从官方页面解码，见[内部文本](source/design.md)。它属于 **Demo Day 的设计建议**，本次只用于阅读原则，不替换 Aaron Harris 的种子轮结构，也不把它的 5–7 页建议套到这里。该文强调可读、简单、意思一眼明确：每页聚焦一个意思，大字、高对比，图表写明结论，避免无说明照片、复杂流程和难读的完整产品截图。本次未声称逐图审计该设计文章的全部教学插图；本任务的逐页全检对象是指定种子轮模板的十张图片。

创始人希望更多图片和图标。执行上用一张可读的产品局部概念图解释动作，用一组有标题的实例画面解释交付，用原生图表表达数据。图标只辅助识别角色与步骤。该视觉增量是创始人授权的改编，**不是 YC 模板本身的风格特征**。Ramp / Linear 的参考研究与具体视觉资产由主会话后续接入，本工作者不生成图片、不冻结色值、不冒充真实客户照片。
