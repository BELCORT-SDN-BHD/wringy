# Content Rewards／Whop 审核机制核查

2026-09-10。事实以当前第一方文本为准，设计推论另见 [Wringy提案](../../foundation/review-design-v1.md)；可直接排版见 [两页机制＋附录](deck-brief.md)。来源ID、访问日期、短引文与整节读取范围见 [台账](source-ledger.md)。CPM指每千次合格播放计酬；结算指奖励成为可提现应付余额，不能等同外部到账。

## 1. 版本边界与谁检查什么

| 范围／角色 | 检查或决定 | 明确边界与来源 |
|---|---|---|
| 旧Whop教程（2025-05-14） | AI按活动要求初检，不合格者标记；符合条件、已审但超过48小时未批准者自动通过 | 不是当前CR规则。[L FAQ](https://whop.com/blog/set-up-content-rewards/) |
| Whop项目合同（未标日期） | 卖家审要求、条款、合法性/可疑欺诈，持续监控；Whop可在自定合理期限后自动批准或拒绝 | 合同本身未固定48小时；不能证明任何旧活动接受了此网页当前版本。[W Sellers review/monitor](https://whop.com/content-rewards-terms-of-service/) |
| 新CR品牌审核员 | 人工批准/拒绝最终投稿，只能依据平台活动Requirements/Description；Pending持续至人工操作 | 私聊、Discord、外部文件单独新增要求不可作为拒稿依据；客服不能代品牌批准。[O §§5.6、6](https://contentrewards.com/brands-terms) |
| 创作者＋品牌发布前审核 | 创作者交未发布原片；品牌批准/拒绝/要求修改，多轮讨论 | 草稿通过不是成稿通过；实际发帖仍可能漏披露或偏离brief。[C §8](https://contentrewards.com/terms)。V公告另写批准发布账号及版本控制；未实测其当前界面。 |
| CR＋第三方风险服务 | 对投稿与账号作0–100风险评分，分流人工审核；品牌可调活动风险阈值 | 分数不是假播放百分比；自动标记不是自动拒绝；风险未结案暂停付款。具体信号权重不公开。[P §6](https://contentrewards.com/privacy-policy)、O §8 |
| CR人工支持 | 处理风险标记申诉；普通拒稿只与品牌协调 | 风险解除不等于成稿获批；品牌决定普通拒稿是否改判。[C §§7、9–10](https://contentrewards.com/terms) |
| Whop | 按独立条款负责资金处理、相关身份核验与提款 | CR管理奖励逻辑和应付账本；Whop角色不能替代品牌内容判断或证明银行已收款。[O §§3、18](https://contentrewards.com/brands-terms) |

新条款Scope保留旧Whop活动、投稿/余额的原接受合同；新web条款不是全量追溯替换。2026-08-19公告是可查的V2发布描述；2026-09-03是条款标注更新时间，均不能当当前运行构建号。[C Scope/§31](https://contentrewards.com/terms)、[V](https://contentrewards.com/articles/v2-is-here)

创作者应负责素材/音乐等权利和披露；品牌负责brief、素材与广告主张。CR明确不提供FTC广告披露预批准/持续监控；删除CR内投稿不等于能删除社交平台原帖。[C §§12、17](https://contentrewards.com/terms)、[O §§12–14](https://contentrewards.com/brands-terms)

## 2. 合格播放能证实到哪里

当前声明：连接社交账户核对帖子归属并读取平台数据；风险评估结合投稿及账号信号，品牌按已公布要求审核；CPM按核验播放逐步消耗预算，单稿有活动设定的最低应赚金额与最高奖励。按帖奖励如设播放门槛，须在品牌设定监测期内达到，否则预留退回；按周期模式另看交付规则。[P §§3–6](https://contentrewards.com/privacy-policy)、[O §5](https://contentrewards.com/brands-terms)

严禁买量、机器人或人为操纵；未经活动允许的协同发帖可能因归属分流被拒。不能把平台公开播放数、独立人数、目标地域人数及可计酬播放画等号。新条款没有公开一套完整扣量公式、采样频率、跨平台去重或地域核验准确率。[C §§12、14](https://contentrewards.com/terms)

旧Whop合同进一步排除机器人/脚本及奖励诱导等非真实观看，最终由Whop判断；这是旧合同的有效观看定义，不能自动搬成新版算法。[W Participants Payment](https://whop.com/content-rewards-terms-of-service/)

首页强调独立验证与多信号，但其FAQ限定外部独立观看验证仍在部分代理商beta；不能宣称每一观看均已独立证明为真人。[H FAQ](https://contentrewards.com/) 隐私政策虽列自动内容处理服务，最终审批/拒绝/风险裁决仍明确由人决定。[P §§6–7](https://contentrewards.com/privacy-policy)

## 3. 证据、申诉、退款与追索

| 事件 | 已证实处理 | 不可外推 |
|---|---|---|
| 风险标记申诉 | 每稿一次、书面说明、可能补证；目标10工作日答复；成立解除标记、暂停款恢复；不成立可能逆转未结算奖励 | 不是保证10天结案，也不是普通拒稿通用次数规则。[C §10](https://contentrewards.com/terms) |
| 已批准后被拒／风险成立 | 未结算部分退回活动预算并通知；已结算不走该流程 | 已结算≠绝对无法追索：欠CR款项、确认欺诈损失可抵扣/扣留，法律及制裁另有暂停。[C §§11、13.4、15](https://contentrewards.com/terms) |
| 品牌退款 | 有待审稿不能申请；先处理创作者应付，再退余额；5–7工作日审核；最多酌留未花预算20%，处理商费不退 | 不是“拒绝所有稿即可全额退款”；拒稿理由仍受限制。卡组织拒付是另一路径，不自动永久封禁。[O §10](https://contentrewards.com/brands-terms) |
| 留存证据 | 草稿/讨论删除活动后仍作证据；未批准草稿不赋予品牌使用权 | 隐私保留须有目的与期限；YouTube API数据30天内刷新或受保留限制，不能无限保存全部接口原始数据。[P §§4.6、7、9–11](https://contentrewards.com/privacy-policy)、O §12.3 |
| Whop访问被封 | CR验证余额记录仍保留，支持可酌情安排替代支付并核验身份 | 非保证替代通道；不能把访问问题变成取消欠款。[C §16.2](https://contentrewards.com/terms) |

## 4. 时钟与冲突登记

| 来源与事件 | 此次核查 | 应如何写 |
|---|---|---|
| L旧教程审稿 | 48小时自动通过 | 只标旧体验教程，不是新版服务时限 |
| O §6.1新版审稿 | Pending直到人工操作；没有统一审核截止 | 可显示已等待时长；不能承诺到点通过 |
| PC定价、F帮助、C §7.3、O §6.2 CPM | **此次四者均有批准后7天计酬＋3天等待**；合同另保留调整及风险暂停 | 不能沿用“只有定价7＋3，合同纯变量”的旧概括；仍非保证银行到账。[PC](https://b4e0vdqv6zgqeqj4pfgm.apps.whop.com/pricing/creators)、[C](https://contentrewards.com/terms)、[O](https://contentrewards.com/brands-terms) |
| C §4.2与§7.3 | 前者泛称活动有资金且开放时可能继续累积；后者具体7天计酬 | 7天后是否另开累计批次，公开文本未澄清；不发明滚动窗口 |
| V（8月）付款与当前合同 | V写按帖/周期15分钟，CPM三天周期；当前按帖批准后不久、retainer周期末 | 用现条款条件，不继承15分钟。[V For creators](https://contentrewards.com/articles/v2-is-here) |
| F提交帮助 | 发布后30分钟内交链接 | 当前FAQ指导；合同未给同等迟交处置；不能推断自动拒稿/丧失全部收益。[F](https://contentrewards.com/creators) |
| O §5.1与§5.2 | CPM最低奖励金额；按帖最低观看量与活动监测期 | 金额门槛≠统一最低观看；监测期由活动决定 |
| V风险与现合同 | V说标记即停止赚取；现合同明确的是暂停结算 | 标记期间是否持续计数、补算收益须再问，不把冻结付款解释成停止抓数 |
| C申诉／O退款／Whop提款 | 10工作日目标答复／5–7工作日审核／CR转述Whop约3–5工作日发起估计 | 三个不同事件；不相加为统一到账期限 |

其他需保留的冲突：PB定价“无其他费用”与O §4.2代收处理费有差异；V权限限制与O §11 Owner/Admin可变更角色不同；O §10.3已批准/已付不可退款与§9未结算可逆转应按“普通退款”和“有依据的逆转”分别处理，不宣称已批准奖励绝对不可变。条款优先次序见C §31；没有对每个实际合同争议作裁定。

## 5. 未验证与后续成本

- 未取得：真实审批/申诉案件、风控供应商与完整算法、扣量和补算口径、预算耗尽并发顺序、旧接受合同、登录后角色权限及实际收款。完成本研究不等于这些问题已解决。
- 已有本地地基：`foundation/business-model-v2.md`明确合格播放方向；`prd-v1.md`仍是未批准历史按帖候选；设计规范也未冻结。此任务只形成获授权草案。
- 建议补缺（粗估、非承诺）：一次2小时计酬/申诉规则工作坊；一名运营与Belcort用1–2工作日核对样本案件及可取得的数据字段；第三方准入和法律审查另计。非Git镜像不运行工程分支流程；无产品代码或付款变更，后续由主任务接收缺口。
