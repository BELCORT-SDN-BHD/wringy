# 财务能模拟发放奖励并核对未知付款

Ticket: M1-06
Milestone: 三端交互原型（M1）
Label: ready-for-agent
Status: blocked

**What to build:** 获授权的模拟财务角色处理确认款项，creator查看付款状态；结果未知时必须查看原交易并对账。

**Blocked by:** [商家与运营能审核，创作者能申诉](./05-review-and-appeal.md)（05）

**Spec:** [首阶段原型规格](../../../phase-0/foundation/milestones/prototype-spec-v1.md)

**验收追溯：** P01, P08, P10, P11。这些是原型验收，不代表对应生产业务验收已通过。

## 验收条件

- [ ] 处理中的确认未付款不重复占用预算；模拟已发放后为1995/0/0/5，三端相同。
- [ ] 已发放表示模拟收款账户可用；银行到账未知另列，不能声称真实汇款完成。
- [ ] 提供处理中、已发放、确认失败及未知场景；未知没有直接再付一次按钮。
- [ ] 对账沿原模拟交易处理；只有已确认未付失败才可受控重试；重复操作不生成第二笔业务付款效果。
- [ ] 财务与普通审核角色分开；所有模拟操作留原因/原交易/记录，普通用户只见自己的结果。
- [ ] 从商家创建至creator模拟发放可完整演示；对应通知/邮件预览、手机与三语均可用。

- [ ] 本票自身检查390px/1440px并抽查320px；切换三语保留输入；有业务事件时核对接收角色、已读记录及模拟邮件；刷新、空/加载/错误/权限不足状态可复现。

## 实施边界与交付证据

仅做M1本地模拟纵向流程，界面、数据状态、持久化、角色反馈和验证一起交付。必要Next.js运行基础随首票建立，不另建只有脚手架但不可演示的票。沿用共用设计系统及已批准规则，不新建真实资金/认证/采集服务。

当前未开工、验收未执行。实施时按项目规则落实工程工作区及开工规格记录；拆票本身不是生产部署批准。完成时记录实际演示步骤、检查结果、已知限制及回退方式。回退本票入口/模拟状态适配应保留其他票功能；共享模拟数据结构变化需支持重置回基准并提前提示，不删除真实资料。
